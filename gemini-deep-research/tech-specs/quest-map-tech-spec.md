# Техническая спецификация: Интерактивная карта квестов (Quest Map)

**Маршрут страницы:** `/eft/progress/quests`

Настоящий документ описывает архитектуру, логику взаимодействия и дизайн-систему для модуля продвинутого отслеживания квестов. Модуль представляет собой интерактивный графовый интерфейс (node-based дерево), позволяющий игрокам визуализировать цепочки заданий, фильтровать критические пути (Каппа, Смотритель Маяка) и отмечать свой прогресс в реальном времени.

> **Базовая концепция:** Использование библиотеки `React Flow` для рендера узлов с алгоритмом `dagre` для автоматического выстраивания (auto-layout) сложных иерархических деревьев, исключая необходимость ручного позиционирования сотен квестов.

---

## 1. Архитектура и Технологический стек

* **Графовый движок:** `React Flow` (рендеринг холста, масштабирование, перемещение).
* **Алгоритм Layout:** Библиотека `dagre` (направленные ациклические графы) для автоматического расчета координат `X` и `Y` на основе связей (`prerequisites`).
* **State Management:** `Zustand` (или глобальный React Context) для хранения массива `completedQuests: string[]` и синхронизации с локальным хранилищем/БД.
* **Источник данных:** Локальный скилл `tarkov-api` (GraphQL от `tarkov.dev`), извлекающий объекты квестов с полями `objectives`, `prerequisites`, `minPlayerLevel`, `kappaRequired`, `lightkeeperRequired`.

---

## 2. Дизайн-система: Кастомная нода (QuestNode)

Стандартные блоки заменяются на интерактивные компоненты в стиле "Тактического брутализма". Каждая нода представляет собой карточку фиксированного размера (например, 260x80px).

**Визуальные состояния (Status Mapping):**

| Статус | Условие | UI Индикация (Tailwind классы) |
| :--- | :--- | :--- |
| **Locked** | Предыдущие квесты не выполнены или уровень ЧВК ниже требуемого. | `bg-[#111315] opacity-60 border-dashed border-zinc-700 text-zinc-500` |
| **Active** | Доступен для выполнения (пререквизиты закрыты). | `bg-[#161819] border border-[#e2b13c] shadow-[0_0_10px_rgba(226,177,60,0.2)] text-gray-100` |
| **Completed** | Отмечен пользователем как выполненный. | `bg-[#182216] border border-[#6A8B5D] text-[#739964]` |

**Внутренняя структура карточки:**
* **Левый блок:** Аватарка торговца (50x50px, обрезка по форме).
* **Центральный блок:** Название квеста (шрифт `Blender Pro`, uppercase) и индикатор требуемого уровня.
* **Правый блок:** Интерактивный чекбокс (Toggle) для быстрой смены статуса на `Completed`.
* **Бейджи (Абсолютное позиционирование):** Желтая иконка `[K]` для квестов Каппы, синяя `[Л]` для Смотрителя Маяка.

---

## 3. Логика фильтрации и Дашборд управления

Над графом (или в боковой панели) располагается контрольная панель, которая динамически перестраивает холст.

* **Глобальные цели (Макро-фильтры):**
  * **Путь к Каппе:** Фильтрует граф, оставляя *только* ноды, где `kappaRequired: true`, и их зависимости.
  * **Смотритель Маяка:** Оставляет цепочки, ведущие к `lightkeeperRequired: true`.
* **Фильтры сущностей:**
  * **Торговцы:** Мультивыбор (Прапор, Лыжник и т.д.).
  * **Ивенты:** Теговая фильтрация для сезонных линеек (Борей, Хэллоуин).
* **Калькуляция прогресса:** Динамический счетчик в заголовке, например: `Каппа: 45 / 213 (21%)`.

---

## 4. Интерактивность и UX

* **Быстрое выполнение:** Клик по чекбоксу внутри ноды мгновенно добавляет ID квеста в `completedQuests`, перекрашивает текущую карточку в зеленый и разблокирует дочерние ноды (переводя их из `Locked` в `Active`).
* **Детальная информация (Side Drawer):** Клик по самому телу карточки (не по чекбоксу) открывает правую выдвижную панель (Slide-over / Drawer).
  * Внутри панели: Полный список целей (убить Диких, найти предметы `FiR`), награды (репутация, открываемые бартеры), ссылка на подробный гайд.
* **Smart Edges (Умные связи):** Линии (Edges), соединяющие квесты, анимируются (эффект `animated: true` в React Flow) и подсвечиваются цветом статуса материнской ноды.

## 5. Пошаговый план разработки (Спринты)

| Этап | Задача (Промпт для ИИ) | Ключевой результат |
| :--- | :--- | :--- |
| **Этап 1** | Архитектура графа и Auto-Layout | Интеграция `React Flow` + `dagre`. Построение базового дерева квестов без ручных координат. |
| **Этап 2** | UI-компонент `QuestNode` | Верстка кастомной ноды с тремя состояниями (Locked, Active, Completed) в стиле проекта. |
| **Этап 3** | Глобальный State Management | Подключение `Zustand`, логика сохранения прогресса, динамическое изменение связей при клике. |
| **Этап 4** | Фильтры и Side Drawer | Разработка панели управления (Каппа, Торговцы) и выдвижной панели с деталями квеста. |
