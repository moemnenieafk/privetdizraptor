## 🟢 РЕЗУЛЬТАТЫ СПАЙКА (2026-06-24) — пайплайн жизнеспособен

- **Гейт A (бандлы читаемы офлайн): ПРОЙДЕН.** Бандлы EFT в `StreamingAssets/Windows/assets/content/items/...` — стандартный `UnityFS`, Unity `2022.3.43f2`, **НЕ зашифрованы** (шифрование метадаты режет только код, не ассеты). 4124 бандла предметов, по категориям (equipment/meds/barter/...). Имена описательные, не по id.
- **Гейт B (ракурс камеры под шифрованием): ПРОЙДЕН — главный риск снят.** Бандлы содержат **встроенный typetree**, поэтому `UnityPy.read_typetree()` отдаёт поля `PreviewPivot` ИМЕНОВАННО, несмотря на зашифрованный `global-metadata.dat`. Структура `PreviewPivot.Icon`:
  `rotation` (кватернион — ракурс камеры), `perspective` (FOV°, напр. 15.0), `boundsScale` (вписывание в кадр, напр. 0.876), `orthographic` (0=перспектива), `overrideIcon`. Плюс `pivotRotation`/`pivotPosition`/`scale`.
- **Извлечение:** UnityPy (Python) открывает бандл, экспортирует меш в OBJ (с UV), читает PreviewPivot. Меши/материалы/текстуры — стандартные engine-типы, читаются. (Текстуры — в зависимых бандлах по PPtr, резолвить отдельно.)
- **Рендер:** Blender 5.1 (`--background --python`) импортирует OBJ, ставит камеру по `Icon`-параметрам (FOV, дистанция из boundsScale), рендерит 512×512 RGBA прозрачный (EEVEE). Замкнуто.
- **PoC:** AA-батарейка (`item_battery_aa.bundle`, id `5672cb124bdc2d1a0f8b4568`) отрендерена и сличена с tarkov.dev 512px: **форма/перспектива/масштаб совпали**, расходится только ОРИЕНТАЦИЯ (поворот) — конвертация кватерниона Unity(LH,Y-up)→Blender(RH,Z-up) приблизительная. Скрипты спайка: scratchpad `bundle-probe.py`, `probe-pivot.py`, `render.py`.

### Осталось до продакшен-качества (приоритет)
1. **Точная камера: РЕШЕНО (2026-06-24).** Конвертация `Icon.rotation` Unity→Blender = **raw-переупорядочивание `Quaternion(w, x, y, z)`** (UnityPy кладёт меш уже в Blender-кадр → ось-фикс НЕ нужен, только переставить компоненты). Камера ставится по миру = этот кватернион, дистанция = `(radius/boundsScale)/tan(FOV/2)`, FOV=`Icon.perspective`. Сверка на AA-батарейке: наклон силуэта −51° vs эталон tarkov.dev −41° (~10° остаточно, визуально совпало: направление и торцы точные). Метод подбора — объективный замер угла наклона силуэта через моменты изображения (не глазами). Остаточные ~10° добить позже (возможно микро-roll или boundsScale-нюанс).
2. **Текстуры/материалы: ГОТОВО (2026-06-24).** Паттерн EFT: текстуры предмета лежат в СОСЕДНЕМ `*_textures`-бандле той же папки (напр. `battery_aa/batareiki_textures`). Загрузка папки целиком в одно окружение UnityPy → PPtr `_MainTex`/`_BumpMap` резолвятся → экспорт PNG. Слоты материала: `_MainTex`(albedo), `_BumpMap`(normal), `_Cube`(рефлекс-кубмапа, в общем бандле — пока пропускаем). Назначены в Blender (albedo→Base Color, normal→Normal Map). Результат на батарейке: **узнаваемая «Energymax AA+», этикетка читается, совпадает с tarkov.dev.**

3. **Освещение/материалы/металл: ГОТОВО (2026-06-24).** Рецепт: **world-окружение** (серое ~0.45, strength 0.6) = ровный филл + источник отражений для металла; **студийные sun-лампы** ключ(4.8)/заполнение(1.7)/контровой(1.6); из материала EFT — `_Shininess`→roughness 0.34, `_SpecColor`→specular 0.5; view transform **Standard** (не AgX, иначе десатурация). Результат на батарейке: яркая, ровная, металл-торцы бликуют, этикетка читается — близко к tarkov.dev.
   Параметры материала EFT (кастомный spec/reflect-шейдер): `_MainTex`/`_BumpMap`/`_Cube`, `_Shininess`, `_SpecColor`, `_ReflectColor`(~0.5 — вклад Cube), `_SSRPow`.

4. **Генерализация + маппинг + оркестратор: ГОТОВО (2026-06-24).** Скрипты в `scripts/icon-render/`:
   - `extract_item.py` — бандл → меши(OBJ) + текстуры(albedo/normal) + `meta.json` (Icon-параметры). Зависимости резолвятся через `Windows.json` (`Dependencies`, включая `cubemaps`/`shaders`).
   - `render_item.py` — `meta.json` → 512px PNG (Blender, камера/свет/материалы параметрически).
   - `resolve_bundle.py` — `template-id → бандл`: источник 1 = BSG `items.json` `_props.Prefab.path` (= ключ `Windows.json`, НАДЁЖНО); источник 2 = name-fallback по `items_database.json` (локально, но НЕНАДЁЖНО).
   - `render_missing.mjs` (`npm run icons:render-missing`) — оркестратор: список недостающих (`src/data/icon-backfill-eft.json`) → resolve→extract→render→webp→upload (service-role). Флаги `--upload`/`--ids`/`--items`. **ЛОКАЛЬНЫЙ** (Blender+UnityPy+файлы игры, не Vercel).
   - Проверено end-to-end: `id → бандл → extract → render → webp` (батарейка ✓, золотая цепь/мед/сигареты — рендерятся).

### Осталось
- **items.json (Prefab.path) — КЛЮЧЕВОЙ недостающий ВХОД для точного маппинга.** Без него name-fallback промахивается (пример: «Golden neck chain» → по токену «chain» смапился на пистолетную рукоять). С items.json — точно. items.json = стандартный датамайнинг-артефакт, обновляется по патчам. Достать/сгенерировать и положить, передавать `--items`.
- **Edge-case текстур:** часть предметов рендерится без текстуры (напр. пачка сигарет — `_MainTex` не нашёлся; вероятно другой слот/несколько материалов). Доработать extract.
- **Микрокосметика:** насыщенность красного, наклон ~10°, точный `_Cube`-рефлекс.
- **Оружие/пресеты** (Гейт 3) — сборка из множества бандлов-деталей по дефолт-пресету.

### Архитектура авто-заполнения (два дозаливщика)
1. **Серверный крон `sync-icons`** (`src/db/icons.ts`) — авто-зеркалит готовые 512px с tarkov.dev, ежечасно, без участия.
2. **Локальный `render_missing.mjs`** — рендерит из клиента то, чего у tarkov.dev НЕТ; запускать после патча.
3. **Маппинг id↔бандл:** BSG `items.json` → `_props.Prefab.path` → путь бандла. Закрывает «как назвать выход» для НОВЫХ предметов.
4. **Оружие/пресеты:** сборка из нескольких бандлов-деталей по дефолт-пресету (самое сложное; Гейт 3).
5. **Перенести спайк-скрипты** из scratchpad в `scripts/icon-render/` когда стабилизируется.

## Зачем

Полная автономия по иконкам предметов: уметь получать 512px-иконки EFT **без tarkov.dev** и **без боевого клиента**. Сейчас закрыто гибридом (синк-крон зеркалит готовые 512px tarkov.dev — `src/db/icons.ts`). Этот пайплайн нужен ТОЛЬКО если независимость от tarkov.dev станет жёстким требованием (или чтобы закрывать самые свежие предметы быстрее, чем их рисует tarkov.dev).

## Что уже установлено (выводы ресёрча — не переоткрывать)

- **Готовых 2D-иконок в бандлах EFT НЕТ.** Иконка рождается рантайм-рендером 3D-префаба (меш + материалы + скрипт `PreviewPivot` = ракурс камеры) через render-to-texture. Значит «распаковать спрайт» нельзя — только «отрендерить самим».
- **IL2CPP-реверс боевого клиента заблокирован:** `global-metadata.dat` зашифрован (`cd66…`, не `af1bb1fa`), BattlEye активен → рантайм-дамп памяти рискован/банабелен.
- **Хеш Icon Cache в текущем EFT (Unity 2022.3) не вскрыт** стандартным криптоанализом (287 достоверных пар, 8 алгоритмов × XOR/разность — 0 совпадений). Перцептивный матч известных иконок РАБОТАЕТ (для эталонных пар), но недостающие предметы матчить не с чем.
- **Офлайн-извлечение из ФАЙЛОВ бандлов — BattlEye-safe** (работа с файлами, не с памятью). AssetRipper/AssetStudio дают меши + материалы/текстуры + PreviewPivot.
- **Истинное разрешение иконки — сеточное:** `(ячейки*63)+1`; «8x» = ×8 (1×1 → 512px). Открытый `create512Image` (the-hideout) даунскейлит hi-res в 512 webp lossless — финальный шаг можно переиспользовать as-is.

## Целевой пайплайн (черновик, 4 фазы)

1. **Офлайн-экстракт (BattlEye-safe).** AssetRipper/AssetStudio из инсталла EFT (игра выключена): для каждого предмета — меш, материалы/текстуры, данные `PreviewPivot` (позиция/ротация камеры), освещение.
2. **Маппинг asset ↔ template-id.** Связать извлечённый префаб/ассет с 24-hex BSG id. Кандидаты: имена ассетов/бандлов, item-таблицы из бандлов, или сверка с нашим каталогом.
3. **Render-to-texture харнесс (главная инженерия).** Headless Unity (или Blender), воспроизводящий preview-камеру BSG: загрузить модель → выставить ракурс из `PreviewPivot` → освещение → рендер в 512×512 (или выше → даунскейл) на прозрачный фон.
4. **Пост и заливка.** PNG → открытый `create512Image` → webp → залить в `cta-media/items/eft/{id}.webp` (переиспользовать service-role-заливку из `src/db/icons.ts`).

## Открытые вопросы / спайки (оценивать по одному в фоне)

## Риски

- **Фиделити кадрирования под BSG трудно повторить точь-в-точь** (особенно оружие). Возможен «похоже, но не идентично» — приемлемо ли для UI?
- **Поддержка каждый патч/вайп** (новые модели, смена форматов бандлов).
- **Юридически:** держим как ВНУТРЕННИЙ дериватив (рендер для своего сайта), не раздаём паки ассетов. Дисклеймер в футере. (См. риск-секцию `[[eft-asset-extraction]]`.)

## Решение / гейты

- **Гейт 1:** спайк камеры+материалов на 5–10 простых предметах (броня/барахло). Если рендер визуально совпадает с tarkov.dev 512px — идём дальше; если нет — пайплайн нежизнеспособен, остаёмся на гибриде.
- **Гейт 2:** маппинг id без хеша. Если нерешаемо — пайплайн бесполезен (нечем именовать выход).
- **Гейт 3:** оружие/пресеты. Если слишком дорого — ограничить пайплайн НЕ-оружием, оружие оставить на tarkov.dev-гибриде.
