# Эволюция распознавалки компаньона (как она становится лучше)

## Главный нюанс (развеять заблуждение)
Наш OCR — **Tesseract**, *предобученная* модель. Она **не учится** на наших скриншотах сама: скорми хоть миллион — движок не изменится. Поэтому «просто больше скриншотов» распознавалку НЕ улучшает.

Что путается — две разные вещи:
- **Распознавалка** (Tesseract + матч имён + геометрия) — от объёма сама не растёт.
- **Итоговая цена** (агрегат) — **растёт уже сейчас**: больше независимых авторов → точнее медиана (случайные OCR-ошибки выбрасываются). Работает без обучения.

**Ключ к обучению — не объём, а РАЗМЕЧЕННЫЕ данные:** пара «кусок картинки → правильное значение». И у нас есть **бесплатный генератор меток** — крауд-медиана + модерация (approve/reject) подтверждают истину. Значит каждый скриншот + подтверждённое значение = готовая обучающая пара. Очередь аномалий = источник меток.

## Слои улучшения (дешёвое → дорогое)
| Слой | Что делает | Стоимость | Когда стоит |
|---|---|---|---|
| **1. Крауд-медиана** | больше авторов → точнее агрегат (гасит одиночные ошибки) | ✅ уже есть | сейчас |
| **2. Лог ошибок** | копим OCR-реады, что модератор поправил → видим СИСТЕМНЫЕ ошибки (₽→«6», миллионы, X/Y) → чиним геометрию/препроцесс руками | дёшево | как пойдёт поток |
| **3. Confidence-флаг** | Tesseract даёт уверенность на слово → низкая → авто-переснять / на ревью / не публиковать | дёшево | после потока |
| **4. Дообучение Tesseract** | тренируем на НАШЕМ шрифте барахолки по размеченному датасету → реальный скачок точности (кир. имена, миллионы, X/Y) | средне | когда меток «достаточно» (сотни-тысячи пар) |
| **5. Vision-модель** (multimodal LLM / кастом) | читает всю карточку без геометрии | дорого (per-image) | если 1–4 упрутся в потолок |

## Пайплайн накопления датасета (что построить)
Цель — из модерации сама собой копилась обучающая выборка, «для галочки» ничего вручную не размечая.
1. **Хранить сырьё скриншота фрагментами.** При сабмите ридер уже вырезает кропы (цена/имя/X/Y). Опционально грузить эти кропы (или их хэши/мелкие пруфы) в бакет с привязкой к оффер-id. ⚠️ приватность/объём — только с согласия, сжато, TTL.
2. **Метка = подтверждённое значение.** Когда крауд-консенсус (N независимых → одно значение) ИЛИ модератор approve → это ground-truth для тех кропов. Reject/поправка → «трудный пример» (самое ценное для обучения).
3. **Таблица `ocr_samples`** (позже): {кроп-ref, тип (price/name/uses), ocr_read, confirmed_value, source (consensus/mod), created_at}. Растёт сама из потока.
4. **Экспорт → дообучение.** Периодически выгружаем размеченное → fine-tune Tesseract (traineddata на шрифте) или тренируем маленький распознаватель. Замеряем на hold-out.

## Дешёвые «умные» механики ДО обучения (ставить первыми)
- **Лог поправок** (слой 2): фиксировать, что модератор изменил/отклонил → ручной разбор системных багов (как чинили ₽/миллионы/имена). Максимум пользы за минимум работы.
- **Confidence-порог** (слой 3): Tesseract возвращает per-word confidence — низкая уверенность цены → в очередь / не в публикацию.
- **Кросс-чек якорем** (уже есть): tarkov.dev ref ловит грубые ошибки → и это тоже сигнал для лога.
- **Консенсус-метки:** N авторов независимо → одно значение = высокодоверенная метка без модератора.

## Итог
- **Объём помогает ВЫХОДУ уже сейчас** (медиана), а РАСПОЗНАВАЛКЕ — только когда объём превращается в **размеченный датасет** (что наша модерация и делает бесплатно).
- Порядок: слой 1 (есть) → слой 2 (лог ошибок, дёшево, первым) → слой 3 (confidence) → слой 4 (дообучение Tesseract, когда меток хватит) → слой 5 (vision) при упоре.
- Отличать от [[companion-anomaly-detection]]: там самообучение *порогов* аномалий; здесь — самообучение *самого OCR*. Оба питаются одним источником — решениями модератора.
