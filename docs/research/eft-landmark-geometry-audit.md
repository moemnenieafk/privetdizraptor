# Инвентаризация застройки карт EFT и цена знакового здания

Спутник заметки `docs/research/deep-research-3d-clay-maps.md`. Та намерила **экструзию**
(Развязка 456 тыс. tri, Таможня 367 тыс., Улицы 314 тыс.; наземный этаж Таможни в `.glb` —
65 148 tri / 1 draw call / 139 КБ по проводу). Здесь меряется **вторая половина гибрида A+C**:
сколько построек реально лежит в наших артефактах, какие из них годятся в знаковые
и во что обходится одно такое здание настоящей геометрией клиента.

Всё считано 2026-09-05 скриптом **`scripts/eft-map-layers/inventory-buildings.py`**
(`inventory` / `cost` / `extrusion` / `affines`) по готовым артефактам. Конвейер не перезапускался.

## Вердикт

**Гибрид проходит по бюджету 410 тыс. tri при K ≤ 5 знаковых зданий — и только если
знаковый меш децимирован примерно в 5–10 раз, а в кадре живёт один этаж, а не все сразу.
Сырую геометрию клиента брать нельзя ни при каком K.**

Три числа, на которых держится вывод (все — **замер**, Резерв, где есть полный дамп сцены):

| Одно знаковое здание | Треугольников | Отношение к экструзии |
|---|---|---|
| Экструзия его же пятна (наши контуры, фильтр ≥0.5 м² + RDP 0.15) | **2.5–5.3 тыс.** | ×1 |
| Клиент, **только оболочка** (стены, крыши, каркас) | **240–585 тыс.** | **×80…×156, медиана ≈120** |
| Клиент, **всё, что физически в пятне** (оболочка + мебель, трубы, лут) | **1.4–5.0 млн** | ×400…×1100 |

Пример дословно: `Reserv_academy_w_kitchens` (Академия Резерва, пятно 3 941 м²) — экструзия
**4 696** треугольников, оболочка из клиента **384 736**, всё содержимое пятна **5 014 761**.

➡️ **Знаковое здание — это не «дорого», это на два порядка дороже.** Десять зданий сырой
оболочкой = ≈2.7 млн треугольников, в 6.6 раза больше всего бюджета прототипа.
Бюджет «≤300 тыс. tri на 10 знаковых» из предыдущей заметки означает **30 тыс. на здание**,
то есть децимацию оболочки в **8–10 раз** — цифра выполнимая (gltfpack `-si`, Blender Decimate),
но её обязательно надо проверить глазами: именно она решает, останется ли силуэт узнаваемым.

**Второй вывод, неожиданный.** Мы искали цену знакового меша, а нашли, что
**вопрос «как это здание зовут» закрыт полностью, тремя независимыми мостами** (§5):

1. **Имена BSG прямо в наших артефактах** — `<карта>-rooms.json`: `buildings[].name` + `path`
   + AABB в игровых метрах, и отдельно `rooms[].name` + `center` (в SVG это `<g id="room-labels">`).
   Утверждение «имён зданий в артефактах нет» **опровергнуто**.
2. **Подписи игроков в тех же координатах** — `labels` из `maps.json` tarkov.dev.
   72 подписи по четырём картам легли внутрь наших построек; **систематического сдвига
   координат нет** (медиана ≤2 м по обеим осям) — наши аффины и игровые координаты
   tarkov.dev это одна система.
3. **Реестр `docs/registry/`** — `bboxZ6` пересчитывается в игровые метры через аффину арта.

Побочный улов: в реестре нашлись **две доказуемо перепутанные метки** (`T-0087` «Старая
заправка» — на самом деле Склад 17, `T-0089` «Crackhouse» — на самом деле Бойлерная),
а спор «Общага двух- или трёхэтажная» **закрыт данными клиента**, а не голосованием
источников (§5.9).

## 1. Инвентарь застройки по картам

Источник — `buildings[]` из `<карта>-rooms.json`: прямые дети узла `BUILDING`/`BUILDINGS`
в иерархии BSG, с AABB в игровых метрах. Перекрёстно сверено с `<g id="buildings">`
в `gen/<карта>/rooms/*.svg`: `rooms.json` → аффина слоя → `<rect>` совпадают до десятых пикселя
(проверено на `KPP` Таможни: AABB `[576.58,−1.62]…[588.32,10.12]` → расчётный
`x=14011.2 y=6905.3 w=154.3` против записанного в SVG `x="14010.8" y="6905.3" width="154.3"`).

⚠️ **Дедупликация.** Сумма поля `buildings` по слоям в `*-rooms-frame.json` **не равна** числу
зданий: `render-rooms.py` кладёт здание в слой по центру его AABB, а полосы этажей у части карт
перекрываются. Уникальных зданий Таможни **129**, а сумма по слоям — 212. В таблице ниже —
уникальные.

но с одной записью (`platform_opora`, ж/д платформа). Для этих трёх карт **инвентарь застройки
по классу невозможен**, и кандидатов в знаковые придётся отбирать иначе (§7).

**Этажность считается по ИМЕНАМ комнат, не по высотам.** Столбец «Этажей (имена)» —
число уникальных этажных меток (`_f1`…`_f9`, `stage_N`, `basement`) в именах комнат внутри
пятна. Это источник уровня «файлы игры». Первая версия скрипта считала этажи кластеризацией
комнат по высоте (разрыв >2.2 м) — **метрика оказалась негодной**: на общагах Таможни комнаты
идут по Y непрерывно и все три этажа склеиваются в один кластер. Признак доступен не везде:
этажные суффиксы есть у 39 % комнат Таможни и 28 % Резерва, у остальных карт 0–7 % (§5.9),
поэтому «0 этажей» в таблице значит «меток нет», а не «один этаж».
Столбец «Комнат» — сколько комнат клиента внутри пятна; у фоновых силуэтов он нулевой,
и это второй фильтр «настоящее здание или декорация».

## 2. Цена знакового здания — замер

### 2.1 Источник, о котором мы не знали

`dump-occluders.py` (резак для рендера камней) оставляет в
`D:/eft-export/<карта>/render-objects/` файл **`<карта>-occluders.json`**: **все** экземпляры
геометрии сцены (`mesh`/`x`/`y`/`z`/`quat`/`scale`) плюс прототипы с готовым полем **`tris`**,
и рядом `occl-meshes/*.npz` с самими вершинами и треугольниками. Это прямой замер, а не оценка.

Дамп есть **не у всех карт** (он делался только под ночной прогон рендера с резаком):

|---|---|---|---|
| Терминал | 3 024 | 86 674 | 134 891 742 |
| Развязка | 3 911 | 88 090 | 106 782 733 |
| Маяк | 6 565 | 72 626 | 63 723 324 |

⚠️ У Терминала число надо делить пополам: в клиенте каждая его сцена лежит **дважды**

Из резака сцены не дедуплицированы.

### 2.2 Как считалось

Для каждого здания из топ-30 суммируются треугольники экземпляров, чей **пивот** лежит
в его AABB (по XZ точно, по Y с запасом ±3 м). Пивот, а не полный AABB меша: точный тест
потребовал бы прочитать тысячи `.npz` на здание. Погрешность двусторонняя — часть мешей
с пивотом снаружи не попадает, часть мелочи у стены попадает лишняя.

Разделение **оболочка / начинка** сделано **по габариту прототипа**, а не по имени:
`dump-occluders.py` имена в выход не пишет (хотя читает их — см. §6). Из каждого `.npz`
взят локальный AABB, и структурным считается меш шире **6 м** по горизонтали или выше **4 м**.
Это эвристика; на глаз она отделяет стены, крыши, перекрытия и каркас от мебели, труб,
ящиков и лута. По всей сцене Резерва такой фильтр оставляет **25 %** треугольников
(14.4 млн из 58.2 млн) — правдоподобная доля.

## 3. Бюджет гибрида

### 3.1 Что складываем

Все числа — **мой замер** тем же скриптом; методика (фильтр площади ≥0.5 м², RDP 0.15 м,
`3V−2` треугольника на контур) взята из `deep-research-3d-clay-maps.md` §0.1, чтобы числа
были сравнимы. Проверка сходимости: на Резерве я получил **172 874** против **172 516**
в той заметке — расхождение **0.2 %**, на Ground Zero 3.2 %, на Береге 5.1 %. Парсер сходится.

| Карта | Экструзия, все этажи | Экструзия, наземный этаж | Рельеф, шаг 4 м | Дороги (fat lines) |
|---|---|---|---|---|
| Таможня | 276 863 | **90 770** | 126 052 | ≈42 000 |
| Резерв | 172 874 | **107 928** | 39 738 | **0 — слой пуст** |
| Улицы Таркова | 237 584 | **47 669** | 62 336 | ≈30 000 (оценка) |

Рельеф: `2 × (ΔX/4) × (ΔZ/4)` от `bounds` в `frame.json`. Дороги Таможни — из
`deep-research` §2.5 (1 236 путей / 8 240 вершин × 6 tri на сегмент).

🔴 **Расхождение с предыдущей заметкой по Таможне объяснилось, и это дефект артефактов.**
В `gen/customs/walls/` лежат **три байт-в-байт одинаковых файла**: `customs-walls-main.svg`,
`customs-walls-floor0.svg`, `customs-walls-floor1.svg` (по 42 896 tri каждый). В `frame.json`
слоёв `floor0`/`floor1` нет — это остатки более раннего прогона. Предыдущий замер брал
каталог целиком (12 файлов) и **посчитал наземный этаж трижды**: 362 655 вместо 276 863,
то есть **завысил Таможню на 85 792 tri (23 %)**. Файлы `floor0`/`floor1` надо снести.

### 3.2 Сцена в кадре

Ключевая развилка: **сколько этажей в кадре одновременно.** Во вьюере этаж гейтится
переключателем — значит в бюджет честно идёт **один** этаж, а не сумма.

| | Таможня | Резерв | Улицы |
|---|---|---|---|
| Все этажи + рельеф + дороги | **444 915** | 212 612 | 329 920 |
| **Один (наземный) этаж + рельеф + дороги** | **258 822** | **147 666** | **140 005** |

Уже на этом шаге видно: **режим «вся карта всеми этажами» на Таможне выходит за 410 тыс.
ещё до первого знакового здания.**

### 3.3 K знаковых зданий

Из бюджета вычитается экструзия их собственных пятен (замер, все этажи):
Таможня K=3 → −28 903, K=5 → −36 006, K=10 → −69 405;
Резерв −12 091 / −17 519 / −29 124; Улицы −15 895 / −21 132 / −32 033.

Итог для трёх карт платного релиза, режим «один этаж в кадре» (тыс. треугольников):

| Карта | K | Сырая оболочка клиента (≈150 тыс./шт) | Децимация ×5 (30 тыс./шт) | Децимация ×10 (15 тыс./шт) |
|---|---|---|---|---|
| **Таможня** (база 259) | 3 | 700 ❌ | **340 ✅** | **295 ✅** |
| | 5 | 995 ❌ | **400 ✅** (впритык) | **325 ✅** |
| | 10 | 1 740 ❌ | 540 ❌ | **370 ✅** |
| **Резерв** (база 148) | 3 | 590 ❌ | **229 ✅** | **184 ✅** |
| | 5 | 886 ❌ | **291 ✅** | **216 ✅** |
| | 10 | 1 632 ❌ | 432 ❌ | **272 ✅** |
| **Улицы** (база 140) | 3 | 578 ❌ | **217 ✅** | **172 ✅** |
| | 5 | 874 ❌ | **279 ✅** | **204 ✅** |
| | 10 | 1 620 ❌ | 420 ❌ | **260 ✅** |

Вес по проводу — по измеренному в `deep-research` §0.4 курсу **2.13 КБ на 1000 tri**
(meshopt + brotli): 340 тыс. tri ≈ **0.72 МБ**, 400 тыс. ≈ **0.85 МБ**, 540 тыс. ≈ **1.15 МБ**.
Ни один вариант не упирается в вес — упирается всё в треугольники.

**Draw calls.** Знаковые здания идут обычными `Mesh` — по одному на здание (плюс LOD).
При раскладке из `deep-research` §4.4 (экструзия этажа 1 call на класс, рельеф 1, дороги 1–2,
метки 1 на иконку) K = 10 даёт ≈25–35 calls, K = 5 — ≈20–30. **В бюджет ≤12 calls
из постановки не влезает ни один вариант с десятью зданиями**: только знаковые съедают 10.
Либо K ≤ 5 и слияние всего остального в 5–7 вызовов, либо потолок 12 надо поднимать до 30
(что соответствует и рекомендации Mugen87 «идеально ~20», и вердикту предыдущей заметки).

### 3.4 Что из этого следует

1. **Сырая клиентская оболочка не годится ни при каком K.** Даже одно здание —
   треть-половина всего бюджета.
2. **K = 5 при децимации ×5 (30 тыс. tri на здание) — рабочая точка** на всех трёх картах релиза.
3. **K = 10 требует 15 тыс. tri на здание** — это децимация ×10, и вот тут силуэт может
   поехать. Проверять глазами, а не расчётом.
4. **Один этаж в кадре — не оптимизация, а условие.** На Таможне это разница 445 → 259 тыс.
5. Потолок draw calls надо назначить **30**, а не 12.

## 4. Топ-30 крупнейших построек по картам

Координаты — **центр AABB в игровых метрах** (те же оси, что в `frame.json` → `affine`;
сходимость с игровыми координатами tarkov.dev проверена, §5.1).
«Имя игрока» — подпись из `maps.json` tarkov.dev, попавшая **внутрь** пятна (§5.1).
«Кластер комнат BSG» — два самых частых префикса имён комнат внутри пятна (§5.9).
«Мешей» — мешей в поддереве BSG. «Комнат» — комнат клиента внутри пятна.
«Этажей (имена)» — уникальных этажных меток в именах комнат (`_f1`, `stage_N`, `basement`);
ноль означает «меток нет», а не «один этаж». «Экструзия» — треугольники наших контуров
внутри пятна (замер). «Клиент» — только там, где есть дамп сцены (§2.1).

## 5. Имена: три моста от геометрии к тому, как здание зовут игроки

### 5.1 🔑 Прямой мост — подписи tarkov.dev в тех же игровых координатах

`https://raw.githubusercontent.com/the-hideout/tarkov-dev/main/src/data/maps.json`
(легальный транспорт по §4.12: статический файл, не GraphQL) отдаёт по каждой карте массив
`labels` — текст плюс `position: [x, z]` **в тех же игровых координатах**, в которых лежат наши
AABB зданий. Никакого пересчёта не нужно: подпись либо попадает внутрь пятна постройки, либо нет.

**Сходимость систем координат — замер, а не допущение.** По четырём картам 72 подписи
попали внутрь какой-нибудь постройки из нашего инвентаря; систематического сдвига нет:

| Карта | Подписей | Попали внутрь постройки | Медиана dx | Медиана dz | Медиана расстояния до центра | Макс |
|---|---|---|---|---|---|---|
| Таможня | 24 | 15 | **−1.7 м** | +1.2 м | 4.8 м | 18.2 м |
| Резерв | 27 | 15 | **−0.1 м** | −0.2 м | 2.9 м | 28.9 м |
| Улицы Таркова | 46 | 33 | **+0.5 м** | −0.1 м | 5.5 м | 62.3 м |
| Ground Zero | 13 | 9 | **−2.0 м** | −0.8 м | 3.3 м | 23.6 м |

➡️ **Наши аффины и игровые координаты tarkov.dev — одна система, расхождения нет.**
Медианный сдвиг ≤2 м по обеим осям на всех четырёх картах; остаточное расстояние 3–6 м —
это разница «центр пятна» против «где подпись удобно поставить на карте», а не ошибка привязки.
Отдельного «расхождения 7.6 м», как на Таможне в другом контексте, тут не наблюдается.
Единичные выбросы (62 м на Улицах) — подписи улиц, а не зданий (`Primorsky Ave.` стоит
посреди проезжей части).

Подписи есть у **Таможни (24), Резерва (27), Улиц (46), Ground Zero (13), Берега (20), Леса (16)**;
у **Терминала — ноль**. У Берега и Леса они бесполезны для нашей задачи: инвентаря застройки
там фактически нет (§1, §7.4).

### 5.10 Стороны света — считать из ротации, не из вики

`json.tarkov.dev/regular/maps` отдаёт `coordinateToCardinalRotation` (Резерв θ = 195.209°,
Развязка θ = 180°), пересчёт: `E = cosθ·x − sinθ·z`, `N = sinθ·x + cosθ·z`.
Мы этим **не пользовались**: все замеры и таблицы ниже — в сырых игровых `x`/`z`, компас
нигде не участвует. Отмечаю потому, что колонка «часть карты (запад/центр/восток)»
в `docs/registry/customs-landmarks.md` компасу противоречит: `Dorms` там помечены «восток»,
а лежат в `x = +207`; `Big Red` помечен «запад» при `x = −210`. Пока стороны света
не пересчитаны из `coordinateToCardinalRotation`, эту колонку реестра **как факт не использовать**
— и на Резерве отдельно помнить, что внутриигровая карта нарисована севером вниз.

## 8. Что осталось неизвестным

1. **Цена знакового здания измерена только на Резерве, Терминале и Береге.** У Таможни,
   Улиц, Ground Zero и Ледокола дампа сцены (`<карта>-occluders.json`) нет, и числа для них —
   **оценка** по плотности tri/м². Закрывается прогоном `dump-occluders.py` по этим картам
   (скрипт возобновляемый, переписывать ничего не надо).
2. **Разделение «оболочка / начинка» — эвристика по габариту** (≥6 м по горизонтали или ≥4 м
   по вертикали), а не по именам. Имена в дампе резака не сохраняются, хотя читаются.
   Погрешность не оценена: длинная труба или забор попадут в «оболочку», низкая пристройка — нет.
3. **Децимация не проверена ни разу.** Весь вердикт §3 держится на допущении, что оболочку
   в 300 тыс. tri можно свести к 30 тыс. без потери силуэта. Ни gltfpack `-si`, ни Blender
   Decimate на нашей геометрии не запускались. Это следующий шаг и он обязателен.
4. **Тест «пивот в пятне» вместо честного пересечения AABB.** Меш с пивотом снаружи не
   учитывается, мелочь у стены учитывается лишняя. На больших зданиях ошибка невелика,
   на узких (Общага) может быть заметной.
5. **Расхождение ±24 % по Улицам и Терминалу с предыдущей заметкой** (§7.5) не объяснено.
   Пока обе оценки надо считать вилкой.
6. **У Развязки, Маяка и Леса инвентаря застройки нет** — узла `BUILDING` в иерархии BSG
   нет вовсе. Как отбирать знаковые там, не решено: вероятный путь — кластеризация
   `props`-экземпляров из резака по плотности, но это отдельная задача.
7. **Знаковые за пределами узла `BUILDING`**: мосты (Главный, Мусорный), Трейлерный парк,
   Снайперская гряда, рубильник ZB-013 — в `buildings[]` не попадают по определению.
   Для них нужен другой отбор.
8. **Русские имена есть только у Таможни.** Имена BSG теперь есть у всех карт, подписи
   игроков (англ.) — у шести, но русская номенклатура V4DYA/комьюнити существует только
   в `customs-landmarks.md`. Где русского имени нет, в таблицах стоит английская подпись
   tarkov.dev или имя BSG — перевод не выдумывался.
8b. **Этажность по именам недоступна на восьми картах из десяти** (§5.9). На Терминале,
   Развязке и Ледоколе этажных суффиксов ноль; чем их заменить — не решено.
8c. **Стороны света не пересчитывались.** `coordinateToCardinalRotation` из
   `json.tarkov.dev/regular/maps` не применялся: все числа отчёта — сырые `x`/`z`.
   Колонка «часть карты» в `customs-landmarks.md` компасу противоречит (§5.10) и до
   пересчёта не пригодна.
8d. **Импостеры не отделены от настоящих зданий.** На Улицах и Ground Zero часть крупнейших
   пятен — узлы `*_Imposters` / `*_LODLAST` (дальние заглушки). В топ-30 они остались:
   фильтра по суффиксу имени я не ставил, чтобы не потерять настоящие узлы со схожими
   именами. Перед выбором знакового меша это надо разобрать вручную.
9. **Аффина арта выведена, а не найдена в конфиге.** Переход `bboxZ6` → игровые метры
   опирается на совпадение аффины `customs-stones.json` с калибровкой тайлов из
   `eft-map-config.ts` через вертикальный леттербокс 4 054 px. Совпадение подтверждено
   пятью независимыми попаданиями по именам сцен плюс подписью `New Gas` из tarkov.dev
   (расхождение 6 м), но формально это вывод, а не документ.
10. **Три карты (Завод, Лаборатория, Лабиринт) не собраны вовсе** — каталоги `gen/factory`,
    `gen/the-lab`, `gen/labyrinth` пустые. Это уже записано в хендоффе конвейера.

## Инструмент

`scripts/eft-map-layers/inventory-buildings.py` — четыре команды:

```
python inventory-buildings.py inventory [карта ...]   # инвентарь + топ-30, json
python inventory-buildings.py cost <карта> [--top N]  # треугольники клиента в пятне здания
python inventory-buildings.py extrusion <карта>       # треугольники экструзии, карта и пятна
python inventory-buildings.py affines [карта ...]     # сверка аффин слоёв
```

Читает только готовые артефакты (`gen/`, `D:/eft-export/`), ничего не пересобирает и не пишет
в них. Вывод — json на stdout; для Windows-консоли нужен `PYTHONIOENCODING=utf-8`.
