# Deep research: MapLootEditorLite + TarkovMapTracker

Разбор двух репозиториев из секции «На подумать» ([[maps-marker-render]]). Вывод: **обе техники применимы к CTA**, причём трекинг игрока — почти готов (мы уже владеем нужной математикой проекции).

---

## 1. TarkovMapTracker (M4elstr0m) — трекинг игрока на карте

**Что это:** десктоп-приложение (Go + Wails v3, только Windows, только скомпилированный `.exe` в релизах — исходников в репо нет). Рисует живую позицию игрока на картах tarkov.dev/Shebuka. Лицензия **CC BY-NC-ND 4.0** (нельзя переиспользовать/модифицировать код и распространять производные).

**Как работает «распознавание скриншотов» (главная фишка):**
Это **НЕ** компьютерное зрение. EFT сам **запекает мировые координаты игрока и кватернион поворота камеры прямо в ИМЯ ФАЙЛА** скриншота. Когда игрок жмёт игровую клавишу скриншота, EFT пишет PNG в `Documents/Escape from Tarkov/Screenshots/` с именем вида:

```
2026-07-08[21-47]_-124.6, 3.4, 512.8_0.0, 0.71, 0.0, 0.70_0.00.png
                  └── x,  y,  z ──┘ └── qx, qy, qz, qw ──┘
```

- `x, y, z` — мировые координаты (Unity; **y = высота/этаж**).
- `qx..qw` — кватернион поворота камеры → yaw (куда смотрит игрок).

Приложение: watcher папки (`fsnotify`) → ловит новый PNG → парсит имя → `(x,z)` через тот же трансформ карты → точка игрока + стрелка направления. POI (выходы/лут) — из tarkov.dev.

> Косвенно подтверждается видео «We Found a Cheat That Exploits Tarkov Screenshots» — утечка позиции через имя файла давно известна.

**BattlEye-безопасно:** читается файл, который сам игровой клиент записал на диск. Никакого доступа к процессу игры. Та же категория, что динамическая карта tarkov.dev — не чит (прямая цитата из их README: *"this is not a cheating software"*).

### Почему для CTA это почти готово
Мы **уже владеем идентичным трансформом** (`src/data/eft-map-config.ts`):
```
imgX = x * transform[0] + transform[1]
imgY = z * transform[2] + transform[3]   → поворот на coordinateRotation
```
Значения совпадают с tarkov.dev (Customs `[0.239, 168.65, 0.239, 136.35]`, rot 180) — это тот же трансформ, что мы применяем к маркерам. Спроецировать игрока из имени файла = переиспользовать то, что уже работает.

### Как встроить в CTA — БЕЗ десктоп-приложения (браузерно)
**File System Access API** (Chrome/Edge): кнопка «Отслеживать позицию» → `showDirectoryPicker()` один раз даёт доступ к папке `…/Escape from Tarkov/Screenshots` → JS каждые ~1-2с читает свежий `.png`, парсит имя → трансформ → маркер игрока + стрелка (yaw из кватерниона) на нашем Leaflet.
- 100% клиент, без бэкенда, без рантайм-вызовов tarkov.dev (§4.11 не нарушается).
- **Бонус:** `y` (высота) → авто-выбор этажа на мультиэтажных картах (у нас уже есть floor-фильтр!).
- Клиентский компонент поверх `MapViewerClient`; хук `usePlayerPosition` (dir-handle + poll + parser + quaternion→yaw).

**Ограничения:** апдейт по нажатию клавиши скриншота (как у оригинала, ~1 точка/нажатие, не непрерывно); Factory/Labs — поворот ненадёжен (их known issue); File System Access API — только Chromium (для не-Chromium нужен fallback: ручной drag&drop скриншота или мини desktop-companion).

**Оценка усилий:** S-M. Парсер имени + dir-poll + quaternion→yaw + маркер. Переиспользует трансформ и floor-логику. Код с нуля (их лицензия ND).

**Перед реализацией:** снять один реальный скриншот EFT и сверить точные разделители имени (запятые/подчёркивания могут отличаться по версии/локали).

## 2. MapLootEditorLite (ShaneeexD) — авторинг реальных позиций

**Что это:** мод-фреймворк для **SPTarkov 4.0.13** (C# 84% BepInEx клиент-плагин + TypeScript 15% серверный мод + веб-тул). Зависит от WTT-CommonLib.

**Workflow:** **в рейде жмёшь F8 → ставишь маркер в текущей позиции игрока** → экспорт в JSON-паки (`SPT/user/mods/MapEditorLite/packs/`). Серверный мод читает пак и инжектит контент в лут-таблицы рейда. Маркеры: спавны лута, зоны лута, статик-объекты, интерактив, спавны ботов, зоны выходов, зоны света. Есть `api_item_names.json` (справочник предметов).

**Ключевая ценность для CTA:** это **инструмент авторинга реальных координат**, не готовый датасет. Но он закрывает наш пробел из [[maps-marker-render]] Фаза F: **SPT сервер-БД НЕ хранит XYZ контейнеров** (лежат в клиентских бандлах). А тут — стоя рядом с объектом in-raid, F8 читает **точную мировую позицию** и пишет её в JSON `{x,y,z}` в **той же координатной системе**, что наш трансформ → ложится 1:1.

**Практическое применение:**
- Ручной сбор недостающих позиций (контейнеры, кастомные объекты) для карт, где tarkov.dev неполон, или для наших статик-карт (Ледокол/новые). Мы (или доверенный человек с SPT) авторит пак → мы парсим JSON → в mirror-таблицу или `src/data/map-markers/*`.
- Формат `{x,y,z}` совместим с `EFT_MAP_CONFIG` напрямую.

**Ограничения/риски:** нужен SPT-инстанс + WTT-CommonLib; сбор ручной и трудоёмкий (не bulk-автоматизация); **только офлайн SPT** — не запускать на live (BattlEye). Код C#/TS — не копируем, берём только паттерн JSON-пака.

## Итоговые рекомендации (приоритет)
1. **Трекинг игрока (браузерный, File System Access API)** — высокая ценность, низкий-средний труд, переиспользует наш трансформ+этажи. Кандидат в отдельное решение/спринт. Чисто, BattlEye-safe.
2. **MapLootEditorLite как источник недостающих координат** — держать в уме как способ добрать позиции, которых нет в tarkov.dev (контейнеры in-raid), без реверса. По необходимости, не сейчас.

**Не блокеры, оба — «на будущее».** Ни один не требует нарушать §4.11 (наш бэкенд остаётся единственной рантайм-точкой; трекинг — чисто клиент по локальному файлу).
