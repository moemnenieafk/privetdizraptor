# Детект аномалий companion-цен + самообучающиеся пороги

## Цель
Companion — внутренний источник правды, публикуется ТОЛЬКО после модерации. Аномальное отклонение companion-цены от текущей (демпинг/накрутка/грубый OCR) → **в очередь на ревью**, не молча дропать и не показывать игроку. «Кто-то демпит рынок на 100К» — модератор должен это увидеть.

## Референс (от чего меряем отклонение)
1. **Текущая цена tarkov.dev** (`prices.avg24h/lastLow`) — спот-референс.
2. **Собственная история предмета** (`price_history`, 60 дней) — даёт НОРМАЛЬНУЮ волатильность предмета (сколько он обычно скачет за сутки). Ключ к самообучению.

## Пороги — ОБА (решение V4DYA), тестируемые
- **Относительный:** `|comp − ref| / ref > R%` — ловит дешёвые предметы.
- **Абсолютный:** `|comp − ref| > A₽` (условно 100К) — ловит крупный демпинг дорогих даже внутри %-коридора.
- Флаг, если сработал ЛЮБОЙ (или комбинированный скор). `R`, `A` — **калибруются на данных** (стартовые — приоры, не истина).

## Самообучение (адаптивная часть — суть запроса)
Захардкоженные пороги плохи: волатильный предмет (скачет 30%/день) и стабильный (2%/день) нельзя мерить одной линейкой. Два уровня обучения:

1. **Из истории (data-driven пороги):** для каждого предмета считаем его волатильность из `price_history` (MAD/σ суточных цен). Аномалия = отклонение сверх `N × волатильность_предмета`. Волатильный → шире допуск, стабильный → уже. Пороги R/A становятся ПЕР-ПРЕДМЕТНЫМИ и обновляются по мере накопления истории. Это и есть «самообучение» на первом уровне.
2. **Из решений модератора (feedback-loop):** approve/reject — обучающий сигнал. Approve флага → было реальной ценой → снижаем чувствительность предмета/категории. Reject → подтверждённая аномалия → детект верен. Со временем пер-предмет/категория чувствительность тюнится по соотношению approve/reject. Позже — полноценный классификатор.

## Типы аномалий (различать)
- **OCR-ошибка** — случайная, одиночная, некоррелированная → медиана гасит, но одиночный trusted-сабмит пролезет → нужен якорь.
- **Демпинг/накрутка** — несколько заниженных/завышенных сабмитов, устойчиво во времени, возможно с новых аккаунтов (низкая карма) → главная цель очереди.
- **Реальный сдвиг рынка** — подтверждён многими независимыми авторами, постепенный, согласуется с трендом истории → НЕ аномалия (не зарубить зря).

## Фазы реализации
- **✅ P1 · Фундамент (сделано 2026-07-24):** таблица `companion_anomalies` (PK game+item, отклонение %/₽, статус) + `profiles.banned`. `detectCompanionAnomalies` (порог R=40% ИЛИ A=100К, стартовые) — **инлайн** при сабмите + **крон** `/api/cron/detect-anomalies` (vercel.json 06:00). Очередь `/admin/anomalies` (`canModerate`): **принять/отклонить/бан**; API `/api/admin/anomalies`. Бан = zero-tolerance: `isBanned` блокирует сабмит, `resolveAnomaly('ban')` банит авторов предмета + вычищает их вклад. **Штраф кармы за reject** — хук на потом (V4DYA: «продумать за что»). Решения: пороги R=40/A=100К, очередь в /admin, детект и-и. Осталось из P1: точечный бан конкретного автора (сейчас блант — все авторы предмета), публикация approved.
- **P2 · Самообучение (после данных):** пер-предметные пороги из `price_history` (волатильность); feedback-тюнинг чувствительности по решениям модератора.

## ⚠️ Data-caveat
Самообучение НЕ на чем тренировать сейчас (все данные — чистые trusted V4DYA). Нужен реальный краудсорс + история решений модератора. Поэтому: P1 со стартовыми приорами (R/A конфиг) → собираем данные + решения → P2 калибрует/учит. Пороги в P1 — заведомо «на потестировать».

## Открытые решения
1. Стартовые приоры R (%), A (₽) — с чего начать тестить (напр. R=40%, A=100К?).
2. Где живёт очередь — `/admin` или раздел модерации `/eft/comlink`.
3. Штраф за reject — сколько кармы снимать (и порог до бана).
4. Детект — крон (периодически) или инлайн при агрегации/сабмите.
