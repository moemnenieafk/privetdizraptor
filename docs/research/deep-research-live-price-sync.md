# Deep Research: живые цены и сканирование для мультигейм-портала

**Вопрос V4DYA:** найти рабочий способ фетчить/сканировать живые цены — не только для EFT, но и для остальных игр портала (Arena Breakout: Infinite, Gray Zone Warfare, …). Если рабочего автономного способа нет — спроектировать ручное заполнение БД предметов через CMS-админку (см. [[cta-content-management-system]]).

## Главный вывод

**Универсального «скана живых цен» не существует.** Способ определяется не игрой, а **типом её экономики**. Портал должен классифицировать каждую игру по одной из двух моделей:

| Модель экономики | Что это | Источник цен | Автономно? |
|---|---|---|---|
| **A. Статичные vendor-цены** | Фиксированные цены продажи торговцам, зашитые в файлы игры (не рынок игроков) | **Файлы клиента / датамайн** | ✅ **ДА** — как наш EFT-каталог из SPT |
| **B. Динамический рынок игроков** | Барахолка/marketplace, цена плавает от спроса на серверах издателя | Только живой фид (агрегатор или свой скан) | ❌ **НЕТ** — в файлах цены нет |

Ключ: **для игр модели A живые цены нам не нужны вообще** — они статичны и извлекаются из клиента (BattlEye-safe, как иконки/каталог). «Проблема живых цен» существует только для игр модели B.

## Классификация игр портала (по ресёрчу 2026-07-23)

| Игра | Модель | Природа цен | Наш путь |
|---|---|---|---|
| **Escape from Tarkov** | B (+ A для торговцев) | Флиа — динамический рынок BSG; цены торговцев — статичны (в SPT) | Флиа: агрегатор/свой скан → mirror; торговцы: SPT-дамп ✅ |
| **Gray Zone Warfare** | **A** | Продажа 4 NPC-вендорам по **фиксированным** ценам (нет player-рынка) | **Датамайн из файлов** → полностью автономно ✅ |
| **Arena Breakout: Infinite** | B | Marketplace игроков; **сама игра публикует «среднюю цену за последний час»** | Официальный/агрегаторный фид → mirror |

## Каталог методов (с оценкой легальности/риска)

### 1. Официальный API издателя — почти всегда НЕТ
- **EFT:** публичного API нет намеренно (анти-бот, чтобы скупщики не выкупали лут). Всё «API» — реверс-инжиниринг внутреннего протокола.
- **ABI:** официального публичного price-API не нашли, но игра **сама показывает среднечасовую рыночную цену** внутри клиента — это легальная точка для OCR/чтения экрана.
- **GZW:** цены статичны, «API издателя» не нужен.

### 2. Датамайн из файлов клиента (только модель A) — ✅ рекомендуется
Тот же паттерн, что уже отлажен на EFT (каталог/иконки/сетки, скилл `game-asset-extraction`, BattlEye-safe — читаем файлы, не память). Для **GZW** это закрывает цены на 100% автономно. Рецепт — как `dump-container-grids-spt.mjs` / `etl-items.ts`.

### 3. Консюм чужого агрегатора → наша mirror-таблица (модель B) — 🟡 прагматично к релизу
Существующие фиды по играм:
- **EFT:** `tarkov.dev` (GraphQL, свободный) · `tarkov-market` (API, требует атрибуцию-ссылку).
- **ABI:** `abitradingplatform.com`, `arena-breakout-market.com` (заявляют «100% policy-compliant, без доступа к памяти игры и авто-кликов» — то есть OCR своего экрана = легальная граница).
- **GZW:** `gzwitems.com` — публичный **REST API**, данные с Fandom-вики + сабмиты игроков.

**Паттерн:** крон читает агрегатор → пишет в **нашу** mirror-таблицу (как `sync-prices`). Плюс: тренды 24ч/7д становятся **нашими** (копим свою историю). Гочи: §9 CLAUDE.md запрещает *исходящие ссылки* юзеров на внешние вики/базы — но **серверной инжест данных в нашу БД** это не нарушает (мы и есть агрегатор); атрибуцию по ToS источника соблюдаем на бэкенде.

> ✅ **РЕШЕНО (V4DYA 2026-07-23):** идём вариантом 4 в безопасной форме — **пассивный opt-in компаньон**. План и архитектура: [[eft-live-price-companion]] (браузерный ридer скриншотов барахолки + OCR, реюз `player-position-tracking`, НЕ авто-скан).

### 4. Свой парк OCR-сканеров (модель B, полная автономия) — 🔴 тяжёлый проект
Ровно то, что делает tarkov.dev: **живые игровые аккаунты**, открывающие барахолку и **читающие цены с экрана (OCR)**; сканеры только смотрят, не торгуют. Стратегически — единственный путь к 100% независимости на динамических рынках, но: аккаунты, инфра, поддержка OCR под каждый патч, операционный риск. **Не под релиз.** Граница легальности всех компаний в индустрии — **OCR своего экрана / чтение логов клиента, НЕ чтение памяти процесса** (память = античит-бан). Техника лог-дампа зафиксирована в [[autonomy-prices-research]].

### 5. Ручное заполнение через CMS — 🟢 fallback (см. ниже)

## Fallback: ручное заполнение цен через CMS-админку

Если по игре нет ни файлового источника (не модель A), ни приемлемого агрегатора — цены заводит редактор руками. **Важно:** это осознанно ломает границу из [[cta-content-management-system]] («НЕ трогаем синкаемые данные — они из кронов»). То есть нужен **новый режим**: цена предмета — либо `synced` (крон), либо `manual` (редактор), с приоритетом и меткой источника.

Эскиз (переиспользуем инфраструктуру E10):
- **Схема:** в таблицу цен/предметов — `price_source: 'synced' | 'manual'`, `manual_price`, `updated_by`, `updated_at`. На чтении: `manual` перебивает `synced` (тот же оверрайд-паттерн, что `eft-flea-levels.json` / `container-grid-overrides`).
- **Роль:** уже есть `editor` (`canEditContent`) из E10.1 — либо новый гейт `canEditPrices`.
- **UI:** инлайн-«✎» на плитке/странице предмета (живой рендер = превью, как в E10.3) + список в `/admin` с фильтром «нет цены / устарела / manual», массовый ввод.
- **Гигиена:** метка «цена введена вручную, обновлено N дней назад» на фронте; крон **не затирает** `manual` (как сейчас `syncEftPrices` не затирает при пустой карте).
- **Границы:** не строим price-history вручную; ручной ввод — точечный fallback для новой игры без фида, не замена синка.

## Рекомендация (дерево решений на новую игру)

```
Новая игра на портал →
  Цены статичны в файлах? (vendor-only, нет player-рынка)
    ДА  → датамайн из клиента → автономно, живой скан НЕ нужен   [GZW]
    НЕТ → есть приемлемый агрегатор/офиц. фид?
            ДА  → крон-инжест в нашу mirror-таблицу + копим свою историю  [EFT-флиа, ABI]
            НЕТ → свой OCR-скан (тяжело)  ИЛИ  ручной ввод через CMS  [fallback]
```

**К релизу:** EFT-флиа — оставить `tarkov.dev` + начать копить свою history-mirror (вариант 3+C из [[eft-data-autonomy-research]]); GZW — датамайн (автономно с нуля); ABI — агрегатор/офиц. среднечасовая цена в mirror. CMS-ручной ввод — заложить схему `price_source` как страховку, полный UI строить по необходимости.
