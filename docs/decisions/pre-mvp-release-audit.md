# Масштабная оценка проекта перед релизом MVP

Эпик E11 из [[additional-workout]] (добавлен V4DYA: «хочу запуститься как можно скорей»).
Кросс-сквозной **релиз-гейт**: инвентаризация всего проекта + определение **среза MVP**
(что shippable сейчас, что уезжает в пост-релиз).

## Цель
Оценить готовность всего проекта к запуску MVP и составить чек-лист «до релиза / после релиза»,
чтобы запуститься максимально быстро без стыдных дыр.

## Подход (2 прохода)
### Проход 1 — Инвентаризация `M` 🤖 (сделать ПЕРВЫМ, дёшево)
Фоновые агенты собирают карту состояния:
- Готовые разделы vs заглушки/404 vs «в разработке».
- Битые ссылки, пустые страницы, мёртвые роуты (краул по sitemap/навигации).
- TODO/FIXME/`disabled`-кнопки по коду.
- **Выход:** таблица «фича → статус → нужно ли к MVP».

### Проход 2 — Гейт-чек-лист `L` (перед самим запуском)
Технический смок по осям:
- **Build/типы:** `tsc` чисто, `next build` ок, нет рантайм-ошибок консоли.
- **Безопасность:** прогнать скилл `/security-review`; RLS на всех таблицах (особенно новые: `feedback`, будущие `subscriptions`); секреты не в клиенте; rate-limit на публичных эндпоинтах.
- **Мобилка:** смок ключевых страниц на телефоне (см. `cta-mobile`); нет горизонтального скролла/сломанных сеток.
- **Юридическое:** страницы `/terms` и `/privacy` — сейчас на них ссылается форма фидбэка ([[feedback-form]]), но самих страниц может НЕ быть → создать; куки/согласия если нужно.
- **SEO/мета:** title/description/OG на ключевых страницах, sitemap, robots, favicon.
- **Ошибки/пустые состояния:** 404/500-страницы, skeleton'ы (не спиннеры), обработка оффлайна API.
- **Данные:** кроны синка живы (цены/бартеры/убежище/карты), нет пустых каталогов.
- **Перф:** вес бандла, отсутствие блокирующих SSR-фетчей, ленивая загрузка тяжёлых либ (Leaflet и т.п.).

## Границы
- **В scope:** весь проект — оценка и чек-лист; точечные фиксы «шоу-стопперов».
- **НЕ трогаем:** большие рефакторы (mobile-first аудит, CMS) — они пост-MVP, если не блокеры.

## Влияние на роадмап
Срез MVP из Прохода 1 может **переставить приоритеты**: часть Монетизации/Карт/Mobile может
уехать в пост-релиз, если не критична для первого запуска. Монетизация (Фаза 1) — вероятно
пост-MVP (можно запуститься бесплатным ядром и включить paywall позже).

### B. Умные заглушки (навигируемы, не тупик; ждут данных/фазы) → пост-MVP
- `/eft/videos` (+ `[category]`) — видео-раздел (заглушка).
- `/eft/progress/hideout/[metric]`, `craft-profit`, `bitcoin-profit` — экономика убежища (Phase 2.2/2.3).
- `/eft/progress/loadouts` (+ `[action]`) — сборки оружия (заглушка).
- `/eft/maps/[slug]` без SVG · `/eft/gamesetting/[slug]` · `/eft/quests/[slug]` без данных — умные заглушки-фолбэки.
- `/[game]/[[...rest]]` — мультигейминг: 5 игр «В РАЗРАБОТКЕ» (`games.ts`) — умная заглушка второй игры.

### C. Внутреннее (не для паблик-MVP)
- `/eft/styleguide` — тех-паспорт дизайн-системы → решить: скрыть из паблик-нав/индекса.

### 🔴 Шоу-стопперы (к решению V4DYA / фиксу до релиза)
1. **Юр-текст** — `/legal/{offer,terms,privacy,eula}` резолвятся, но это **черновики** с баннером «не имеет юр. силы» (noindex). Ссылки формы фидбэка **не битые**, но для аккаунтов/платежей нужен реальный текст terms/privacy. → правовой риск, не технический блокер.
2. **Мёртвые ссылки в футере (`href="#"`)** — соц VK / X / Reddit + доп-ссылки «Партнёрская программа», «Интеграции», «Экосистема ЦТА». На паблике выглядит недоделанным → проставить URL или скрыть до готовности.
3. ~~**«Связь» — целый непостроенный раздел**~~ ✅ **РЕШЕНО (2026-07-05):** заведён веткой `comlink` в `headerConfig.menuItems` (6 подпунктов: Поиск напарника · Кандидаты · Биржа шерпов · Мастер-классы · Новостной блог · Обновления игры) + навигируемые смарт-заглушки `/eft/comlink` и `/eft/comlink/[section]` (SectionPlaceholder, noindex). Мёртвый footer-`#` убран (COMLINK теперь из общего конфига). Реал-контент 6 подпунктов — отдельный эпик, пост-MVP.
4. ~~**Мультигейминг-заглушки**~~ ✅ **ПРОВЕРЕНО (2026-07-05):** 404/тупиков НЕТ. Все 8 игр консистентны (`GAMES_DATA` = `HEADER_DICTIONARY`), catch-all `/[game]/[[...rest]]` отдаёт `PlaceholderPage` («В разработке») для игры и всех под-путей; неизвестная игра → 404 (корректно). Косметика (не блокер): у `frago`/`abi` подзаголовки не «В РАЗРАБОТКЕ» — на хабе выглядят «доступными», хотя ведут на заглушку.

> ⚠️ **Оговорка к Проходу 1:** скан инвентаризировал **код** (роуты `page.tsx`). Разделы, спроектированные, но ещё не заведённые в коде (живут только в Figma/голове V4DYA — как «Связь»), скан НЕ видит. Для полноты среза MVP нужен от V4DYA список **запланированных, но не начатых** разделов. «Связь» — первый выявленный.

### 🟢 НЕ шоу-стопперы (ок как честная заглушка)
Видео, экономика убежища, сборки оружия — навигируемы, помечены, уезжают в пост-MVP. `disabled`-кнопки все условные (валидация форм, недоступные игры) — постоянных «мёртвых» нет.

### Влияние на срез MVP (предложение)
Запуск **бесплатным ядром** реален уже сейчас (A + честные заглушки B). До релиза закрыть только шоу-стопперы 1–3 (юр-текст, мёртвые ссылки, «Связь»). Монетизация (Фаза 1), маркеры карт (Фаза 2), mobile-first (Фаза 3) — **пост-MVP**, как и предполагал роадмап.

### Осталось на Проход 2 (перед самим запуском)
`tsc`/`next build` · `/security-review` + RLS (`feedback`, будущие `subscriptions`) · мобилка-смок · SEO (sitemap/robots/OG/favicon) · 404/500 · живость кронов · перф (Leaflet lazy).
