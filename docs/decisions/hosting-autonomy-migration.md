# Переезд на автономный стек (Vercel → Hetzner + Cloudflare + self-hosted Supabase)

**Статус:** ⏳ к исполнению
**Затрагивает:** весь деплой · Supabase (БД+Auth) · крон · домен `cta.quest` · [[CLAUDE.md]] §4.11

## Контекст
Куплен домен `cta.quest` (reg.ru, на 3 года) + по ошибке взят shared-хостинг ISPmanager (триал, стек не тянет). Возник вопрос переезда «части готовых разделов». В ходе грилинга цель уточнена: не привязка домена, а **полная автономность от Vercel + доступность портала везде** (портал планируется международным, региональность — только на биллинге).

Ключевое напряжение: «свежесть по сезону» держится на связке **крон → Supabase → UI читает зеркало** (§4.11) — то есть на серверном рантайме и планировщике, а не на статике. Значит переезжает не «папка со страницами», а рантайм + БД + Auth + крон.

## Решения (зафиксированы грилингом 2026-08-19)

| Развилка | Решение | Почему |
|---|---|---|
| Цель | Автономность от Vercel + глобальная доступность | Международный портал, региональность только на биллинге |
| «Частично» | Переезд **целиком, поэтапным выкатом** | Одна БД на все разделы → раздвоение = анти-автономность; «частично» = порядок миграции, не финал |
| Origin | **Hetzner CPX31** (4 vCPU / 8 ГБ / 160 ГБ NVMe + 4 ГБ swap), EU | Нейтральная юрисдикция, дёшево+мощно, глобально связан. RU-хостинг отвергнут: санкц. трение для междунар. продукта |
| CDN / фронт | **Cloudflare** (free) | Глобальная раздача статики (гео-скорость для РФ и Запада), скрытый origin, точка флипа DNS |
| Панель | **Coolify** на VPS | «Свой Vercel»: git-push деплой, Let's Encrypt SSL, бэкапы, healthcheck-автоподъём |
| Бэкенд | **self-hosted Supabase** (Docker) | GoTrue = тот же Auth, `@supabase/supabase-js`/`ssr` без изменений, меняется только URL. Свою Auth с нуля НЕ пишем |
| Ассеты (R2) | **Остаются на Cloudflare R2** | R2 не Vercel-зависимость и не РФ-блок; уже заполнен (5044 иконки, тайлы). Тащить на VPS = раздувать диск без выигрыша |
| Эксплуатация | Самовосстановление, настраивает Claude | Nightly-бэкап Postgres во внешнее хранилище, `restart: always`+healthcheck, Telegram-алерты. V4DYA — реагирует на редкие алерты |
| Cutover | Стейдж → обкатка → флип, Vercel как резерв | Домен ещё чистый → можно обкатать, не задев трафик; откат = вернуть DNS |

### Юр-фон (BSG / RU)
Риск низкий: у V4DYA личный контакт с разработчиками BSG, проект им известен, претензий не ожидается. Оговорки: неформальная договорённость ≠ лицензия юротдела; РКН/ПДн — отдельная тема, для малого проекта практически не трогает. Домен нейтральный (`cta.quest`, без «tarkov») ✅. Портируемость (Docker-стек поднимается на новом VPS за час) держим как страховку в любом случае. Ср. `transport-json-canon`, §4.12.

## Целевая архитектура

```
Пользователь (РФ / Запад)
        │
   Cloudflare (CDN, кэш статики, SSL, DNS, скрывает origin)  ← флип домена здесь (1 запись)
        │
   Hetzner CPX31 (Coolify)
   ├── Next.js 16  (next start, git-push деплой из GitHub)
   ├── Supabase self-hosted (Postgres + GoTrue-Auth + PostgREST + Realtime + Storage + Kong + Studio)
   ├── Cron (Coolify scheduled → /api/cron/sync-prices 05:00, /detect-anomalies 06:00)
   └── Автобэкап Postgres → внешнее хранилище (nightly)
        │
   Cloudflare R2 (иконки, тайлы карт — без изменений)
```

## Этапы

**Ф0. Подготовка и страховка** *(прод не меняется)*
- Полный дамп текущей облачной Supabase (схема+данные), проверить восстановление.
- Аудит env и Vercel-специфики (в зависимостях `@vercel/*` нет — хорошо; крон-секрет, connection strings).
- Аккаунты: Hetzner, Cloudflare (NS домена → Cloudflare, регистрация остаётся на reg.ru).

**Ф1. Origin встаёт** *(на стейдж-адресе, трафик не видит)*
- CPX31 (Ubuntu, swap, firewall) + Coolify.
- self-hosted Supabase в Coolify, восстановить дамп. Auth-ключи (ES256-гоча `supabase-jwt-es256-dataplane` — на self-host ключи наши, ставим верно сразу).
- Coolify ↔ git-репо → деплой Next.js, env на локальную Supabase.
- Vercel-крон → scheduled-задачи Coolify на те же `/api/cron/*`.

**Ф2. Обкатка** *(Vercel ещё боевой)*
- Живьём: логин/аккаунты, готовые разделы (карты, предметы, квесты), Realtime (отряд-шаринг).
- Крон отрабатывает ≥ суток (цены/аномалии реально синкаются на своём железе).
- Cloudflare-кэш/заголовки, скорость из РФ и Запада.

**Ф3. Флип** *(обратимая точка невозврата)*
- Свежий дамп + досинк дельты (профили).
- `cta.quest` → новый origin правкой DNS в Cloudflare (минуты, откат = вернуть запись). Vercel держим включённым.

**Ф4. Закрепление**
- Несколько дней наблюдения → гасим Vercel. Замкнуть петлю (§8): статус ✅, срез инфры в `docs/state/`.

## Явно ВНЕ переезда (следующие воркстримы)
- **i18n** (англоязычная версия) — фундамент есть (`_ru`/`_en` в данных, §4.12), но это отдельный контентный воркстрим ПОСЛЕ стабилизации.
- **Мульти-биллинг по регионам** — ещё позже (налоги/чеки/KYC: EU VAT, РФ 54-ФЗ).
- **Мульти-регион / второй origin** — только по метрикам; Cloudflare пока закрывает гео-скорость. Второй сервер = мульти-мастер Postgres (боль), не делаем.

## Риски и откаты
- Билд-OOM на 8 ГБ → swap; при упорстве апгрейд CPX41 в клик.
- Auth не заводится (ES256) → ключи наши, закладываю время; откат — Vercel жив.
- Данные → дамп в Ф0 + досинк в Ф3; оригинал не трогаем до Ф4.
- Флип сломал прод → DNS назад на Vercel за минуты.
- BSG/претензия → портируемый Docker-стек, переезд за час.

## Ориентир по деньгам
Hetzner CPX31 ~€13–14/мес · Cloudflare €0 · R2 как сейчас · Supabase €0 (свой) · reg.ru только домен. Против Vercel+облачный Supabase — вероятно дешевле и без потолков тарифа.
