# Ранбук: как прогнать карту целиком

**Что это даёт.** Набор слоёв, извлечённых из клиента и положенных в **одну пиксельную сетку
с растром карты**. V4DYA кладёт их поверх своего HD-арта и видит, где расставил объекты не так.

**Это не фича сайта.** Ни базы, ни UI, ни синков. Скрипты в git, артефакты — нет.

Инвентаризация, гочи и находки: **`eft-map-layers.md`**. Здесь — только как запускать.

---

## 🔑 Три правила, нарушение которых стоит прогона

**1. Все слои кладутся ОДНОЙ аффиной, и никто не выводит её заново.**
Источник — `gen/<map>/rooms/<map>-rooms-frame.json`. Скрипты сверяют свою аффину с этим файлом
и **падают при расхождении**. Иначе один слой однажды уедет на метр, и найдётся это нескоро.

**2. `coordinateRotation: 180` — это ОТРАЖЕНИЕ по X-индексу, а не поворот на 180°.**
`IDX[:, ::-1]`, не `IDX[::-1, ::-1]`. Ошибка жила во всех трёх потребителях террейна и не была
замечена, потому что **статистики к отражению инвариантны**: после починки ни одна цифра
Таможни не изменилась.

**3. `UnityPy Mesh.export()` зеркалит X** (`-pos[0]`). Вершины читать через `MeshHandler`.

## Одна команда

```bash
python scripts/eft-map-layers/run-all.py <map>            # весь конвейер, 13 шагов
python scripts/eft-map-layers/run-all.py <map> recon      # только разведка новой карты
python scripts/eft-map-layers/run-all.py <map> --dry-run  # план шагов, ничего не делает
```

Шаг, у которого выход уже на диске и свежее входа, **пропускается** с явной строкой;
`--force` пересобирает. Выбор шагов: `--only zone,roads` · `--skip render` · `--from walls` ·
`--with-deps` (дотянуть предков). Коды возврата: `0` ок · `1` упал обязательный шаг ·
`2` preflight · `3` ошибка вызова.

Шаги: `recon manifest terrain height material vegetation rooms frame zone roads stones walls
obstacles render` плюс вне дефолтного плана `gate verify-bin align`.

Ниже — те же шаги по отдельности, если нужно руками.

## Порядок и зависимости

⚠️ **`frame.json` производит `render-rooms.py`.** Значит комнаты идут рано — до зоны, дорог,
камней и стен. Это неочевидно и это главная ловушка порядка.

```
манифест карты ──┬─> dump-terrain ──> .bin ──┬─> build-heightmap ──> height-meters.npy ──┐
                 │                           ├─> build-material                          │
                 │                           └─> extract-vegetation ──> vegetation.json ─┤
                 └─> dump-rooms ──> rooms.json ──> render-rooms ──> frame.json ──────────┤
                                                                                          │
  frame + height ──> dump-zone ──> zone-mask.png ──┬─> dump-roads                        │
                                                    └─> dump-stones ──> stones.json      │
  frame + height ──> cut-walls                                                            │
  frame + height + zone ──> cut-obstacles  (слой 7: ОДИН файл, рез по рельефу)            │
  stones.json + vegetation.json + frame ──> render-objects <──────────────────────────────┘
```

### Этажи

Слой 7 режет КАЖДУЮ полосу `layers[].heights` манифеста отдельным файлом
(`<map>-obstacles-<этаж>.png/svg`); `--no-floors` возвращает одну карту. Полоса — не пол:
уровень пола каждого этажа оценивается модой низов геометрии в полосе и печатается вслух.
Наземный этаж карты с террейном по-прежнему режется поверхностью «земля + 1 м».

У карт с синтетическим манифестом этажи берутся из `EFT_MAP_CONFIG` (`heightRange` +
`layers[].height`) — раньше `make-manifest.py` писал пустой `layers[]`, и этажности не было
ни у слоя комнат, ни у стен, ни у препятствий.

⚠️ **Карта высот у `cut-obstacles` желательна, но не обязательна.** С ней рез следует рельефу.
Без неё (Завод, Лаборатория, Лабиринт, Терминал, Ледокол — карты, где в сценах нет ни одной
terrain-ноды) земля считается ПЛОСКОЙ: уровень пола оценивается модой низов геометрии и
печатается вслух. Тот же запасной уровень включается точечно там, где террейн есть, но рамку
не покрывает — иначе объект молча выпадал бы из слоя (так Резерв терял 78 411 объектов из 88 715).

## Команды по шагам

Пути по умолчанию: клиент `D:\Games\Escape from Tarkov\EscapeFromTarkov_Data`,
манифест `D:\Games\raster\<map>\manifest.json`, промежуточное `D:\eft-export\<map>\`,
выход `map-exports/OBJECTS-MAPS/gen/<map>/<layer>/`.

| Шаг | Команда | Даёт |
|---|---|---|
| 0. Манифест | `make-manifest.py <map> <outdir>` | границы карты, если каталога растра нет |
| 1. Дамп террейна | `dump-terrain.py <sharedassets> <level> <outdir> <map> [with-neighbours]` | `.bin` + `splat_*.bin` |
| 2. Высоты | `build-heightmap.py <bin> <manifest> <outdir> <map> [4096]` | 16-бит PNG, отмывка, **метры `.npy`** |
| 3. Материал | `build-material.py <splatdir> <bin> <manifest> <outdir> <map> [4096]` | PNG палитры + индексы |
| 4. Растительность | `extract-vegetation.py <sharedassets…> <bin> <manifest> <outdir> <map> [allow-unresolved]` | JSON/CSV поштучно + плотность |
| 5. Комнаты | `dump-rooms.py <Data> <map> <outdir>` | комнаты, проёмы, двери, выходы |
| 6. **Рамка** | `render-rooms.py <rooms.json> <manifest> <outdir> <map> [locks.json]` | оверлей по этажам + **`frame.json`** |
| 7. Зона | `dump-zone.py <Data> <map> <manifest> <outdir> [--height npy]` | полигон + **`zone-mask.png`** |
| 8. Дороги | `dump-roads.py <Data> <map> <rooms-frame.json> <outdir> [zone-mask.png]` | полотно/разметка/площадки |
| 9. Камни | `dump-stones.py <Data> <map> <manifest> <outdir>` | экземпляры + классы размера |
| 10. Стены | `cut-walls.py <Data> <map> <manifest> <outdir> [--height npy]` | 5 SVG по этажам + группа `props` |
| 11. **Препятствия** | `cut-obstacles.py <Data> <map> <manifest> <outdir> [--height npy] [--zone png] [--cut 1.0] [--no-floors]` | **ПО ЭТАЖАМ**: PNG+SVG на каждую полосу манифеста + сводка |
| 11б. Растительность объектами | `dump-vegetation-objects.py <Data> <map> <manifest> <outdir> [--all-scenes]` | для карт БЕЗ террейна: JSON/CSV/SVG/PNG, радиус кроны из габарита меша |
| 12. Рендер | `render-objects.py all --map <map> ...` | камни и растительность сверху с текстурами |

⚠️ **Ловушка сигнатур:** у `dump-roads.py` третий аргумент — **манифест РАМКИ**
(`<map>-rooms-frame.json`), а не `manifest.json` карты. Единственный такой случай в конвейере.
У `extract-vegetation.py` первый аргумент принимает **список файлов через запятую**.
Флаги `dump-terrain.py` — голые слова (`with-neighbours`, `orient-override`), посторонние отвергаются.

**Проверки, которые стоит гонять:**

| Что | Команда |
|---|---|
| Дамп против Unity-эталона | `verify-terrain-bin.py <эталон.bin> <наш.bin>` |
| Привязка по 4 гипотезам × 4 масштабам | `verify-alignment.py <grounddir> <bin> <manifest> <map> <эталон> landsea\|gradient` |
| Шумовой гейт ориентации | `check-orientation-gate.py` — 5 опытов, «сошлось 5 из 5»; карты в аргументах нет |

² дороги Маяка пересобраны 2026-09-04: было 1 285 «сущностей полотна», из них 512 теней
и 437 барьеров с конусами; стало 19 настоящих дорожных мешей при той же площади.

**Завод (поворот 90°), Лаборатория и Лабиринт (270°) НЕ СОБРАНЫ ОСОЗНАННО.** Рамка умеет только
`coordinateRotation` 0 и 180. Соблазнительно «просто повернуть оси», но проверка чисел это
запрещает: у Завода при развороте 90° масштаб выходит 118.8 px/м по одной оси против 104.8 по
другой — **13 % анизотропии**, то есть квадратное здание легло бы прямоугольником. Без разворота
расхождение 3 %, тоже не ноль. Значит `boundsFromConfig` этих манифестов посчитан не тем путём,
и правильную привязку надо ВЫВОДИТЬ (у Завода для этого есть `worldTransform` в
`EFT_MAP_CONFIG` — калибровка на 11 опорах, невязка 0.7 м), а не угадывать. Отдельная задача.
**Улицы Таркова** — нет ни манифеста, ни записи в `EFT_MAP_CONFIG`: рамку не из чего строить.

⚠️ **Терминал собрался, но лёг МИМО РАМКИ, и это важнее, чем выглядит.** Слой пересёк 30 188
мешей и дал 29 640 контуров — счётчики бодрые, — но закрасил **ноль пикселей**: геометрия карты
уходит в px[−29 240, −4 226], а рамка это [0, 0, 13 181, 16 384]. Комнаты Терминала стоят в
X≈195 / Z≈−223, тогда как синтетический манифест описывает X[−1605,−675] / Z[315,1471], то есть
**`bounds` терминала в `EFT_MAP_CONFIG` не соответствуют мировым координатам карты**. Ровно тот
же сорт ловушки, что отражение террейна: все статистики выглядят здоровыми, неправда видна
только на растре. Поэтому в `cut-obstacles.py` заведена гарда «пересечений много, а закрашено
ничего» — она печатает габарит геометрии против рамки и пишет это в JSON (`checks.outsideFrame`).

### Пять блокеров, вскрытых до причины

1. **Лес: «высоты не лезут в делитель 32766».** Реестр объяснял это тем, что делитель —
   свойство карты. Замер опроверг: **9 значений из 1 050 625** (0.0009 %) на один шаг выше,
   хвост распределения гладкий (32764:3, 32765:1, 32766:4, 32767:9). Это край int16, а не иной
   масштаб. Теперь выброс подрезается, а «другая нормализация» отличается **долей** (> 0.01 %
   значений выше делителя), а не максимумом.
2. **Лес, Берег, Резерв: «контроль сетки промахивается на 2152.7 / 2852.1 / 1759.1 м».**
   У всех слайсов карты промах **одинаковый до сантиметра**, а шаг между слайсами ровно 700 м.
   Проверять надо ОТНОСИТЕЛЬНУЮ структуру: карта целиком стоит на своём якоре, и это нормально —
   боевые позиции берутся из иерархии, формула лишь контроль. Ошибка теперь — РАЗЪЕЗД слайсов
   между собой, а не общий сдвиг.
3. **Лес и Берег: гейт ориентации ронял прогон из-за ОДНОГО слайса.** Ориентация хранения splat —
   свойство формата, а не слайса: внутри карты она обязана быть одинаковой. Вердикт перенесён
   на КАРТУ (среднее по слайсам): у Леса 3 из 4 слайсов уверенно за «как есть», агрегат
   подтверждает 2.6×; у Резерва 3.7×. Гейт от этого не ослаб, а усилился — настоящее зеркало
   проявилось бы на всех слайсах сразу; харнесс `check-orientation-gate.py` сошёлся **5 из 5**.
4. **Резерв: один блокер ломал ТРИ слоя.** Сцена ссылается на 4 слайса террейна, три из которых
   лежат в чужих `sharedassets` (17 и 25) — их брали только по признаку в реестре, а у Резерва
   его не было. Итог: земли не было под **78 411 объектами из 88 715**, слой 7 собрал 0.23 %
   рамки, а зона падала с «панели не образуют замкнутого контура» (фильтр приземности врал
   без высот). `with-neighbours` стал ДЕФОЛТОМ: слайс, на который ссылается сцена самой карты, —
   часть её террейна, где бы он физически ни лежал. После этого: props 1 214 → **10 025**
   экземпляров, зона собралась за 5.3 с.
5. **Развязка: `heights: null` в манифесте роняло два скрипта.** Полоса не задана = «весь
   диапазон», а не отказ разбора.

### Две гарды, заведённые по итогам прогона

Обе ловят одно и то же семейство лжи: **счётчики здоровые, а слоя нет**. Это ровно тот сорт
ошибки, что уже стоил проекту зеркального террейна — статистика к ней инвариантна.

| Гарда | Где | Что ловит |
|---|---|---|
| «пересечений много, а закрашено ничего» | `cut-obstacles.py`, `checks.outsideFrame` | слой лёг мимо рамки (Терминал: 30 188 пересечений, 0 пикселей) |
| «зона подозрительно мала» | `dump-zone.py`, `plausible` + `frameSharePercent` | заливка нашла карман, а не игровую зону (Лес 1.3 % рамки при пороге 5 %) |

### Мелочи, которые тоже стоили карт

- **Подложка для сверки искалась как `<map>-main-8192.webp`.** У Леса главный слой называется
  `main_0.16`, у Берега и Ground Zero — `main_summer`: имя берётся из манифеста, и `check.jpg`
  появился у всех карт с растром.
- **Карта без террейна больше не отказ.** Завод, Лаборатория, Лабиринт, Терминал и Ледокол
  террейна не имеют вовсе (в сценах нет ни одной terrain-ноды). Там «земля» — это пол: уровень
  оценивается модой низов геометрии и печатается вслух. ⚠️ На многоуровневой карте без террейна
  плоский рез показывает ТОЛЬКО уровень основания — Ground Zero с его перепадом честнее
  смотреть слоем стен по этажам.
- **Запасной плоский уровень** применяется и там, где террейн ЕСТЬ, но не покрывает рамку —
  иначе объект молча выпадал из слоя.
- **`MAP_LOCATION` в `dump-stones.py` был четвёртой копией одной таблицы карт** — убрана,
  теперь общая из `mapgeom`. Из-за неё Ground Zero и Ледокол не собирали камни.
- **У Ледокола камней нет вовсе, и отказ «ни одного кандидата» тут ожидаемый** — гарду не
  ослабляли: она ловит сломанный словарь имён на новой карте, а корабль без камней это правда.

## ⚠️ Новая карта — это НЕ смена аргумента

Соглашения общие, **словари имён у каждой карты свои**. Перед прогоном — разведка:

| Что проверить | Как | Пример расхождения |
|---|---|---|
| Граница | есть ли корень `<Карта>_LevelBorders` в `*_Scripts` | Таможня 440 панелей, Маяк 1 439 |
| Комнаты | `<Карта>_Sound`, сколько `SpatialAudioRoom` | Таможня 398, Улицы 1 239, Лес 139 |
| Дороги | есть ли узел `OO/ROAD` в дорожной сцене | **у Маяка его НЕТ** — отбор по именам тянет ~1 млн треуг. с реквизитом |
| Камни | какие семейства по именам | Таможня `Stone_0N`; Маяк `AM_Rock_Big/Middle/Small`, `Arid_rock_*_cliff` |
| Этажи | доля комнат с этажным токеном в пути | Таможня 52 % (207/398) — воспроизведено дважды. По Маяку два замера разошлись: разведка дала 12 %, `recon` раннера — 69 %. **Число не подтверждено, перемерить.** Лес 3 % |
| Слайсы террейна | есть ли соседние колонки в чужих `sharedassetsN` | Маяк: 3 своих + 3 соседних, покрытие 64 % → 98.5 % |

**Объекты карты разбросаны по ВСЕМ её сценам,** а не по одной: слой камней нашёл экземпляры
в семи неочевидных сценах помимо основной. Не ограничиваться `levelN` террейна.

## Слой 7 — как он устроен (переделан 2026-09-04)

**Заказывали один слой с резом 1 м от земли — теперь так и есть.** `cut-obstacles.py`,
выход `gen/<map>/obstacles/`: PNG-силуэты в рамке растра, SVG с теми же контурами по группам,
`check.jpg` поверх арта, JSON со сводкой.

- **Рез — ПОВЕРХНОСТЬ, а не плоскость.** Порог `y − (земля(x,z) + 1)` считается **повершинно**
  по карте высот (билинейно). Забор на склоне и здание на косогоре режутся на метре от земли
  по всей длине. У стен рез плоский на этаж — это разные инструменты, а не настройка одного.
- **Фильтра «выше 1 м» нет и не нужно** — он и есть построение: на Таможне до реза не достают
  **61 306 из 81 657** экземпляров. Валун по колено не пересекает поверхность и не режется.
- **Заливка — чёт-нечет ПОЭКЗЕМПЛЯРНО, объединение по ИЛИ.** Полости внутри одного меша
  вычитаются, а два пересекающихся объекта не выедают друг в друге дырку (так было бы при
  чёт-нечет на всю карту). Ориентацию контура для правила намотки использовать нельзя:
  сшивка идёт по неориентированному графу и направление обхода произвольно.
- **Группы SVG:** `building` / `openings` / `fence` / `props` / `stone`, и то же с суффиксом
  `-outside` для того, что вне игровой зоны (гасится одним кликом, но не теряется).

### Три вещи, которые слой 7 нашёл в клиенте

1. **Купол неба (`Sky Dome/Space|Clear|Atmosphere`) пересекает ЛЮБОЙ рез** и заливает
   **97 % рамки** (578 000 м² на экземпляр). Глазом PNG выглядел «просто залитым» — поймал
   только счётчик площади. Отсюда **предохранитель**: экземпляр крупнее 1.5 % рамки в слой
   не пускается и печатается вслух. На новой карте это первое, что сработает.
2. **У BSG вторая опечатка того же сорта, что `_Aldebo`:** узел `SOO_LOD0/OUTDOOR/balistic`
   написан **с одной «л»** и мимо строгого фильтра `BALLISTIC` проходил как реквизит.
   Исправлено в общем фильтре прокси-геометрии (`mapgeom.SKIP_MESH_RX`) — значит, и у стен.
3. **`stencil` и `decal` — не препятствия.** Стенсил-прямоугольники рендера бывают в пол-локации
   (20 463 м²), декалей на Таможне 12 271 штука, и 4 433 из них лежат в ветке `BUILDING`.

### Гоча самопроверки: центр камня — не точка внутри его сечения

Первая версия проверяла «центр камня слоя 9 попал в силуэт слоя 7» и показала **264 из 264**.
Это был **ложный зачёт на залитой куполом рамке**: когда протечку убрали, стало 100 из 264.
Валун сужается кверху, и pivot на высоте метра лежит **мимо собственного сечения**. Правильная
проверка — перекрытие с **габаритом обводки** (`hullPx` слоя 9) и порог по высоте **4.5 м**
(измеренная слоем 9 граница «декор/препятствие»): **79 из 83**. Тот же урок, что с отражением
террейна: статистика, инвариантная к ошибке, её не ловит.

## Что НЕ сделано

- **У стен только SVG, растра нет** (у комнат, дорог, камней и препятствий есть оба).
- **Слой 7 не отделяет проходимое от непроходимого**: полотно двери в проёме — это `openings`,
  а открыта дверь или нет, из геометрии не следует.
- **Стены несут тот же шум, что вычистил слой 7** (купол неба, стенсилы, декали в ветке
  `BUILDING`) — правила отсева живут в `cut-obstacles.py`, в `cut-walls.py` их не переносили.
- **Теней на землю нет** — рендер содержит только объекты, shadow-catcher не ставился.
- **Рендер только камней и растительности**, зданий нет (меши и трансформы для них уже добыты).
- **Наружные/внутренние стены разделены приблизительно** — заливкой снаружи; точное разделение
  только по ветке-источнику иерархии.
- **Рез `underground` на 0.20 м — оценка** (мода низов 636 building-мешей), не факт из данных.
