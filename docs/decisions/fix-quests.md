# Фиксы раздела "Задания"

**Статус:** ⏳ к исполнению — развилки закрыты 2026-07-01
**Затрагивает:** `quests/page.tsx` · новый `features/quests/QuestsHubNav.tsx` · `headerConfig.ts` (источник разделов)

## Контекст
Требуется переработка некоторых разделов для актуальности данных.

## UI-правки (ui-edits)
* реализовать удобное переключение между разделами посредством внедрения навигации HubNav - где есть удобная навигационная панель справа от заголовка.
* отказаться от использования HubCard которые создаются вручную, использовать динамическую навигацию по разделам

## Варианты (главная развилка — `HubNav` зашит на items: `useItemsStore` + фильтр торговцев)
- **A — Обобщить `HubNav`:** вынести traders-фильтр + `useItemsStore` в опциональные пропы/слот; один компонент на items и quests.
- **B — Отдельный `QuestsHubNav`:** dumb-навигация под quests (левый блок + ряд табов-ссылок из словаря), items не трогаем.

## За / Против
| Вариант | За | Против |
| ------- | --- | ------ |
| **A** | DRY, единый источник навигации, переиспользуемо дальше | трогаем рабочий items → риск регресса; тащим store/фильтр в общий код |
| **B** ✅ | items не трогаем (0 риска на рабочем разделе); простой презентационный компонент; быстро | небольшой дубль левого блока+табов с `HubNav` (без traders/store) |

## Вывод
**Вариант B** — отдельный `QuestsHubNav`, items не трогаем. Развилки с V4DYA закрыты (2026-07-01):
- **Навигация = только 3 раздела** (Сюжетные / Побочные / События) из `HEADER_DICTIONARY` (children узла `/eft/quests`). Торговцы — внутри «Побочных», НЕ вторым рядом.
- **Scope = только UI-навигация.** Наполнение квестов данными — отдельная задача.

### Границы
- **В scope:** новый `features/quests/QuestsHubNav.tsx`; в хабе `quests/page.tsx` заменить **навигационные** `HubCard` (3 карточки Сюжетные/Побочные/События) на `<QuestsHubNav>`.
- **Подстраницы `side-quests`/`lore-quests` — НЕ трогаем** (V4DYA: «хватит хаба»). Переключение между разделами уже есть в Header-меню; их контентные `HubCard` (списки торговцев/квестов) — это данные, не навигация.
- **НЕ трогаем:** `ui/HubCard.tsx` и использования вне quests-навигации (progress, videos, eft-hub, gamesetting, CategoryTabs); items `HubNav`; данные/бэкенд квестов.

### Находка → отдельная задача «данные квестов»
Списки в `side-quests`/`lore-quests` — ручные хардкод-массивы (`TRADERS_CARDS`, `STORY_QUESTS`), **дублируют** children из `headerConfig` и уже **разошлись** (сюжетных: в словаре 10, на странице 9). Это «неактуальность данных» из контекста — выносится отдельно (единый источник → БД/словарь).
