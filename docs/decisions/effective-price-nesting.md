# Рекурсивная выгодная цена — «тарковская матрёшка»

**Статус:** 🔵 обдумываю (деньги/калькулятор → стратегический узел, [[engineering-loop]])
**Затрагивает:** [[bugs-triage-2026-07-19]] · [[item-card-overhaul-2026-07-22]] · [[EFT_CURRENCY_MODEL]] · `src/lib/eft-indicators.economics.ts` · `src/lib/barter-calc.ts`

## Контекст
Пункты 8–9 дампа 19.07. Игроку важнее всего знать **самую выгодную цену получить предмет**
с учётом всех путей: купить на барахолке / купить у торговца / **забартерить** / **скрафтить**.
Причём бартер и крафт — рекурсивны: у ингредиента крафта тоже может быть свой крафт/бартер,
и так вглубь («матрёшка»).

**Пример Вади (Боевой стимулятор SJ6 TGLabs, на 19.07):**
- Купить SJ6 на барахолке — 80 292 ₽.
- Но SJ6 можно **скрафтить** (нужны SJ1 ×1 + Набор медикаментов ×2) и **забартерить** у Терапевта.
- SJ1, в свою очередь, тоже крафтится (Набор медикаментов ×7) — но купить SJ1 на барахолке
  за 21 000 ₽ **выгоднее**, чем крафтить.
- Значит в расчёте крафта SJ6 стоимость SJ1 надо брать = **min(купить, скрафтить, забартерить)** = 21 000,
  а не «наивную» стоимость крафта SJ1.

Сейчас в коде (`eft-indicators.economics.ts::requiredCost`) стоимость ингредиента = **только
`cheapestBuyRub`** (цена покупки), **одноуровнево**. Рекурсии и сравнения путей нет — это и есть пробел.

## Что уже есть (не с нуля)
- `barter-calc.ts` — точная формула комиссии барахолки (`calcFleaFee`), вердикты.
- `eft-indicators.economics.ts` — `buildBarterData`/`buildCraftData`, `requiredCost`, `rewardValue`.
- Зеркало бартеров/крафтов в БД (правило §4.11) — данные о рецептах уже наши.
- [[EFT_CURRENCY_MODEL]] — модель для арена-валют (GP/Лега считаются не рыночной ценой, а курсом).

## Определение (что считаем)
`effectivePrice(item)` = минимум из доступных способов получить 1 шт:
- `buyFlea` — цена барахолки (если уровень позволяет, п.5);
- `buyTrader` — минимум по торговцам (с учётом лояльности/валюты, п.3–4);
- `craft(recipe)` = Σ `effectivePrice(ingredient) × count` / `выход` (+ опц. время/энергия убежища);
- `barter(trade)` = Σ `effectivePrice(required) × count` / `выход`.

Рекурсия по ингредиентам крафта/бартера. Результат — цена **и** путь («как выгоднее получить»).

## Варианты реализации

- **A — Полный рекурсивный решатель с мемоизацией и защитой от циклов.**
  Строим граф предмет→рецепты, считаем `effectivePrice` мемоизированно (Map по id),
  детектим циклы (A→B→A) через стек посещённых, ограничиваем глубину. Отдаёт цену + путь.
  Один раз офлайн (крон/ETL) на весь каталог → в БД колонка `effective_price` + путь.

- **B — Ограниченная рекурсия на 1–2 уровня, на лету в RSC.**
  Считаем при рендере карточки, вглубь на 1–2 шага, дальше — `cheapestBuyRub` как отсечка.
  Проще, но пример SJ6→SJ1 требует ровно 2 уровня, а бывают глубже → риск недосчёта.

- **C — Оффлайн-предрасчёт всего каталога (расширение A).**
  A + сохранить `effective_price`/`best_source` в зеркало кроном (как цены/курсы). UI только читает.
  Дорого по первой реализации, но снимает нагрузку с рендера и даёт консистентность по сайту.

## За / Против
| Вариант | За | Против |
|---|---|---|
| **A** | точно; путь для игрока; переиспользуемо | сложность решателя, циклы/глубина, тесты обязательны |
| **B** | быстро внедрить; локально к карточке | недосчёт на глубине >2; дублируется на каждый рендер |
| **C** | UI дёшев; консистентно; кэш | самый большой объём; ещё один крон/колонка (граница сессий §4.11) |

## Риски / грабли
- **Циклы рецептов** (взаимные бартеры) — обязательна защита по стеку + лимит глубины.
- **Арена-валюты** в стоимости ингредиента — брать из [[EFT_CURRENCY_MODEL]] (`arena-currency.ts`),
  не рыночную цену (у GP/Леги её нет).
- **Комиссия барахолки** при перепродаже — учитывать `calcFleaFee`, иначе «выгода» завышена.
- **Уровень барахолки/лояльности** (п.4–5) — путь «купить» доступен не всегда; фильтровать.
- **Верификация — детерминированная:** зафиксировать кейс SJ6/SJ1 как тест-фикстуру
  (ожидаемо: SJ1 в матрёшке = 21 000, а не крафт-стоимость), гейт `tsc` + unit-тест.
- Пересекается с фильтрами [[item-filters-toggles]]: тумблеры «использовать бартеры/крафты»
  = какие ветки `effectivePrice` включать. Проектировать вместе.
