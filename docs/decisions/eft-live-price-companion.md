# Пассивный компаньон живых цен (crowdsourced flea)

## Решение (V4DYA, 2026-07-23)
Строим **пассивный opt-in компаньон** — собственный источник живых цен барахолки EFT, чтобы уйти от зависимости от tarkov.dev на динамическом рынке. Выбран из развилки в [[deep-research-live-price-sync]] после того, как «безопасный авто-скан» отпал (см. ниже).

## Почему не «флот сканеров» / авто-скан (проверено на файлах Вадима, [[autonomy-prices-research]])
Связка «живой флиа + BattlEye-safe» невыполнима автоматически: лог-дамп → files-checker откатывает конфиг + бинарные ответы (0 цен); сеть шифрована → расшифровка = память = бан; OCR-**автоматизация** клиента = EULA §4.2.11/§4.3.4 = перма-бан. Единственная безопасная зона — **пассивное чтение того, что игрок делает сам** (класс RatScanner, ~0 банов за 5+ лет).

## Ключевой прецедент — уже есть в проде
[[player-position-tracking]] (✅ 2026-07-08, `lib/eft-screenshot.ts` + File System Access API): браузер читает **скриншоты, которые EFT сам пишет** в `Documents/Escape from Tarkov/Screenshots/`, без установки .exe, без рантайм-tarkov.dev, BattlEye-safe (читаем файл игры — та же категория, что динамическая карта tarkov.dev). **Компаньон цен = тот же паттерн, но с OCR содержимого скриншота**, а не парсингом имени файла.

## Архитектура v1 (браузерный, в нашем стеке — НЕ desktop)
```
Игрок сам открыл барахолку в EFT и нажал клавишу скриншота
  → наш веб-тул (открыт в браузере, File System Access к папке Screenshots)
  → замечает свежий PNG → OCR офферов на экране (Tesseract.js, в браузере)
  → распознаёт предмет (наш каталог) + цену
  → POST /api/companion/flea (наш ingest API, авторизованный юзер)
  → агрегатор пишет в prices/price_history с source='companion'
  → портал читает ТОЛЬКО нашу БД (§4.11 не нарушается)
```
**Безопасность:** без автоматизации (скриншот жмёт игрок), без памяти, без пакетов, без модов клиента — читаем файл, который игра записала. Та же посадка риска, что уже отгруженный трекер позиции.

## Что где живёт
- **Наш репозиторий (моя зона, в стеке):** ingest-API `/api/companion/flea` + анти-абьюз, схема-агрегация (`price_history.source='companion'`, дедуп офферов), браузерный ридер+OCR-UI (переиспользуем `eft-screenshot.ts` / File System Access), приоритет источников на чтении.
- **Desktop .exe — НЕ нужен для v1.** Отдельный нативный компаньон (вне Chromium, фоновый вотчер) — только если браузерный охват окажется мал (фаза 3, отдельный проект).

## Честные ограничения (обязательно проговорить)
- **Cold-start:** данных мало, пока мало юзеров/скриншотов. **tarkov.dev-зеркало остаётся backbone**, компаньон — additive-слой, растущий с аудиторией. Это НЕ rip-and-replace.
- **OCR лоссовый:** нужно надёжное распознавание предмета+цены; шум фильтруем (медиана по офферам, отброс выбросов).
- **EULA — серая зона, но мягкая:** пассивное чтение game-written файлов + ручной скриншот ≈ посадка риска уже отгруженного трекера позиции; НЕ автоматизировать клиент, opt-in + явное согласие. При коммерциализации — учитывать IP BSG.
- **PvP/PvE:** офферы разнятся по режиму → `gameMode` в контракте с первого дня.

## Модель доверия и модерации (design, Фаза 2 — ещё НЕ в коде)

Разбор V4DYA↔AI 2026-07-23. Две разные угрозы закрываются разными слоями.

**Модель угроз:**
- **Случайная ошибка** — честный игрок криво снял скрин (мисрид OCR, не тот предмет, обрезанная строка — наш «48 000» среди LEDX).
- **Умышленный скам** — вливание фейковых цен (в одиночку или сговором аккаунтов) для манипуляции.

**Уже в коде (Фаза 0/1) — закрывает СЛУЧАЙНЫЕ ошибки почти полностью:**
- медиана (не среднее) → выбросы + vanity-цены (777 777) не тянут;
- **≥3 НЕЗАВИСИМЫХ автора** (`count distinct submitted_by`) на предмет — один человек не создаёт цену;
- только залогиненные + `submittedBy` в каждой строке → аудит-след, любого автора можно откатить;
- rate-limit 120/час; санити-границы 1…1e9 ₽; клиентский `rejectOutliers` (медиана в одном кадре); RLS без публичного чтения.
- **✅ Доверенные роли (2026-07-23):** сабмит от `moderator`/`admin` помечается `trusted` и становится **истиной сразу** — агрегатор берёт медиану доверенных офферов, минуя порог ≥3 и медиану толпы. Роль = «бесконечная репутация» (предвестник п.2). Даёт ручной override и **решает cold-start** (модератор/админ засевает авторитетные цены в одиночку). Колонка `companion_flea_offers.trusted`, гейт `canModerate(role)` в роуте, флаг `trusted` в `CompanionPrice` (для будущего бейджа «проверено модератором»).
- Итог: случайный шум перекрывается медианой, честный автор за ошибку не наказан.

**НЕ закрыто, проектируется (Фаза 2) — против СКАМА и cold-start:**
1. **Якорь на tarkov.dev (ключ для cold-start).** Зеркало tarkov.dev = референс-коридор: companion-цена перебивает боевую ТОЛЬКО если в пределах X% от базлайна; вне коридора → очередь ревью, не публикуется. Пока авторов мало — якорь держит.
2. **Репутация/карма (на `profiles`, единая система со стимулом).** Вес голоса = историческая точность автора (сходимость его сабмитов с консенсусом). Скамер копит отрицательную репу → влияние →0; новые аккаунты = низкая репа = почти нулевой вес (анти-сговор/анти-мультиакк). Это же — мотивация вкладываться.
3. **Порог доверия ↑ для дорогих предметов** — LEDX/GPU манипулировать выгоднее → больше подтверждений/ревью, чем дешёвому хламу.
4. **Тиры уверенности на витрине** — «подтверждено сообществом» только при высоком согласии; иначе «предварительно» / скрыто.
5. **Человеческая модерация — реюз существующего** (`canModerate`, очереди жалоб/верификации): очередь аномалий цен (вне якоря / резкие скачки / подозрительная активность) → подтвердить/обнулить/забанить. Петля коррекции («увидел кривую → поправил») = голос; много коррекций → авто-флаг.

**Осознанный порядок:** сначала пайплайн (Фазы 0–1), доверие навешиваем в Фазе 2, когда есть что модерировать. Якорь на tarkov.dev делает риск cold-start управляемым (fallback = известный-хороший источник).

## Связь с CMS-fallback
