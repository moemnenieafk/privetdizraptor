# Адаптивный хаб «Ульта» — вход по роли игрока

**Статус:** 🔵 обдумываю → дизайн готов, к поэтапному исполнению
**Затрагивает:** [[snapshot-2026-07]] · профиль игрока · телеметрия · подписка · раздел «Я новичок»

## Контекст

Сейчас вход в портал одинаков для всех. Но игроки extraction-шутера — разные роли со своими задачами (ролевое исследование, 7 архетипов): **Новичок · Прогрессор · Барыга · Оружейник · Инженер базы · Рейдер · Зритель**.

Профиль игрока уже есть (`usePlayerStore` + облако + OCR), телеметрия есть — но они **не влияют на то, ЧТО показывает портал**. Идея «Ульты» (супер-способность проекта): единая адаптивная точка входа — кнопка, которая **сама определяет роль игрока по профилю + поведению** и агрегирует то, что нужно ЕМУ прямо сейчас. Ярлык кнопки меняется: «Я новичок» / «Я бывалый» / «Я барыга» / «Я оружейник»…

Это связывает воедино три наработки: роли (исследование) → «Я новичок» (один из выходов) → позиционирование («адаптируем тебя»).

## Что добавить в профиль

OCR-скрин профиля EFT показывает не только ник/левел, но и **часы в игре, число рейдов, выживаемость**. Расширяем:
- `PlayerProfile` (`usePlayerStore`) + `ProfileOcrResult` (`types/profile-ocr`) + `playerProfiles` (schema) → `hoursPlayed: number | null` (опц. `raids`, `survivalRate`).
- OCR-промпт Gemini — дораспознавать эти поля (null, если не видно → пользователь дозаполнит).

Часы = самый дешёвый детерминированный сигнал стадии («Timmy» / «бывалый» / «эндгейм»).

## Движок роли (Role Inference)

Чистая функция `role-inference.ts`: `(profileFacts, behaviorSignals) → { primaryRole, secondaryRole, confidence, axes }`. Два источника сигнала:

**1. Факты профиля (детерминированно):** hoursPlayed, level, prestige, mode (PVP/PVE), traderLevels, edition → грубая **стадия** прогресса.

**2. Поведение (телеметрия):** какие домены человек трогает (счётчики визитов/запросов с затуханием):
- barters/prices/price-slot → **Барыга**
- loadouts/gunsmith → **Оружейник**
- quests/questmap/needed → **Прогрессор**
- bosses/maps/loot-containers → **Рейдер**
- videos → **Зритель**
- codex/rookie → **Новичок**
- hideout → **Инженер базы**

**Психопрофиль (поведенческие оси)** — про стиль игры, не про личность:
- осторожный ↔ агрессивный (PVE/выживаемость vs боссы/PVP)
- эконом ↔ боевой (barter/prices vs ammo/loadouts)
- спидран ↔ коллекционер (квест-фокус vs items/favorites)
- соло ↔ сокланы (find-partner/comlink)

Выход: **основная роль + уверенность + вторичная роль + оси**. На старте — **правила, без ML** (правила прозрачны и отлаживаемы; ML — потом, если понадобится).

## Кнопка «Ульта» и хаб

Кнопка = surfaced-выход движка (не статичный текст). Тап → **персональный хаб**, агрегирующий под роль ссылки на уже существующие фичи:
- **Барыга** → топ-бартеры, свежие цены, профит, watchlist.
- **Оружейник** → свежие билды Димы + Gunsmith под мои уровни трейдеров + ammo chart.
- **Прогрессор** → next-квесты, needed-items, квест-карта.
- **Рейдер** → боссы (спавны/лут), карты, лут-контейнеры, быстрый ammo-vs-armor.
- **Инженер** → ближайший достижимый апгрейд хидаута + чего не хватает.
- **Зритель** → «что нового» у Димы + мост видео→инструмент.
- **Новичок** → **Путь Новобранца** (см. «Я новичок»).

## Доверие и холодный старт

- **Ручной оверрайд** — игрок всегда может переключить роль сам. Система предлагает, человек решает.
- **Прозрачность** — показать, ПОЧЕМУ выбрана роль («ты часто смотришь бартеры»), дать сбросить. Никаких тёмных паттернов.
- **Холодный старт** (аноним без профиля/телеметрии) → экран «Выбери себя»: те самые кнопки Новичок/Бывалый/Барыга → дальше уточняется поведением.

## Подписка

«Ульта» — киллер-фича ценности, поэтому:
- **Базовая адаптация — бесплатно (Боец).** Новичка НЕ гейтить.
- **Глубина — Оперативник/Ветеран:** мультипрофиль-инсайты, история поведения, продвинутые рекомендации, облачный синк роли между устройствами.

## Варианты

- **A —** только ручной выбор роли (кнопки-переключатели). Просто, но не «умно».
- **B —** только авто-инференс. Умно, но холодный старт и риск ошибки → недоверие.
- **C —** гибрид: авто-предложение + ручной оверрайд + прозрачность.

## За / Против
| Вариант | За | Против |
|---|---|---|
| **A** | тривиально, предсказуемо | не «Ульта», ноль магии |
| **B** | вау-эффект | пустой холодный старт, чёрный ящик, ошибки бесят |
| **C** | магия + контроль у игрока + работает с 1-го визита | больше слоёв (инференс + оверрайд + объяснимость) |

## Вывод

**Вариант C.** Поэтапно, чтобы каждый шаг компилировался и давал ценность сам по себе:

1. **Профиль+часы** — `hoursPlayed` в `PlayerProfile`/`ProfileOcrResult`/schema + OCR-поля.
2. **Инференс на фактах** — `lib/role-inference.ts` (детерминированно) + `store/useRoleStore.ts` (persist: `derivedRole`, `manualOverride`, `lastComputedAt`; селектор `effectiveRole = override ?? derived`).
3. **Поведенческий слой** — `lib/behavior-signals.ts` (агрегатор визитов по доменам с затуханием, поверх существующей телеметрии).
4. **UI** — `features/adaptive/UltaButton.tsx` (header/hero) + `features/adaptive/AdaptiveHub.tsx` (роут `/eft/hub` или модалка) + `data/role-hubs.ts` (конфиг агрегации на роль).
5. **Подписочная глубина** — гейт продвинутых инсайтов на operative/veteran.

Первый срез в прод — **шаги 1–2 + ручной выбор** (роль работает уже на фактах). Поведение (3) и объяснимость наращиваем итеративно. Роль=Новичок автоматически ведёт в **Путь Новобранца** — так «Я новичок» становится веткой «Ульты», а не отдельной фичей.

**Типизация:** роли — дискриминированный юнион (`type PlayerRole = 'rookie' | 'progressor' | 'trader' | 'gunsmith' | 'engineer' | 'raider' | 'viewer'`), никаких магических строк. FSD-lite: логика в `lib/`, состояние в `store/`, UI-атомы чистые.
