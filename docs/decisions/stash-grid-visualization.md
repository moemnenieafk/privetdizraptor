# Эпик: Стойка «Схрон игрока» — визуальная сетка инвентаря

Идея V4DYA (2026-08-21, во время грилла craft-profit). **Не входит** в текущий автопилот craft-profit — самостоятельная фича, отдельный спринт. Здесь фиксируем замысел + точки переиспользования, чтобы не потерять нюансы.

## Замысел
Отдельный раздел-визуализация **схрона игрока**: тарков-подобная сетка ячеек (базово **56×56px**), куда попадает **всё, что пользователь накликал кнопкой «В схрон»** по сайту (Важные предметы, craft-profit-входы и т.д.). Держит юзера в курсе: «что и сколько у меня уже лежит».

Ключевые свойства:
- **Реальный размер предмета по ячейкам** — предмет занимает `gridWidth × gridHeight` (1×1, 1×2, 2×2…), а не одну клетку.
- **Расширяется от наполнения** — сетка растёт по мере добавления лута (авто-упаковка).
- Ячейка красится **рарити-фоном** предмета (как TrackCell), иконка предмета сверху, бейдж количества.

## Что переиспользуем (нюансы уже разработанного)
- **`useInventoryStore`** («в схроне» из Важных предметов): единый источник «сколько предмета у игрока». `bumpCount(id, delta, max)` — функциональный кламп (защита от гонки hold-repeat, см. needed-merge-session). Кнопки «В схрон» уже пишут сюда.
- **`items.gridWidth` / `items.gridHeight`** (зеркало) — footprint предмета по ячейкам. ЕСТЬ в БД.
- **`items.backgroundColor`** → `getTarkovBackgroundColor()` — рарити-фон ячейки (как на /needed и /modules).
- **`itemIconUrl(id)`** — иконка. ⚠️ Проверить: для сетки нужна **grid-иконка** (tarkov.dev `gridImageLink`, обрезана под клетки), а не 512px-арт. Уточнить, зеркалим ли `gridImageLink`; если нет — завести поле/синк (game-data-ingest / cta-backend).
- **`TrackCell`** — канон-ячейка (рарити-фон + бейдж + «в схроне»). Возможно, база для StashCell (или отдельный компонент с packed-layout).
- **Размер схрона по изданию** — `docs/research/eft-editions-hideout-bonuses.md` + `editionFloor`: Standard 10×30 … Unheard 10×72 (ячейки). Стандартная ширина схрона EFT — **10 колонок**, издания добавляют ряды. ⚠️ V4DYA упомянул «14×14» — сверить желаемую ширину сетки (10 канон EFT vs 14 произвольная витрина).

## Нюансы для проработки (открытые вопросы эпика)
1. **Алгоритм упаковки** (bin-packing) предметов разного размера в сетку фикс. ширины; правила поворота (2×1 ↔ 1×2), порядок (по размеру? по редкости? по времени добавления?).
2. **Стеки**: несколько одинаковых предметов — отдельные ячейки-стеки (как в игре, с лимитом стека) или один предмет × N? EFT-стек-лимиты в данных? (проверить `items.stackMaxSize` — есть ли поле).
3. **Ширина сетки**: 10 (канон схрона по изданию) или 14 (витрина). Влияет на реализм «реального занимаемого места».
4. **Расширение**: показывать пустые ряды до размера схрона издания, или растить строго под контент?
5. **Взаимодействие**: клик по ячейке = −1 «в схроне»? ссылка на предмет? read-only?
6. **Перф**: сотни предметов → виртуализация/мемо (гоча из needed-merge — тяжёлый пересчёт state).
7. **Мобилка** (cta-mobile): 56px×10кол = 560px — на телефоне скролл/зум сетки.

## Разбивка (набросок, до реального спека)
1. Ридер размеров: убедиться, что `gridWidth/Height/backgroundColor/gridImageLink` доезжают до клиента (join к `useInventoryStore` id).
2. `StashCell` (или расширить TrackCell) — предмет во «footprint» ячеек.
3. Packer — раскладка по сетке ширины W.
4. Раздел/страница + вход из Важных предметов и craft-profit.
5. Live-verify + мобилка.

**Следующий шаг:** после закрытия craft-profit — отдельный грилл по этому эпику (упаковка, ширина, стеки), затем спека и реализация. Данные (`gridImageLink`, `stackMaxSize`) выверить на старте.
