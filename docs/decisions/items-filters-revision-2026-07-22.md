## Найденные проблемы (ревизия)

1. **Мёртвый табличный вид (крупный тех-долг).** `viewMode` захардкожен `'grid'` (клиент, стр. 1015), но `useCategoryFilters` до сих пор читает/пишет `view` в URL + localStorage + `SavedFilters`; `CategoryTableRow` (~400 строк, switch по всем категориям), `handleColumnSort` и колоночные ветки сортировки — мёртвый код (~30% файла).
2. **Скрытые сохранённые фильтры → «почему пусто».** Дискета персистит `caliberFilter` и `activeArmorClasses` глобально; на чужой категории фильтрация применяется, а панель Advanced фильтр не показывает (`showCaliber=false`) → пустой список без видимой причины.
3. **Асимметрия `favoritesOnly`.** Есть в URL (`fav`) и в `resetFilters`, но НЕ в `SavedFilters` / `handleSaveFilters` / restore. Единственный фильтр, который дискета не сохраняет, хотя тост обещает «по умолчанию».
4. **«Невидимые» фильтры трейдеров и подтипа очков.** `selectedTraders` и `activeEyewearSubtype` режут список, но не входят в бейдж `activeAdvancedCount` и не сбрасываются кнопкой «Сбросить фильтры» (они в другом сторе / локальном стейте) → кнопка сброса не помогает.
5. **Класс брони — нет «снять/выбрать всё».** Сняв все 6 тумблеров, юзер прячет всю броню; вернуть можно только по одной иконке. Нет мастер-тумблера.
6. **Мелочи.** «Цена от/до, ₽» неоднозначно (это цена ПОКУПКИ `minPrice`) · `isFlVendor` пересоздаётся в `.filter` на каждой итерации.

## Deep research: CTA vs конкуренты (живой UI, июль 2026)

**tarkov.dev** — «таблица на категорию + глобальные настройки». Категорийные страницы скупые (у оружия только колонки цен, без калибр/эрго/отдача). Тумблер «Игнорировать настройки» + глоб. настройки (уровни торговцев, PVP/PVE). Богатые фильтры вынесены в специнструменты: аммо-чарт (мин. пробитие, мин. урон, макс. цена, тумблер «патроны торговцев», клик по калибру + scatter-plot пробитие/урон); отдельные `/barters`, `/crafts`, `/hideout`, `/loot-tiers`.

**tarkov-market** — «барахолка-центричная таблица + дерево категорий». Дерево категорий со счётчиками (Боеприпасы 411, Оружие 205, Оружейные части 2206…) + поиск по дереву. Чипы трейдеров (Любой…Реф). Чипы-теги (Избр., Ключи, Бартер, Кейсы, Прицелы, Глушаки…). Слайдер «Ур. барахолки 1–40». Колонки-тренды (Ср. цена 24ч/слот, Изм. 24ч, Изм. 7д) + профит-флип (часть за Pro). Тумблер PVP/PVE, валюта.

## Deep research 2: чего хотят игроки (фидбек из соцсетей и трекеров issue)

Reddit заблокирован для нашего веб-краулера → снято через браузер (old.reddit). GitHub issues `the-hideout/tarkov-dev` (16 открытых / 129 закрытых) = буквальные запросы игроков.

### Jobs To Be Done — зачем игрок вообще открывает агрегатор
Из гайдов для новичков (сотни upvotes) видно повторяющийся набор задач — по ним игроки описывают, ЗАЧЕМ идут на tarkov-market / tarkov.dev:
1. **«Стоит ли подбирать / держать этот предмет?»** — быстрый value-чек в рейде (цена, цена/слот). *«check for prices of items in raid — is this worth picking up?»*
2. **«Нужен ли он мне для квеста / убежища / бартера, и нужен ли FiR?»** — **самый частый юзкейс**, всплывает в каждом гайде. *«check whether or not you need an item for a specific quest or barter… if it needs to be found in raid»*, «Quest item chart to remember what to keep».
3. **«Какой патрон лучший под бюджет/ситуацию?»** — best-in-slot по пробитию/урону vs цена (ammo chart — обязательный инструмент в каждом гайде).
4. **«Какие моды подходят к моему стволу?»** — фильтр совместимости. Топ-саджест `«Add a "Compatible With" filter»` (65 upvotes, 15 комм.).
5. **«Выгоден ли крафт/бартер?»** — маржа/лучший margin для хайдаута.
6. **«Реально ли это купить/продать на барахолке?»** — ликвидность: GitHub #1050 «"Availability" metric for flea prices», #826 «Trade High, Low, Volume».

### Прочие релевантные issue tarkov.dev
- #656 «Muzzle device list» — игроки хотят более **гранулярные подкатегории** модов.
- #1287 «Story Chapters progression» — привязка каталога к сюжетному прогрессу (у нас уже есть истории).

### Сверка с CTA — что уже закрыто, что гэп

Данные у нас есть (`useQuestStore`, трекинг убежища) — это, возможно, **киллер-фильтр** и наша дифференциация.
- JTBD-3 (ammo best-in-slot) — покрывается Этапом 3 (стат-слайдеры).

**Правка V4DYA №3 — range-цена + валюты, снос старых фильтров:**
- Снесены: инпуты «Цена от/до» и 4 флага доступности (Купить/Продать у торговца/на барахолке) — **полностью**: UI, стейт хука (`cantBuy/Sell*`), URL-параметры (`nbt/nbf/nst/nsf`), `SavedFilters`, save/restore/reset, логика фильтрации. Контрол `availabilityFlags` убран из конфига.

- **Переключатель валют** ₽/$/€ (маски `icon-eft-currency-ruble/dollar/euro`) в шапке блока цены. Конвертация по **живому курсу**: `getCurrencyRates()` прокинут с сервера (`page.tsx` → `rates` проп); подписи слайдера показываются в валюте (₽→$/€ ÷ курс), фильтр по-прежнему по ₽-цене (`minPrice`). $/€ дизейблятся, если курс недоступен.
- `caliber` (ammo/guns) и сброс — сохранены; `activeAdvancedCount` = цена+калибр+подкатегории (без cant*).
- **Итерации вёрстки (V4DYA):** панель без верхней линии-разделителя; ряд «категории / валюта / **база цены** / диапазон» в одну строку; заголовок «Диапазон цены» заменён на живые границы диапазона в шапке блока; деления шкалы 7 шт (равномерно по лог-оси), **кликабельные** (клик → ближайший ползунок), с тап-зоной под телефон; шкала вплотную к дорожке; кнопка «Сбросить» — компактная, красная, в одну линию.
- **Диапазон цен — независимые базы Купить↑/Продать↓** (V4DYA): два самостоятельных toggle (не XOR), **обе включены по умолчанию**. Предмет проходит диапазон, если цена ЛЮБОЙ включённой базы в [min,max] (buy=`minPrice`, sell=`bestSell`; нулевые/отсутствующие цены не считаются). Юзер сам решает, по чему фильтровать. Стейт `priceBases: Set<'buy'|'sell'>`. Лейбл блока «Диапазон цен».

**Deep research по сортировке + новые пункты (V4DYA):** конкуренты (tarkov-market) сортируют по Название / Ср.цена 24ч / Цена-слот / Изм.24ч / Изм.7д / Продажа торговцу + профит-флип. **Данные minLevelForFlea — синк vs ручной оверрайд:** синк цен УЖЕ полностью проводит `minLevelForFlea` (GraphQL `eft-prices.ts:76` → `syncEftPrices` insert/upsert `db/prices.ts:41,71`), НО в БД 0/5056 (все NULL) — tarkov.dev либо не отдаёт поле (есть fallback-дроп по `OPTIONAL_FIELDS`), либо синк давно не гоняли; на попытке `db:sync-prices` tarkov.dev вернул **HTTP 503** (лежит). Поэтому — **ручной JSON-оверрайд** `src/data/eft-flea-levels.json` (как container-grid-overrides): `byBsgCategory` (id→{label,level}, предзаполнен оружием ~20-25 / бартер-подкатегориями ~30, прикидки EFT 1.0 — править под факт) + `byItem` (normalizedName→level, точечно). Мержится **на чтении** в `eft-category.ts` (`fleaLevelFor`: БД → byItem → byBsgCategory), не зависит от крона. Плашка оживает сразу для профиля ниже порога.

**Флиа-лок на плитке + снос «Доступно мне» (V4DYA):** вместо грубого фильтра «Доступно мне» (blanket `playerLevel≥15`) — пер-предметный индикатор недоступности барахолки. `minLevelForFlea` пробошен по цепочке `getEftPriceMapFromDb → EnrichedItem → CategoryItem → toEftItem → EftItemData`. **Фильтр применён ко ВСЕМ категориям (V4DYA):** `DEFAULT_FILTER_CONFIG` получил современный кластер «Отображать только» (`usedIn` + `needMe`) — теперь на всех «конечных» категориях, не только barter. Диапазон цены/валюта/Купить-Продать и так рендерились везде (advanced у всех). `subtypeBar` для конечных категорий = `null` → «Выбор категорий» показывается ТОЛЬКО там, где есть подкатегории (barter) — как и просил V4DYA. Попутно из DEFAULT убран `barterOnly` (кнопка «Бартер»): на небартерных категориях она бесполезна/вредна (обнуляла список) и дублирует чип usedIn «Бартеры». `armorClass` (armor-категории) / `caliber` (ammo/guns) / `availableOnly` / избранное — сохранены.

**Фильтр «Нужно мне» (needMe) — квесты (V4DYA-скоуп):** кнопка в кластере «Отображать только» (иконка `icon-eft-prog-items-needed`); показывает только предметы, нужные для **незавершённых** квестов — `questIndicatorMap.get(id).status ≠ 'completed'` (тот же источник, что квест-индикатор/фильтр «Квесты»).
