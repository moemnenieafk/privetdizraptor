# cta.quest — изолированный лендинг батлпасса (карта документов Сезона 1)

## Цель
Отдельный **статический** сайт на домене `cta.quest` про Боевой Пропуск Сезона 1 EFT: разводящий лендинг + трекер + простая карта с метками документов. Данные меток и скриншоты **синкаются с нашего основного сайта кроном**, но прод-Supabase на cta.quest **не светится вообще** — ни клиента, ни anon-ключа, ни запросов к БД в рантайме.

## Ключевая идея (почему это не Схема A)
V4DYA решил: **полная изоляция от базы**. Значит cta.quest — не ещё один домен основного Vercel-проекта, а **самостоятельный лёгкий деплой**, который кормится только публичными артефактами на R2 (JSON меток + webp-скрины). База остаётся приватной у крона на основном сайте. Плата за это — **частичный форк дизайн-системы** (копируем токены/шрифты/трекер), принята осознанно.

## Пайплайн данных (крон → R2 → cta.quest)
```
Визард editorial-маркеров (основной сайт)                     ← авторинг, тут БД есть
   → editorial_markers  (link=event «Kord Breach» + предмет-документ 1/8, screenshots[] = R2-URL)
        ↓ КРОН на основном сайте: /api/cron/publish-bp-docs
   R2: landing/battlepass-docs.json   (публичный, короткий cache)   ← «зеркало» §4.11
        ↓  fetch (CDN, no-store/revalidate)
cta.quest: карта-читалка + скрины с R2                        ← 0 обращений к БД, ключа нет
```
- **Селектор меток — связь с событием, а не выдуманный тег.** Метка ставится с привязкой к **событию «Сезон 1 — Kord Breach»** (`link_kind='event'`, `link_id` = id сезона из `eft-seasons.ts`) и несёт **предмет-документ** — один из 8 из `/eft/items/battle-pass` (BSG-id в `lootItems[0]`; он же определяет, ЧТО за документ и его иконку). Одна метка = одна точка спавна одного документа.
- **Крон живёт на ОСНОВНОМ сайте** (там уже есть доступ к БД и R2). Читает `editorial_markers WHERE link_kind='event' AND link_id=<kord-breach>` по всем картам, лепит минимальный публичный JSON (`id, mapId, floor, x, z, itemId(=lootItems[0]), title, description, screenshots[]`), кладёт в R2 под стабильным ключом `landing/battlepass-docs.json`. Добавить строку в `vercel.json → crons` (расписание ~ежечасно, метки редко меняются — можно реже).
- **cta.quest только читает** этот JSON и грузит скрины по их R2-URL. R2 — публичное CDN, не база: светить безопасно (тот же класс, что иконки/тайлы карт).
- Это ровно паттерн §4.11 (крон → зеркало), только «зеркало» здесь — публичный R2-файл, а не Supabase-таблица, потому что потребитель обязан быть без БД.

## Границы
- **В scope:** новый под-проект `cta-quest/` (свой деплой); крон-паблишер JSON на R2; карта-читалка меток; перенос трекера; каркас лендинга (наполнение/дизайн — за V4DYA).
- **НЕ трогаем:** схему `editorial_markers` (всё нужное уже есть: `link_kind='event'` + `link_id`, `lootItems`, `screenshots jsonb`, RLS read-all); визард (авторинг как есть); основной сайт по функционалу — только добавляем крон-роут.

## Открытые вопросы (уточнить до старта)
- **Паритет арта (⚠️ блокер, см. гочи)** — на КАКОЙ версии Shebuka-SVG вы ставите метки в визарде? cta.quest обязан рендерить ровно её, иначе координаты не 1:1. Если обновляем на the-hideout-версию — обновить арт и на основном сайте, ИЛИ ставить метки уже на новой.
- **id события Kord Breach** — точное значение `link_id` (slug/uuid сезона из `eft-seasons.ts`), по которому крон фильтрует. Сверить, что визард пишет именно его.
- **Legacy-скрины** — если какие-то метки успели попасть со скринами в старый Supabase Storage, их URL не R2 → мигрировать. Набиваете на R2 сейчас → скорее не актуально.

## Гочи
- **⚠️ ПАРИТЕТ АРТА КАРТ — главный риск.** Координаты меток `{x,z}` живут в системе рендера КОНКРЕТНОГО Shebuka-арта. Метки, поставленные на одной версии SVG, лягут 1:1 только на неё же. Обновляем на the-hideout-SVG → тем же артом должны рендерить и cta.quest, и (если метки ставятся там) основной сайт. Рассинхрон арта = метки уедут. Проверять паритет до массовой набивки.
- **⚠️ Кэш R2-JSON.** `r2Put` сейчас ставит immutable-кэш на год (годится для картинок, НЕ для меняющегося JSON). Для паблишера нужен вариант с коротким `Cache-Control` (напр. `max-age=300`) — либо параметризовать `r2Put`, либо `r2PutJson`. Плюс cta.quest тянет JSON с `cache: 'no-store'`/revalidate, иначе увидит устаревшее.
- **Читатель по событию.** `getEditorialMarkers(mapId)` берёт по карте; крону нужен срез по событию через все карты — добавить `getEventMarkers(linkId)` (или `getBattlepassDocMarkers()`) в `src/db/editorial-markers.ts`, фильтр `link_kind='event' AND link_id=<kord-breach>`.
- **Иконки документов.** JSON несёт `itemId` — cta.quest резолвит иконку из скопированного минимального набора (8 файлов), а не из полной базы иконок.
- **Дрейф токенов.** Копии NIGHTFALL разойдутся с основным при правках дизайн-системы — держать sync-скрипт и прогонять при изменениях (§6).
- **Публичный R2-base в cta.quest** — это `NEXT_PUBLIC_*` (не секрет), безопасно вшить в env под-проекта.

## Критерий готовности (детерминированный)
- [ ] Крон `/api/cron/publish-bp-docs` кладёт валидный `landing/battlepass-docs.json` на R2 (прод-курл публичного URL → 200 + свежие метки).
- [ ] `cta-quest/` собирается (`tsc` чисто, build ок), в бандле **нет** `@supabase/*` и anon-ключа.
- [ ] Карта-читалка (Leaflet-лайт, зум/пан) рендерит метки из R2-JSON, клик → скрин с R2 + иконка документа; метки ложатся на Shebuka-SVG (the-hideout) 1:1 (визуальная сверка на 1–2 картах).
- [ ] Трекер работает на localStorage без сети к БД.
- [ ] Деплой на отдельном Vercel-проекте, домен `cta.quest` привязан, SSL поднят.

## Гарды
- Бюджет/масштаб: средний — новый под-проект + один крон-роут + карта. Не рефактор основного.
- Ручное подтверждение: покупка домена и DNS — за V4DYA; добавление крона в `vercel.json` (пуш в main) — подтверждением одной строкой.

## Этапы
1. Крон-паблишер JSON на R2 (+ `r2PutJson` короткий кэш, + `getBattlepassDocMarkers`). Домен не нужен.
2. Каркас `cta-quest/` + копия токенов/шрифтов + sync-скрипт.
3. Карта-читалка (арт + метки из R2 + лайтбокс скринов).
4. Перенос трекера.
5. Каркас лендинга (дизайн V4DYA).
6. Деплой: новый Vercel-проект (Root Directory `cta-quest`) → cta.quest → DNS → SSL.
