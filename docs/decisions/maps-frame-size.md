# Карты: единый размер фрейма + адаптив

**Статус:** 🔵 обдумываю — нужно твоё решение по адаптивной стратегии.
**Затрагивает:** `MapFrame.tsx` (sizing) · `MapViewerClient` (CRS/zoom)

## Контекст
Хочется единый эталонный размер фрейма **1100×768px на FullHD (1920×1080)**. Сейчас фрейм резиновый: `h-[80vh] min-h-[600px] w-full` (`MapFrame.tsx`), fullscreen = `fixed inset-0`. Вопрос — как это ведёт себя на других разрешениях (ноуты 1366×768, 1440p, 4K, ультраширокие).

## Развилка (нужно твоё решение)
- **A — Фиксированный aspect-ratio.** Зафиксировать пропорцию 1100×768 (≈1.43:1) через `aspect-[1100/768]` + `max-w`, центрировать. Предсказуемо, но на маленьких экранах фрейм мельчает.
- **B — Резиновый с брейкпойнтами.** Базис 1100×768 на FullHD, ниже/выше — брейкпойнты (Tailwind `lg/xl/2xl`) с заданными размерами. Гибко, но больше правил.
- **C — Адаптив по высоте вьюпорта.** `min(1100px, 92vw) × min(768px, ...)` —攻 заполняет экран, держит пропорцию. Компромисс.

## За / Против
| Вариант | За | Против |
|---|---|---|
| **A** | предсказуемость, 1 правило | мельчает на ноутах |
| **B** | контроль на каждом брейке | много правил, поддержка |
| **C** | заполняет экран, держит пропорцию | сложнее настроить CRS-zoom |

## Вывод
нам подходит решение А, но поведение на ноутбуке 1366×768 - фрейм адаптируется по высоте например 1100х576. Вообще логика такая что у нас есть контентная область состоящая из колонок и масштаб фрейма по умолчанию (не в полноэкранном режиме) регулируется по высоте. Иначе говоря на экране должно быть видно фрейм + хедер практически всегда до малого брейкпоинта минимального экрана ноутбука.
