# Меченые и цветные комнаты

**Статус:** 🔵 обсуждено (1-я итерация), к исполнению после макета
**Источник:** голосовое 2026-07-28 · [[audio_2026-07-28_00-06-43]] (7:10)
**Участники:** V4DYA, Дмитрий

## Суть
Меченые комнаты (и цветные комнаты Лаборатории) получают на карте подсвеченные границы, а по клику — **отдельную страницу** с экономикой ключа, лут-таблицей и живой статистикой открытий от сообщества. Цель — превратить «какой ключ брать и стоит ли» в один экран с готовым вердиктом.

## Как сейчас
- Драйвер (боковая панель) уже есть и используется в других разделах.
- Отдельного модуля меченых комнат нет — проектируем с нуля.

## Решения созвона
- **Отдельная страница, а не drawer.** V4DYA изначально предполагал drawer, но в моменте согласился: объём данных (лут-таблицы, история открытий, пруфы) слишком велик, а drawer уже занят под другие задачи. Пользователь кликает границу комнаты → переходит на полную страницу.
- **Медиа не храним у себя.** Видео — только ссылкой на YouTube; скриншоты — во временное хранилище, удаляются **сразу** после модерации. Экономит диск (Дмитрий: «даже гиг много»).
- **На слово не верим.** Любое открытие подтверждается скриншотом или видео, иначе в статистику не идёт.

## Что делать

### Карта
- Подсветка границ меченых комнат и цветных комнат Лаборатории (чёрная / фиолетовая / зелёная и т.д.).
- Клик по области комнаты → переход на её страницу.

### Страница комнаты
- **Лут-таблица:** все предметы, доступные к луту, с шансами и актуальной ценой.
- **Экономика ключа/карты:** где взять, как найти, цена на барахолке, средняя стоимость одного открытия, вердикт «выгодно / в минус» на текущий момент.
- **Скриншоты** от пользователей (загрузка + модерация, как у предметов).

### Живой трекер открытий (комьюнити)
- Лента последних открытий: «1 мин назад — чёрная ключ-карта, Red Rebel, планшет для документов, фигурка партизана».
- Пересчёт реального шанса выпадения по **последним 100 открытиям** пользователей.
- Предметы открытия добавляются вручную (модератором) и сразу видны в ленте.
- Авторство: какой пользователь добавил открытие (если не анонимный режим).

### Регламент пруфов
1. Запись **до** отпирания — в руках/контекстном меню виден ключ или карта.
2. Заход в комнату и подбор всех предметов.
3. Открыть инвентарь — у предметов галка «Найдено в рейде» (FIR).
4. На видео/скрине видны **текущая версия игры, дата и время**.
- Видео принимаются только ссылкой на YouTube; скриншоты — временно, удаляются после проверки.

### Модерация («колокольчик»)
- Отдельный раздел уведомлений для модераторов (по принципу колокольчика Госуслуг): видно, в каком разделе появились заявки.
- Модераторы — проверенные активные участники сообщества (возможен и платный вариант доступа).
- Действия модератора: просмотр заявки с медиа → быстрый выбор найденных предметов из базы сайта → «Принять» / «Отклонить» с авто-начислением репутации и обновлением базы.

### Геймификация
- За принятое открытие — очки репутации.
- Репутацию можно обменять на бонусы сайта (например, **Premium на 1 месяц**) — мотивация модерировать и присылать открытия.

## 🤖 Backend-дизайн трекера открытий (Claude, 2026-08-02) — ПРЕДЛОЖЕНИЕ к ревью

> Отвечает на 3 «Задачи для Клода» (схема БД · пайплайн модерации медиа · модель репутации).
> ⚠️ ДИЗАЙН, не код: ни таблицы, ни миграции не заведены. UI/страница ждут макета (§ статус), но
> модель данных от макета не зависит — проектируется вперёд. **§4.11:** `room_opens` — НАША
> community-таблица (user-ingest через API после модерации), НЕ зеркало внешнего API → легальная
> запись, UI читает только её; наружу рантайм-фетча нет. Паттерн — editorial/markers (DDL-модуль +
> RLS read-all, запись owner-ролью).

### 1. Модель данных (эскиз; имена — на ревью)
**`marked_rooms`** — реестр меченых/цветных комнат (сущность страницы + подсветки на карте):
`id uuid pk` · `game_id`→games · `map_id`→maps · `slug` (маршрут `/eft/maps/<map>/rooms/<slug>`) ·
`kind` (`marked` | `lab_color`) · `color?` (чёрная/фиолетовая/зелёная — цветные Лабы) ·
`key_item_id?` (ключ/карта, id зеркала — экономика ключа = уже готовый reader) · `polygon?` (границы
подсветки) · `title/description` · timestamps.
> Сид: уже есть `map_markers` type='lock' + `lockKind='marked'` (linkedItemId=ключ) → засеять реестр
> из них; цветные комнаты Лаборатории курируются вручную (их немного).

**`room_opens`** — одно открытие комнаты (заявка сообщества):
`id uuid pk` · `room_id`→marked_rooms · `author_id`→profiles (nullable — аноним-режим) ·
`status` (`pending`|`approved`|`rejected`) · `moderator_id`→profiles? · `moderated_at?` ·
`proof_youtube_url?` · `proof_screenshot_key?` (ключ ВРЕМЕННОГО Storage-бакета; → NULL после
авто-удаления, § «медиа не храним») · `game_version` (регламент пруфов: видна версия/дата) ·
`opened_at` · `created_at`. Индекс `(room_id, status, created_at desc)` — витрина «последние N».

**`room_open_items`** — предметы открытия (M:N, для ленты + пересчёта шанса):
`open_id`→room_opens (cascade) · `item_id` (id зеркала) · `qty int default 1`. Индекс `(open_id)`.

**Репутация** — леджер, не денормализованный баланс:
`reputation_events`: `id` · `user_id`→profiles · `delta int` · `reason` (`room_open_approved`…) ·
`ref_type/ref_id` · `created_at`. Баланс = `sum(delta)`. Обмен на Premium — НЕ тут, а через
энтайтлменты ([[feature-gating-entitlements]]): редемпшн списывает репутацию → grant Premium на срок.

### 2. Витрина «последние 100» → шанс выпадения
Пересчёт по последним 100 **approved**-открытиям комнаты: запрос `limit 100` + агрегат частот
`room_open_items` (дёшево при индексе) — materialized view на старте НЕ нужен; если ленты станут
горячими → materialized + refresh по факту принятия. Лента «1 мин назад — …» = approved-опены
`order by moderated_at desc`.

### 3. Пайплайн модерации медиа
Скрин → приватный **временный бакет** Storage (напр. `room-proofs/`), ключ в `proof_screenshot_key`;
после вердикта — **немедленно удалить объект**, ключ → NULL (Дмитрий: «даже гиг много»). Видео —
только `proof_youtube_url`. Модератор: заявка+медиа → выбор найденных предметов из каталога
(`getEftCatalog`) → «Принять» (INSERT `room_open_items` + `reputation_events` +N, `status=approved`)
/ «Отклонить». «Колокольчик» — отдельный разговор (аккаунт-центр, см. ❓); на старте достаточно
очереди `where status='pending'` (как `reports` в Comlink). **RLS:** read-all по approved; INSERT
заявки — авторизованный юзер (rate-limit через mirror-таблицу, §4.11); модерация/начисление —
owner-роль (`canModerate`).

### 4. Зависимости / границы (что НЕ трогаю)
- **UI-страница + подсветка на карте** — ждут макета V4DYA (модель данных спроектирована вперёд).
- **Обмен репутации на Premium** — гейтит [[feature-gating-entitlements]] (🟡 дизайн-спринт).
- **Раздел модерации/«колокольчик», платный доступ к модерации** — ❓ аккаунт-центр, не финал.
- **Термины в глоссарий** (§8.3, до кода): «меченая комната», «цветная комната», «открытие»
  (room-open), «пруф» — предложены, финал за V4DYA.
- **Переиспользуется (не строить заново):** экономика ключа (карточка Замок→Ключ + prices-зеркало),
