# События — раздел и крон-детект ивентов

**Роль заметки:** как устроен раздел «События» и как узнать, что вышел новый ивент. Ветка от [[Обновление данных при выходе контента.md]] (там про **данные** — предметы/квесты/цены; тут про **редакторскую хронику ивентов**, у неё другая природа).

> [!tldr] Коротко
> - Раздел «События» (`/eft/quests/events`) — **ручная редакторская хроника** в `src/data/eft-events.ts`. Это НЕ зеркалимые данные: нет структурированного фида в нашем формате (`summary`, `changes[]`, категория, `contentStatus`, связки) → **на §4.11-конвейер «крон→Supabase→UI» не садится**. UI лишь резолвит квесты/ачивки/бартеры ивента против живого зеркала на рендере (`src/lib/eft-event-content.ts`).
> - Поэтому авто-запись невозможна; сделали **детект+пинг**, запись ивента остаётся ручной (мы + V4DYA).
> - Актуализировано на **Kord Breach (Сезон 1)** 2026-08-08 (commit `da20d9a4`): «Блэкаут» закрыт, добавлен пред-сезонный босс-ивент + активный Kord Breach.

## Модель раздела
- Данные: `src/data/eft-events.ts` (`EFT_EVENTS[]`, старые→новые), типы `src/types/eft-events.ts`. Один ивент = `{id,title,date,category,summary,changes[],…}` + опц. `active`, `endDate`, `patch`, `contentStatus`, `contentNote`, `quests[]`, `achievements[]`, `barters[]`.
- **Ровно один** ивент несёт `active: true` → бейдж «Идёт сейчас» + амбер-бордер + авто-раскрытие карточки (`EventCard`/`EventsTimeline`).
- `contentStatus` (`permanent`/`seasonal`/`expired`/`unknown`) = что стало с наградами после конца. Дефолт по категории, если не задан явно (`getEventContentStatus`).
- Актуальность бартеров/ачивок считается по **живой БД** на рендере (не по ручным флажкам).

## Крон-детект «вышел новый ивент?» (commit `c88daa0f`)
Только **детект + пинг** — не авто-запись.
- **Роут:** `GET /api/cron/detect-events` (Bearer `CRON_SECRET`, fail-closed). Логика — `src/lib/eft-events-detect.ts`.
- **Два источника (оба best-effort — сбой одного не роняет детект):**
  - Steam News API (`src/lib/steam-news.ts`, appid 3932890) — чистый JSON, надёжно.
  - Офиц. TG-канал BSG (`src/lib/bsg-telegram.ts`, парсинг `t.me/s/escapefromtarkovRU`) — **HTML-скрейп, хрупко**; при сбое детект живёт на Steam.
- **Логика:** новости BSG **свежее последнего записанного события** → кандидаты; помечаем ⚑ похожие на ивент (ключевые слова). Пинг шлём, только если есть ⚑-кандидат (не спамить хотфиксами); полный список всегда в JSON-ответе.
- **Расписание:** GitHub Actions **еженедельно** (`.github/workflows/detect-events.yml`, пн 08:00 UTC) — на Vercel Hobby лимит крон-джоб уже занят (`sync-prices`, `detect-anomalies`).
- **Схему/таблицы не трогает** (без `db:push`).

## ⚙️ ENV (неочевидное — иначе потеряется)
| Переменная | Где | Зачем |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Vercel env | Бот для пинга. Нет → детект работает, пинга нет (graceful). |
| `TELEGRAM_CHAT_ID` | Vercel env | Куда слать (лично/канал/группа). |
| `BSG_TG_CHANNEL` | Vercel env (опц.) | Переопределить TG-канал. Дефолт `escapefromtarkovRU`. |
| `CRON_SECRET` · `PROD_BASE_URL` | GitHub Secrets/Variables | Уже есть от `sync-prices` — новое не нужно. |

## Активация пинга (за V4DYA — 1 раз)
1. `@BotFather` → `/newbot` → **токен**.
2. `chat_id`: написать боту → `https://api.telegram.org/bot<ТОКЕН>/getUpdates` → `chat.id` (или для канала — бот-админ + `@имя`/`-100…`).
3. На Vercel (Production) добавить `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`.

## Проверка
- Actions → **detect-events** → Run workflow, **или** `curl -H "Authorization: Bearer <CRON_SECRET>" <PROD>/api/cron/detect-events`.
- Ответ: `sources` (оба ли опросились), `candidates` (что новее последнего события), `notified`. Детект виден **до** настройки бота.

## Гочи
- **TG-источник хрупкий** (разметка `t.me/s/` может тихо поменяться) — потому и best-effort поверх надёжного Steam. Если TG перестанет парситься — `sources.telegram=false`, детект продолжает на Steam.
- **Пинг эвристический** (ключевые слова) — иногда лишний (промо вроде «Twitch Drops сезона»), редкий чисто-тематический ивент без ключевика может не подсветиться → в JSON всегда полный список.
- **Запись ивента — ручная by design.** Крон только напоминает; текст/категорию/статус/связки заводит человек (нет канон-источника, §4.11/§4.12).

## Рецепт: обновить раздел под новый ивент
1. Снять `active` у прошлого активного, проставить ему `endDate` + актуализировать `contentNote`/`contentStatus`.
2. Добавить новый ивент в конец `EFT_EVENTS` с `active: true` (категория из существующих; season → `gameplay`).
3. Опц. прилинковать `quests[]` (normalizedName из базы), `achievements[]`, `barters[]` — резолв по зеркалу сам покажет актуальность.
4. `tsc --noEmit` (ровно один `active: true`), коммит.
