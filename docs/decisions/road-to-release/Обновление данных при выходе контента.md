# 🔄 Обновление данных при выходе контента

**Вопрос V4DYA:** как обновлять данные на сайте, когда выходит новый контент (патч / вайп / сезон)? Что у нас по **предметам** (все ли в базе), по **квестам** (тянем ли полную ветку), и можем ли **честно брать это из локально установленной игры**. Плюс deep research: почему легла `tarkov.dev` API и можно ли синкать данные прямо из их репозиториев с открытыми ветками.

**Роль заметки:** карта путей обновления данных + отчёт о текущем состоянии + разбор the-hideout. Ветка от [[BSG 1.1.0.0 — влияние на портал.md]] — там **ЧТО** поменял патч, тут **КАК** мы это подхватываем. Основано на 4 фоновых расследованиях (пайплайн, предметы/квесты, the-hideout, локальный SPT) + live-проверке.

> [!tldr] Коротко
> - **Гипотеза V4DYA подтверждена дословно.** GraphQL `api.tarkov.dev` схлопнули ради экономии (миграция с Cloudflare Workers на VM, issue #312), она сломалась ~21.07 и не чинится, потому что сам сайт tarkov.dev давно живёт на **`json.tarkov.dev`**. JSON — их канонический фид, обновляется каждые минуты (проверено: каталог 16.5 МБ, `Last-Modified` = вчера). **Это не юр-война.**
> - **Наш сайт уже на JSON.** После рефактора 23.07 весь EFT-синк = `json.tarkov.dev` primary + GraphQL fallback. На чистом живом GraphQL висят ровно **2 некритичных куска** (тексты ачивок, история цен) — и у **обоих теперь есть JSON-путь**, т.е. живую GraphQL-зависимость можно обнулить целиком.
> - **Предметы:** ✅ **5 266 в базе**, покрытие полное, контент 1.1.0.0 уже внутри.
> - **Квесты:** ✅ **полную ветку тянем** (`taskRequirements[]` = список рёбер графа). НО текущий файл дампился через *мёртвую* GraphQL и он **до-патчевый** → чинить дамп на `json.tarkov.dev/tasks` и пересобирать под УЛ-структуру 1.1.0.0.
> - **Из локальной игры честно берём?** ✅ Да. В `D:\Games` стоят **живые ретейл-клиенты BSG** — `Escape from Tarkov` (**1.1.0.0.46624, current-patch**) + `Escape from Tarkov Arena` — и офлайн `SPT`. Разделение труда: живой клиент **данные на диск не кладёт** (тянет с сервера BSG) → он источник **АССЕТОВ 1.1.0.0** и эталон версии; **ДАННЫЕ** at-rest даёт **SPT** (полный JSON-каталог + весь граф квестов 558/736 рёбер, но **на патч отстаёт**) либо свежий `json.tarkov.dev`. ⚠️ Юр-риск ~12.08 бьёт по SPT-JSON и `sp-tarkov` git, **не по ретейл-клиентам**.
> - **Синк прямо из их git-репозиториев?** ❌ В основном нет: полного корпуса (предметы/цены/квесты) **нет ни в одной git-ветке** — он только за `json.tarkov.dev`. В git лежат лишь узкие MIT-срезы (сетки контейнеров, геометрия карт) — их брать можно.

## ❓ Почему легла GraphQL — разбор the-hideout (подтверждено первоисточниками)

**Причина прозаична и подтверждена — стоимость хостинга, НЕ юристы:**

- **[tarkov-api #312](https://github.com/the-hideout/tarkov-api/issues/312)** «Update GraphQL Deployments» (открыт 2024-07-14, всё ещё не закрыт), дословно: *«In order to save the project costs, we're moving the GraphQL portion of the API off of Cloudflare Workers, and onto a Virtual Machine… the end of Stellate's generous open source tier… changes to Cloudflare Workers' pricing model»*.
- **[PR #468](https://github.com/the-hideout/tarkov-api/pull/468)** «don't process graphql requests in the worker» (влит 2026-06-29) — воркер **лишили GraphQL-вычислений**, он делегирует на VM.
- **[PR #473](https://github.com/the-hideout/tarkov-api/pull/473)** «Trigger deployment after Cloudflare credential rotation» (2026-07-22) — **ротация ключей ~21.07 совпадает с началом даунтайма**. Путь воркер→VM сломался и не восстановлен.
- **[Issue #474](https://github.com/the-hideout/tarkov-api/issues/474)** (открыт 2026-07-22, живой на 03.08): мейнтейнер — *«The GraphQL API is down for the moment, but you have the Json API who alive… Tarkov.dev is based on this Json API and not on the GraphQL»*.
- **Миграция на JSON — осознанная и как ПЕРВИЧНЫЙ путь:** [tarkov-dev #1249](https://github.com/the-hideout/tarkov-dev/issues/1249) «Convert site to use JSON API» (влит 2026-04-23); GraphQL понижен до вторичной страницы `/api-graphql`.

**Чего НЕТ:** формального объявления о deprecation (в issue ноль `sunset`/`deprecat`/`shut down`); юр-претензии к tarkov.dev (ноль `legal`/`bsg`). Репозитории активно поддерживаются (фичи-PR до 05.08). GraphQL просто **сломана и не в приоритете**, потому что сайту она больше не нужна.

> [!note] Что это значит для нас
> `json.tarkov.dev` — это не «живой эндпоинт, дёргаемый на запрос», а **статический дамп данных, отдаваемый по HTTP через CDN** (файлы вида `{"data":{…},"translations":[…]}` — буквально ответ GraphQL, слитый в файл). Это ровно та сторона границы §4.12, что **разрешена** («питать зеркало — да, из любого источника, что не тонет»). Наш серверный крон → Supabase → UI-читает-только-зеркало (§4.11) поверх этого = compliant.

### Предметы — «все ли в базе?»
**Да.** Каталог = **5 266** предметов (было 5 044; новый контент 1.1.0.0 — калибр 5.8×42, тактичка — уже внутри). Источник — статический `items_database.json`, грузится идемпотентным `scripts/etl-items.ts`. В базе: нормализованные `items` + `item_categories` + `item_properties` (JSONB, размеченный union по `__typename`: ammo/armor/weapon/container/medical) + `propertiesRaw`. Живые цены — отдельная таблица `prices`, UI читает только её.

> [!caution] Скрытый ручной шаг
> `items_database.json` не пересобирается сам — это **ручной артефакт**. «Новый предмет на сайте» = кто-то регенерил этот файл (из `json.tarkov.dev/items` или SPT) и прогнал `db:etl`. Это главный кандидат на автоматизацию (см. Путь A).

### Квесты — «тянем ли полную ветку?»
**Да, полностью.** Ключ — поле `taskRequirements[]` у каждого квеста = **список рёбер графа** (предшественники). Граф считается в рантайме: `computeStatusMap` (`src/lib/quest-status.ts`) и `computeLocalDepths` (`QuestMapClient.tsx`) уже обходят пререквизиты + строят раскладку questmap. Цели, награды, трейдер, `minPlayerLevel`, `kappaRequired` — всё есть.

**Но два затыка:**
1. Файл `src/data/quests/eft-quests.json` (520 квестов) дампился скриптом `scripts/dump-quests.mjs` **через `api.tarkov.dev/graphql`** — тот самый, что сейчас 422. Пере-дамп текущим способом **невозможен**.
2. Файл **до-патчевый (1.0.x)** — структура «цепочек», а 1.1.0.0 переехал на **наборы по УЛ торговца** (см. [[BSG 1.1.0.0 — влияние на портал.md]]).

**Граф не хранится в БД реляционно** (нет таблицы `quest_edges`) — он живёт в статик-JSON и считается на лету; в БД только `quest_state` (fingerprint для детекта изменений) и `quest_progress` (прогресс игрока). Это осознанно по §4.11.

### ✅ Полный граф квестов из SPT офлайн — ДА, 100%
Каждый квест — запись по `_id` с `conditions.AvailableForStart[]`, где `conditionType:"Quest"` несёт `target` (id предшественника) + `status` (нужное состояние). Метрики из файла: **535/558 квестов имеют ≥1 предшественника, 736 рёбер, 23 корня, 224 с гейтом по уровню.** Реальный пример (квест «Дебют»):
```json
{ "conditionType": "Level", "compareMethod": ">=", "value": 1 },
{ "conditionType": "Quest", "target": "657315df034d76585f032e01", "status": [4, 5] }
```
`target` джойнится обратно в ключ `quests.json` → ребро графа. Имена — из `ru.json["<_id> name"]`. Форма **идентична** тому, что tarkov.dev отдаёт как `taskRequirements`, только целиком at-rest.

## 🛠 Пути решения — как обновлять данные при новом контенте

Механизм состоит из двух половин: **(1) заметить, что вышло** и **(2) подтянуть данные**.

### (1) Детект нового контента — уже автономен ✅
- **Diff бандлов клиента** до/после патча (`scripts/icon-render/snapshots/`, снят пред-релизный слепок 1.1.0.0) — находит новый контент без внешних API.
- **Кроны детекта изменений** — `sync-game-changes` (стата предметов), `sync-quest-changes` / `sync-trader-changes` / `sync-craft-changes` (diff SPT-базы), `sync-silent-changes` (конфиги), `sync-patches` (Steam). Пишут в `item_changes` / `change_digests` → страница «Изменения».
- **Детект новых ИВЕНТОВ** (редакторский раздел «События», не данные) — отдельный крон `detect-events` (Steam News + TG-канал BSG → пинг в Telegram). См. [[События — раздел и крон-детект ивентов.md]].

### (2) Подтягивание данных — транспорты по устойчивости

**🥇 A. Self-mirror крон поверх `json.tarkov.dev` — основной путь (уже бэкбон).**
Свежо (минуты), полно (все датасеты × regular/pve/pvp-season × 19 языков), стабильно (это фид самого сайта — жив, пока жив сайт). Конкретная работа, чтобы «новый контент подтягивался сам»:
- **Починить дамп квестов:** `scripts/dump-quests.mjs` перевести с GraphQL на `json.tarkov.dev/{mode}/tasks`; поле `taskRequirements` там же. Пере-дампить под УЛ-структуру 1.1.0.0.
- **Автоматизировать предметы:** крон, регенерящий `items_database.json` из `json.tarkov.dev/items` (+ merge переводов, см. гочу) → `db:etl`. Убирает ручной шаг.
- **Снять последнюю GraphQL-зависимость:** ачивки → `/tasks`; история цен → `/prices/{itemId}`.
- **Гоча имён:** базовый `/items` отдаёт **плейсхолдеры** (`"<id> Name"`); настоящие имена — в отдельном файле `/items_ru` (карта `{key:"Имя"}`), мержить по `translations`-JSONPath. (`normalizedName` в базовом — настоящий; ср. память `sprint-maps-interactions`.)
- **Гоча покрытия:** во время даунтайма JSON-`tasks` был на ~11 квестов короче GraphQL (499 vs 510) — при пере-дампе сверить полноту квестов.
- **Троттлинг:** `json.tarkov.dev` ловит Cloudflare-403 на burst — качать пачкой в несколько запросов/прогон, с backoff, ~раз в 15–20 мин.

**🥈 B. Статик-дамп SPT — автономный засев + холодный резерв.**
Полный каталог + **весь граф квестов** + локали офлайн, из своего экземпляра (§4.12-sanctioned). Роль: (а) разовый reseed после апдейта SPT; (б) fallback, если `json.tarkov.dev` однажды умрёт. ⚠️ Отстаёт на ~1 патч **и SPT закрывают ~12.08** → **снять копию `sp-tarkov/server` и `D:\Games\SPT` в архив сейчас** (действие выше).

**🥉 C. git-raw MIT-срезы из `the-hideout/tarkov-dev/src/data/` — узко, но чисто.**
Транспорт стабильнейший (GitHub raw почти не падает), лицензия **MIT**. Брать эти конкретные срезы из raw — ок.

**❌ Не годится:**

- `TarkovTracker/tarkovdata` — **нет лицензии** (all-rights-reserved) + заморожен с начала 2024. Не трогать как фид.
