# Чекпоинты прогресса квестов — именованные save-слоты

**Статус:** ✅ реализовано и проверено end-to-end, **не закоммичено** (ждёт ревью/пуша V4DYA).

## Что было (разведка)

Прогресс квестов жил в **трёх** слоях, а не в одном:
1. **Локально** — Zustand `persist` → localStorage `cta-quest-progress`.
2. **Облако — УЖЕ есть, авто, кросс-девайс.** `ProgressSync` (смонтирован в `layout.tsx`) на логине тянет прогресс из `quest_progress` (одна строка на `user+game`) через `GET/PUT /api/eft/progress`; любое изменение → дебаунс 1200мс → сохранение. **Залогинился на другом устройстве — прогресс подтянулся сам.**
3. **Файловый экспорт/импорт** (кнопки-дискета) — ручной локальный бэкап JSON, дублирует облако и у́же (без пинов/заметок).

**Инсайт:** «загрузить с любого устройства» технически уже работало через аккаунт. Файловые кнопки — рудимент.

## Чего не хватало

Облачный синк — это ОДНО непрерывно перезаписываемое состояние, а не save-слоты. «Чекпоинт» подразумевает **именованные точки, к которым возвращаешься** — этого не было. Это и построено (решение V4DYA из 3 вариантов: именованные чекпоинты).

## Архитектура — ФИКС-СЛОТЫ (модель V4DYA)

Не растущий список, а **3 ручных слота + 1 автослот** (решение V4DYA).

- **Таблица `cta_quest_checkpoints`** (`src/db/schema-checkpoints.ts` + `src/db/checkpoints-ddl.ts`): `id · user_id → profiles · game_id → games · **slot** smallint · name · payload jsonb (полный ProgressPayload) · created_at`. **slot: 0 = авто, 1..3 = ручные.** Уникальность `(user_id, game_id, slot)` → максимум 4 строки на юзера+игру; сохранение = **upsert по слоту** (перезапись). RLS: read own rows; пишет owner-роль через API.
- **Автослот (0)** = страховка-undo: пишется автоматически снимком текущего стейта **перед restore ручного слота и перед сбросом** (в момент клика — стейт до операции). Откат = restore слота 0.
- **API** `/api/eft/checkpoints` (GET все слоты без payload · **PUT** сохранить в слот `{slot,name,payload}`) + `/[slot]` (GET payload для restore · DELETE очистить). Юзер строго из сессии; slot валидируется 0..3.
- **Клиент** `cta-api.ts`: `listSlots / saveSlot / getSlot / clearSlot` (+ `AUTO_SLOT=0`).
- **UI** `QuestActionsDock`: дискета → панель: имя + 3 слота (пустой → «Сохранить»; заполненный → restore-по-клику · перезапись · очистить) + автослот (restore-only, пунктир). Restore = `loadProgress` в стор → `ProgressSync` заливает как живой стейт. Требует логина; аноним видит «войдите» + файловый бэкап (вторично в футере).

## Миграция

DDL-путём (не `db:push` — требует TTY, откатывает всё вне schema.ts): новый `checkpoints-ddl.ts` авто-подхвачен `db:migrate-all` (13 модулей, 183 стейтмента, 0 ошибок). RLS-аудит: 61 таблица с RLS, 0 без.

## Верификация

`tsc`=0 · миграция `db:migrate-all` (185 стейтментов, 0 ошибок), RLS-аудит 61/0 · сохранение из UI в слот 2 («После Каппы») → слот заполнился, имя из инпута подхватилось · **автослот-страховка доказана**: клик restore слота 1 → в БД появился `slot:0 "Автосохранение"` с timestamp момента клика · GET отдаёт `{slots:[…]}` со всеми слотами · консоль чистая, React Compiler ок. DELETE (корзина) и autosave-перед-сбросом — по коду (тот же `saveSlot(0)`, что доказан на restore).
