# Фиксы раздела «Карты» — эпик

**Статус:** ✅ закрыт (2026-07-01) — сделано 3 из 7 (#1, #3, #7). #2/#4/#5/#6 не реализованы → вынесены в самостоятельный бэклог (см. «Закрытие эпика»). Эпик как трекер закрыт.
**Затрагивает:** весь раздел Карты · родитель для дочерних решений ниже.

## Контекст
Накопились правки по разделу Карты: UI-неточности, недостающие маркеры/данные, фича переключения этажей, желание привести карты к единой дизайн-системе, и идея вытащить spawnpoint-данные из дампа tarkov.help. Разбор показал, что это **эпик**, а не одно A/B-решение — расщеплён на дочерние заметки.

## ✅ Ответы на вопросы из заметки (сверка с кодом)
- **Где SVG карт (для Figma)?** → `public/images/maps/eft/{slug}.svg` (фолбэк) + Supabase `cta-media/maps/eft/`. URL: `src/lib/map-image.ts`. Формат — векторный **SVG**, в Figma правится. ⚠️ Этажи переключаются по `<g id="Ground_Level">`/`<g id="Underground_Level">` — **имена слоёв-групп в Figma менять нельзя**, иначе Leaflet сломает переключение этажей.
- **Как назначается категория/позиция маркера?** → Маркеры **не ставятся руками**, синкаются 1:1 из tarkov.dev в таблицу `mapMarkers` (`src/db/schema.ts`). Категория = поле `type`, позиция = игровые `{x,y,z}` → CRS-трансформ (матрица+поворот) в `src/data/eft-map-config.ts`. Дев-тула для ручной правки нет (всё read-only).

## 🔑 Ключевая находка (переопределила скоуп)
БД **уже хранит 11 типов маркеров** (`extract, spawn, transit, hazard, loot_container, loot_loose, lock, switch, boss, stationary_weapon, quest_zone`), а вьюер v1 **рендерит только 4**. Лут/боссы/двери/переключатели **уже синкаются из tarkov.dev и лежат в базе** — их надо просто отрисовать. Дамп tarkov.help — это бандл приложения + иконки (14 «.js» идентичны, координат нет); его роль сжата до **набора иконок/таксономии для легенды**.

## Принятые решения (2026-06-28)
1. **Данные** — рендерим своё (tarkov.dev), дамп tarkov.help только как иконки. Координаты из дампа не тащим.
2. **Первая волна** — быстрые UI-фиксы.
3. **Дев-инструмент маркеров** — отложен в отдельный спринт (нужен бэкенд-слой оверрайдов).
4. **Формат** — дочерние decision-заметки, эта — родитель-индекс.
