# Таблица выпадения лута в контейнере

> [!success] Закрыто 2026-07-08 (ревизия 2026-07-14)
> Проверено в коде: роут `/eft/loot-containers` (+ `[slug]`), `src/data/loot/container-loot.json`, скрипт-нормализатор SPT.


## Цель
Создать для каждого контейнера отдельную страницу (по образцу ID-страницы предмета) с таблицей добычи — что можно найти в контейнере — и ценностью лута. Собрать эти страницы в раздел с иконкой `.icon-eft-loot-containers` и разместить в навигации. Дизайн — в стиле проекта.

## Контекст (по итогам разведки 2026-07-08)
- **Данных для таблицы лута НЕТ.** В проекте нет источника «что спавнится в контейнере»: ни `staticLoot`, ни GraphQL-запроса. Наша БД (`items` + `prices`) зеркалит tarkov.dev, а он статические loot-таблицы контейнеров не отдаёт. Страница `loot-rate` — это рейтинг ценности предметов, НЕ содержимое контейнера.
- **Ассеты есть:** webp loot-контейнеров (`/…/loot-containers/loot-container-*.webp`, `containerFile()` в `src/data/map-marker-icons.ts`), иконка `.icon-eft-loot-containers` (`src/styles/icons.css`).
- **Терминология (важно):** loot-контейнеры (Jacket/Safe/Duffle/сейф — мировые, обыскиваемые) ≠ gear-контейнеры (кейсы/секьюр/сторэдж — предметы под `/eft/items/gear/containers`, их «таблицы добычи» не существует).
- **Референс страницы:** ID-страница предмета — `src/app/eft/items/item/[slug]/page.tsx` (мимикрия под её структуру/стиль).
- **Категории:** `src/lib/item-category.ts` (`container` → `/eft/items/gear/containers`, иконка `icon-eft-eq-containers`), `src/lib/eft-category.ts` (GEAR_TYPES).

## Границы
- **В scope:** loot-контейнеры (мировые), раздел + страницы.
- **НЕ трогаем:** gear-контейнеры (secure/storage/cases) — у них нет loot-table; их раздел `/eft/items/gear/containers` уже есть и работает.

## Решения (2026-07-08)
1. **Тип — loot-контейнеры (мировые):** Jacket, Safe, Duffle, Weapon box, Medcase, PC block, Wooden crate и т.д. Путь — **свой, `/eft/loot-containers`** (НЕ `gear/containers`, там gear-предметы).
2. **Источник данных — SPT `staticLoot.json`** (первоисточник игровых loot-пулов). Факты (вероятности из файлов игры) не копирайтятся. **ОТКЛОНЕНО:** скрейп Тарков Хелп (прямой конкурент — ToS + копирайт его компиляции + `CLAUDE.md §4.9`) и вики 1:1 (§4.9, хрупко). Их роль — **только точечная сверка**, не пайплайн.

## Дата-пайплайн (SPT → наша БД)
- **Источник:** SPT server, `staticLoot.json` — распределение по контейнерам: контейнер (tpl) → распределение предметов (item tpl + относительная вероятность) + распределение количества. *(точные имена полей — сверить по актуальному файлу SPT; версия SPT = версия патча.)*
- **Маппинг:** SPT item tpl → наш `items` (по BSG id / normalizedName) → джойн с ценами (`prices`) для «ценности лута». Относительную вероятность → % / вес в таблице.
- **Хранение — 2 варианта (решить):** (A) статический ассет — нормализованный `container-loot.json` в репо, джойн с ценами при рендере → **db:sql НЕ нужен**, всё через GitHub API из песочницы; (B) таблица в БД (`loot_container_pools`) → db:sql ручной. Рекомендую **A** (проще, телефон-совместимо, обновляется скриптом).
- **Обновление:** при патче — перезалив из свежего SPT (крон/скрипт зеркала, как у остального).
- **✅ РАЗБЛОКИРОВАНО (2026-07-08):** данные тянутся напрямую из `github.com/sp-tarkov/server` (не LFS, `raw.githubusercontent.com` в вайтлисте песочницы). Файл **per-map**: `project/assets/database/locations/{map}/staticLoot.json`. Структура: `{ containerTpl: { itemcountDistribution, itemDistribution: [{tpl, relativeProbability}] } }`. id контейнеров и предметов = **BSG id = совпадают с нашей БД** (проверено: `578f8778…` = Jacket). Вероятность = relativeProbability / сумма пула.
- **Агрегация:** пулы per-map; один тип контейнера встречается на нескольких картах → объединяем в union по containerTpl (пулы контейнера по сути общие). Либо показывать per-map — на выбор.
- **Атрибуция:** источник SPT — вписать; данные = игровые факты (вероятности), не чужая компиляция.

## План реализации (2 фазы)
