# BATTLEPASS Трекер — трекер наград и документации Сезона 1 «KORD BREACH»

Исполняет **Ф4 эпика** [[seasons-battlepass-epic]] («трекер прогресса БП, дневной лимит документации»).
Данные-фундамент (8 документов в каталоге + бейдж BATTLEPASS-S1 + слой карты) уже лежат — это **чистый UI**
поверх статичного словаря, БД/схему не трогаем (§4.11: словарь как `eft-seasons.ts`, не рантайм-фетч).

## Что просили (V4DYA + бриф Дмитрия)
1. Новая страница **«BATTLEPASS Трекер»** в разделе Сезонов, кнопкой рядом с «Конструктор билдов» в карточке
   Первого сезона.
2. Источник данных наград — `docs/eft/Награды_Батлпасс_KORD_BREACH_для_трекера.md`: **12 страниц БП**, на
   каждой набор наград, у каждой награды — стоимость в **документации** (8 типов, валюта БП, лутается в рейде).
3. **Трекер:** игрок отмечает «награда получена» → её стоимость документов **вычитается** из общего остатка.
4. **Сводные таблицы:** (а) сколько всего/собрано/осталось документации по типам; (б) где какой документ
   лутается (документ × карты). Итоги внизу.
5. **Дневной лимит** добычи документов по режимам: PvP 20 · PvE 15 · Season PvP 30 (патч 14.08.2026).
6. Визуал наград — из файлов игры (иконки) / referenced escapefromtarkov.com/kordbreach.

## Решения (автономно, ночная autopilot-сессия)
1. **Маршрут `/eft/progress/seasons/tracker`** — зеркалит `…/perks` (та же структура: Server Component →
   клиент, back-link «Сезоны», без отдельного пункта в шапке). Кнопка на хабе — сиблинг «Конструктора».
2. **Данные — статичный словарь `src/data/eft-battlepass.ts`** (как `eft-seasons.ts`/`eft-season-items.ts`).
   НЕ mirror-таблица: это редакторский датасет одного сезона из MD-спеки + файлов клиента, не игровой рантайм-
   источник. §4.11 не нарушается; promote в Supabase — опция на будущее, если понадобится синк.
3. **Прогресс игрока — localStorage через Zustand `persist`** (прецеденты `useSeasonStore`, `useRoomOpensStore`).
   Ключ по slug сезона. Необратимых БД-операций нет (§5) — можно катать ночью без подтверждения.
4. **Логика вне разметки** (§4.7): все расчёты (итоги/остатки/матрица/ETA) — чистые функции `src/lib/battlepass.ts`.
5. **Иконки документов** — реальные из каталога через `itemIconUrl(id)` по `BP_SEASON_1_DOC_IDS` (8 id уже в
   `eft-season-items.ts`). **Иконки наград** — реальные там, где награда матчится на предмет каталога (пушки,
   броники, рюкзаки, нож, шлем, TarCoin — id зарезолвлены грепом по `items_database.json`); для косметики
   (позы/голоса/стили убежища/плакаты/жетоны-уровни) — глиф-категория (lucide) + `onError`-фолбэк, чтобы
   отсутствующая на R2 иконка не била битой картинкой.
6. **Две вкладки:** «Награды» (12 страниц, тоглы «Получено») и «Документы» (сводная таблица + лимиты + ETA).
   Верхняя полоса — общий прогресс (получено наград / всего) всегда видна.
7. **Разблокировки страниц — информативно, не жёстко** (как свободный выбор в конструкторе перков): показываем
   требование «получить N наград со стр. X», но тоглы не блокируем — трекер, а не симулятор гейтинга.

## Догон (2026-08-15) — 3 кнопки-режима + трекинг дневного лимита (грилл V4DYA, node Figma 2788-1529)

Статичный блок «Дневные лимиты» в рейле → **интерактивный `DailyModeBlock`** (в `BattlePassDocuments.tsx`). 9 решений грилла:

1. **Счётчик (Q1):** любой **+1 набора документа** (ячейка карточки ИЛИ рейл) при выбранном режиме → +1 к дневному. «−»/ПКМ дневной счётчик не уменьшают. Получение награды (`onToggleReward`) идёт мимо (свой `incDoc`). Хук — `onDocCollect` в Tracker: `incDoc` + `if (d>0) bumpDaily`.
2. **Режим (Q2):** radio-**снимаемый** (`setDailyMode`, повторный клик снимает). Включает трекинг + задаёт cap (Season 30 / PvP 20 / PvE 15). ETA `дн. до финала` теперь считается **только для выбранного** режима.
3. **Окно (Q3):** фиксированные **24ч от первого клика** (`windowStart`), один счётчик/окно, переживает смену режима (меняется только cap).
4. **Достижение (Q4):** `count>=cap && ackCap!==cap` → инлайн-баннер (паттерн `confirmReset`, без оверлея) «Продолжить? [Да][Нет]». **Да** → `continued=true`, красный «ИСЧЕРПАН» + обратный таймер `HH:MM:SS` до `windowStart+24ч`; набор **не блокируется**. **Нет** → в окне не переспрашиваем.
5. **Истечение (Q5):** прошло 24ч → `rolloverDaily` (count/окно/ответ в 0, режим остаётся). «Сбросить прогресс сезона» чистит и дневной слой целиком (режим тоже).
6. **Хранение (Q6):** дневной слой — **только localStorage** (`daily` в `useBattlePassStore`), в аккаунт **не** синкается (`BattlePassSync` трогает лишь `claimed`/`docCounts`).
7. **Смена cap (Q7):** всё derived от текущего cap — больший режим со счётчиком ниже гасит «исчерпан» и **перевзводит** предупреждение (`ackCap`+`continued` привязаны к значению cap).
8. **UI (Q8/Q9):** выбранная строка — акцент цветом режима (подложка 10% + акцент-полоса слева + иконка/число в цвете), подпись **«Я ИГРАЮ В …»** + «Сегодня N / cap»; невыбранные притушены `opacity-40`, кликабельны. Обращение на «ты».
9. **Иконки:** `pve-mode`/`pvp-mode` заведены в `icons.css` как маски (`icon-eft-pve-mode`/`icon-eft-pvp-mode`), Season переиспользует `icon-eft-seasons`; красятся динамически (выбран → цвет режима, иначе `text-secondary`).

Данные: `BpDailyMode`+`key`+`BP_LIMIT_BY_MODE` в `eft-battlepass.ts`; `BP_MODE_META` в `battlepassVisual.tsx` (заменил `BP_LIMIT_MODE_META`). Схему/API/БД не трогали. `tsc`/`eslint` чисто (тот же 1 pre-existing warning).

**Правка того же дня (V4DYA, ревизия Q1/Q2):** дневной счётчик считается **от любого взаимодействия** с трекером, **независимо от выбранного режима**:
- «Отметить получение» тоже засчитывает документы награды — но только **новые** (`max(0, need − have)`), уже набранные ячейкой/рейлом не задваиваются; на снятии дневной счётчик не уменьшается.
- Снята привязка `bumpDaily` к выбранному режиму (счёт всегда идёт, режим влияет только на cap предупреждения).
- На каждой кнопке-режиме число-монета показывает **`N/cap`** (`N/30`, `N/20`, `N/15`) — счётчик общий, cap свой; число краснеет при достижении cap. Строку «Сегодня N/cap» убрал (дублировала).

**Видимость запаса документов (V4DYA 2026-08-15):** справа накликанные документы = запас, которым слева закрываешь награды. Модель: `collected[t]` (docCounts) = **в наличии/не использовано**, `summary.spent[t]` = **использовано** на награды, `found = collected + spent`.
- Верхний чип «Найдено в рейде» получил подстроку «M использовано».
- В каждой строке рейла — разбивка `найдено N · исп. M · своб. K` (`своб.` = collected, подсвечен когда >0). Так видно, сколько неиспользованных документов доступно для наград.

**Замок наград по дневному таймеру (V4DYA 2026-08-15):** пока идёт таймер отката (режим выбран + `count>=cap` + нажато «Да» → `exhausted`), все доступные (неполученные, не заблок-прогрессией) награды получают **красный замок «Заблокировано»**. Снять — **7-сек удержание** карточки (переиспользован hold-to-unlock) → модалка **«Уже прошёл день?»** (danger-стиль, оверлей, клик по фону = отмена) → «Да, перезапустить» вызывает `rolloverDaily` (обнуляет счётчик/окно, замок снимается). Два типа замка в `RewardCard` разведены: `progLocked` (прогрессия → hold=`onCatchUp`) в приоритете, `dayLocked` (лимит → hold=модалка) для иначе-доступных. `dailyLocked` вычисляется в Tracker из стора и прокинут в `BattlePassRewards`. По истечении 24ч замок снимается сам (rollover от `DailyModeBlock`).
  - **Тонкость:** набор документов (ячейки/рейл `+`) при активном замке **не** блокируется (Q4 «трекер не симулятор») — замок только на *получении наград*. Если нужно глушить и добор — отдельная правка.
