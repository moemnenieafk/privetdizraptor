# Замок→Ключ: карточка ключа по клику на замок

## Цель
Клик по замку на карте показывает, какой ключ его открывает (+ контекст), со ссылкой на нашу страницу предмета.

## Границы
- **В scope:** клик по замку → read-only карточка-поповер (ключ, тип замка, ток, цена, «ещё N дверей»); подсветка соседних замков с тем же ключом.
- **НЕ трогаем:** синк/схему/БД (данные ключ→замок уже в зеркале), обратный поиск ключ→двери как отдельный режим (кликабельный счётчик — лёгкий намёк, не полноценный реверс), страницу предмета.

## Контекст (данные уже есть)
- `db/maps.ts` синкает замки с `linkedItemId`=id ключа, `label`=имя, `meta={lockType,needsPower,key:{id,name,normalizedName}}`.
- В клиент доходит всё КРОМЕ цены ключа → добавить `keyPrice` в маркер (`map-types.ts` + `page.tsx` из прайс-индекса).
- `itemIconUrl(id)` — иконка ключа; `formatCurrencyDisplay(n)` — цена; `/eft/items/item/{normalizedName}` — линк.
- Клик синканых в `MapViewerClient` (основной луп): override/delete-режим → оверрайд; иначе кросс-линк. Добавить ветку `type==='lock'` → карточка (ДО ветки itemSlug).
- Подсветка соседей — через существующий `flashPointsRef`.

## Критерий готовности
- [ ] `tsc`/eslint чисто, смоук зелёный
- [ ] Клик по замку (не в admin-режимах) открывает карточку с ключом + ссылкой на предмет
- [ ] Счётчик «ещё N дверей» пульсирует соседние замки

## Развилки (закрыты грилингом 2026-08-01)
1. Направление → **Замок→Ключ** (лок-центрично); реверс — потом
2. Клик → **карточка-поповер** у метки
3. Наполнение → иконка+имя ключа · «Открыть ключ» · тип замка · нужен ток · цена ключа · «открывает ещё N дверей»
4. Счётчик дверей → **кликабельный** (подсветка соседей через focusPoints/flash)
- Край: замок без ключа (`key=null`, рубильник/ток) → тип+ток+«открывается без ключа», без ссылки.

## Гарды
- Бюджет: 1 новый компонент (`LockKeyCard.tsx`) + правки `MapViewerClient`, `page.tsx`, `map-types.ts`. Бэкенд не трогаем.
- Ручное подтверждение: не требуется. §4.9 соблюдён (ссылка на нашу страницу).
