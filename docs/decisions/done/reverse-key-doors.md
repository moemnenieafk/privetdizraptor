# Реверс Ключ→Двери: «мои ключи» → подсветка дверей

## Цель
Игрок отмечает свои ключи → на карте постоянно подсвечены все двери, которые они открывают («какие ключи взять в рейд»). Плюс эфемерный клик по ключу → подлёт к его дверям.

## Границы
- **В scope:** секция «Ключи» в левом поиске (список ключей карты + поиск + чекбокс «есть»), стор «мои ключи» (localStorage), оверлей-подсветка дверей на карте.
- **НЕ трогаем:** бэкенд/схему/синк (данные ключ→двери уже на клиенте — lock-маркеры), карточку Замок→Ключ (остаётся; её счётчик «N дверей» — комплементарен).

## Контекст (данные готовы)
- Список ключей карты = из `data.markers` (type==='lock', `linkedItemId`=id ключа, `label`=имя, `itemSlug`=slug, `itemBg`=фон): группировка по keyId → {name, slug, icon, doors:позиции[], count}. Индекс `locksByKey` уже есть в MapViewerClient (перенести/продублировать в drawer из markers).
- Подсветка: эфемерная — `apiRef.focusPoints(points)` (уже есть в MapViewerApi); постоянная — новый оверлей-слой в MapViewerClient (кольцо на позиции замка), вне LOD/фильтра.
- «Мои ключи» — Zustand+persist, глобальный Set id ключей (ключи применимы к любой карте; на карте берём пересечение с её замками).
- Иконка-ячейка ключа — как в LockKeyCard (tint по itemBg + тень).

## Критерий готовности
- [ ] `tsc`/eslint чисто, смоук зелёный
- [ ] Отметил ключ в секции «Ключи» → его двери подсвечены на карте (даже при выключенном слое замков)
- [ ] Клик по строке ключа → подлёт/пульс к дверям; «мои ключи» переживают перезагрузку

## Развилки (закрыты грилингом 2026-08-01)
1. Вход → **секция «Ключи» в левом поиске**
2. Сохранение → **«Мои ключи» (localStorage)** + эфемерный клик
3. Подсветка → **постоянный оверлей** на дверях (всегда виден) + `focusPoints` по клику
- Мульти-ключ — бесплатно (Set → объединение дверей).

## Гарды
- Бюджет: 1 новый стор + правки MapSearchDrawer, MapViewerClient. Бэкенд не трогаем.
- Ручное подтверждение: не требуется (localStorage, без БД).
