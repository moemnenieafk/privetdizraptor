# «Где найти предмет» — секция спавнов на карточке + deep-link на карту с фильтром

## Цель
На карточке предмета, который добывается **в рейде** (loose-лут / контейнер), показать блок
**«Где можно найти предмет»** как на tarkov.help: список карт со счётчиками, список типов контейнеров
со счётчиками, категории лута — и кнопку **«Показать на карте»**, которая открывает нашу карту
(`/eft/maps/<slug>`) с **заранее включённым фильтром** нужной категории лута / типа контейнера.

Источник задачи — голосовая Димы (партнёр по ЦТА), рефы — два скрина tarkov.help (часы Roler,
рулон туалетной бумаги). Установка V4DYA (уточнена на гриле): **не копируем tarkov.help 1:1, а
улучшаем** — честные данные важнее совпадения с их цифрами. Кнопка на карту — предмет-первым +
тумблер категории (решение C).

## Границы
- **В scope:** новая секция на `ItemDetailLayout`; item-центричный ридер в `src/db/` над единой
  `markers` (sync+user) + реверс `container-loot.json`; расширение URL-контракта карты
  (`?item=`/`?loot=`/`?container=`) + гидрация фильтра на маунте.
- **НЕ трогаем:** схему БД (данные есть); механику рендера маркеров/heatmap; крон-синк ([[unified-markers]]
  уже защищает `source='user'`); **SPT loose-пулы `loot_spawns`** — в этой фиче не используем (спина =
  live-маркеры); airdrop/динамику.

## ⚠️ Критичная архитектурная развилка данных (до кода!)
У нас **ДВА независимых набора loose-лута** (см. [[loot-filter]] + [[spt-loot-tables-research]]):
1. **tarkov.dev-маркеры** — точки *конкретного* предмета (`linkedItemId`), уже рендерятся и уже
   фильтруются лут-фильтром по label. **Precise**, «вот тут лежит этот предмет». Покрытие = что есть
   у tarkov.dev (loose-набор неполный).
2. **SPT `loot_spawns`** — точки с *пулом кандидатов* и **относительными** весами; предмет — один из
   многих в пуле точки. Идут **только в heatmap денег**. Для «где именно этот предмет» — грубее.

**Из этого — риск №1 «накодить не то» (честность счётчиков):**
- Счётчик «Улицы 417» по **SPT-пулам** почти врёт: membership предмета в пуле точки ≠ реальный шанс
  встретить (вес относительный, может быть 1 из 10000). [[spt-loot-tables-research]] прямо это фиксирует.
- Контейнерный пул **per-type**: «Куртка 17» = *сколько курток на карте*, а не «в 17 куртках лежит
  предмет» — любая куртка «содержит» его с одним и тем же шансом типа. Это, похоже, и есть модель
  tarkov.help (счёт = число контейнеров этого типа), но надо подтвердить research'ем.
- ~~«Труп Дикого» — динамический~~ **ИСПРАВЛЕНО на гриле (V4DYA):** трупы (Дикий/ЧВК/гражд./лаборант) —
  **статические** контейнеры (`LOOT_CONTAINERS` kind='corpse'; синканные маркеры с позициями, `map-marker-icons.ts`).
  Динамичен только airdrop. Труп = обычный контейнер.

→ **Резолюция (грил 2026-08-13):** позиции/счётчики — из live-`markers`; SPT loose-пулы не используем;
контейнерное членство — из `container-loot.json`. Пул-membership за «шанс» не выдаём. Детали — «Решения» ниже.

## Решения (грил 2026-08-13, V4DYA)
Принцип на всю фичу: **улучшаем tarkov.help, не копируем; честные данные > совпадения с их числами.**

- **A — источник.** Спина = **live `json.tarkov.dev`** (§4.12), читаем из единой `markers` (`source='sync'`).
  SPT loose-пулы (`loot_spawns`) в фиче **НЕ используем** (membership≠шанс). SPT остаётся только под
  контейнерное членство — через готовый ассет `container-loot.json` (не через БД).
- **B — счётчик карт.** Число = честные live-точки предмета на карте. Подача: **карты «где выгоднее»
  сверху + относительный бар**, loose и контейнеры — раздельными блоками, плашка «≈ на патч». Не притворяемся точной цифрой.
- **C — кнопка «на карту».** **Предмет-первым:** основная кнопка подсвечивает этот предмет
  (`useLootFilterStore` по label). Рядом тумблер **«+ категория (Ценности)»** — расширить, когда точек
  мало. Чипы контейнеров/категорий в блоке → каждый ведёт на свой фильтр.
- **D — контейнеры.** Все **статические** = полный трит (членство `container-loot.json` + позиции/счёт/
  переход из `markers`). **Трупы — статические контейнеры** (`LOOT_CONTAINERS` kind='corpse'), НЕ динамика.
  Группировка блока по `kind`: **Контейнеры / Схроны / Трупы / Особые**. Исключение — только **airdrop**
  (kind='special', реально динамичен → в позиционный блок не идёт).
- **E — категория.** Реюз `classifyLoot15(coarse, bsgCategoryId)` (та же, что на карте) → одна из 15;
  категории карточки и карты совпадают.
- **F — гейт.** Блок показываем, только если предмет ∈ ≥1 loose-маркер **или** ∈ ≥1 контейнер-пул. Иначе секции нет.
- **G — deep-link.** `/eft/maps/<slug>?item=<inGameId>` (+ опц. `&loot=<cat>`, `&container=<slug>`).
  Кнопки **по каждой карте** (сценарий Димы) + переход на «лучшую» сверху. Расширить `useMapViewUrlSync`
  на гидрацию параметров на маунте. Гочи §4.6: `useSearchParams` клиентский → обернуть в `<Suspense>`
  (иначе прод-билд «Missing Suspense boundary», в dev маскируется); фильтр применять **после** загрузки
  маркеров (не на prerender); Leaflet только `next/dynamic ssr:false`.
- **H — ручные данные защищены (уже на проде).** Ридер читает единую `markers` (sync+user) → вручную
  добавленные точки (`source='user'`, Wizard/CMS) **автоматически** в блоке/счётчиках/на карте и
  **переживают синк** (крон prune только `WHERE source='sync'`, [[unified-markers]]). Правка синканного =
  user-override, база под кроном остаётся свежей. **Доделывать защиту не нужно.**

## Что реюзаем vs новое (принцип «не городить лишнее»)
**Реюз:** единая `markers` (позиции loose+контейнеров, source-защита) · `container-loot.json` +
`LOOT_CONTAINERS` (членство, kind-таксономия, иконки) · `classifyLoot15` (категория) · `useLootFilterStore`
(подсветка) + `useMapViewStore.setGroupFilters` (слой категории) · `getItemCategory`/`map-layers.ts`.
**Новое (минимум):** item-центричный ридер `src/db/` (реверс `markers` + `container-loot.json`) · компонент
секции на `ItemDetailLayout` · гидрация `?item/?loot/?container` в `useMapViewUrlSync` · один общий
серверный счётчик контейнер-маркеров (сумма по картам), если ещё не вынесен.

## План реализации (для /execute-decision)
1. **Ф1 — ридер.** `src/db/` item→locations: реверс `markers` по предмету (loose-точки + позиции
   контейнеров) + реверс `container-loot.json` (в каких типах бывает). Группировка по карте и по `kind`.
2. **Ф2 — секция UI.** Компонент на `ItemDetailLayout` (гейт F): карты ранжированы + бар (B), блоки
   контейнеров по kind (D), таб/чипы категорий (E), кнопки на карту (C/G). NIGHTFALL, скелетон.
3. **Ф3 — deep-link.** Расширить `useMapViewUrlSync` (гидрация, `<Suspense>`, применять после маркеров),
   кнопки/чипы генерят URL. Live-verify: фильтр включён на первом рендере.
4. **Вне ядра:** ручные точки уже текут через `markers(user)` (H) — доп. работы нет. Полиш бара/плашек (V4DYA).
