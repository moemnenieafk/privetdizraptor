## Варианты (главная развилка — `HubNav` зашит на items: `useItemsStore` + фильтр торговцев)
- **A — Обобщить `HubNav`:** вынести traders-фильтр + `useItemsStore` в опциональные пропы/слот; один компонент на items и quests.
- **B — Отдельный `QuestsHubNav`:** dumb-навигация под quests (левый блок + ряд табов-ссылок из словаря), items не трогаем.

## За / Против
| Вариант | За | Против |

| **A** | DRY, единый источник навигации, переиспользуемо дальше | трогаем рабочий items → риск регресса; тащим store/фильтр в общий код |
| **B** ✅ | items не трогаем (0 риска на рабочем разделе); простой презентационный компонент; быстро | небольшой дубль левого блока+табов с `HubNav` (без traders/store) |

### Доработка 3 (2026-07-01) — быстрый фильтр-индикатор в шапке торговца
Идея V4DYA: счётчики статусов = кликабельный фильтр (счётчик + переключатель в одном).

Каждая = счётчик + фильтр списка; активная залита цветом статуса (`--primary` / `success` / `neutral`), клик по активной снимает (→ все). Состояние `onlyAvailable` → `filter: 'all' | active | completed | locked`. Бейдж `total` у имени.
- **+ Каппа / Смотритель** (по аналогии с QuestMap): два toggle по полям `kappaRequired` / `lightkeeperRequired`, логика `(kappa && kappaReq) || (lk && lkReq)`, комбинируется со статус-фильтром (И). Иконки/токены 1:1 из `QuestStatusBar` (`icon-eft-profile-kappa`/`-lightkeeper`, `--color-kappa`/`--color-lightkeeper`).
