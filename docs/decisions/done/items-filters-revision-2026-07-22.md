## Найденные проблемы (ревизия)

1. **Мёртвый табличный вид (крупный тех-долг).** `viewMode` захардкожен `'grid'` (клиент, стр. 1015), но `useCategoryFilters` до сих пор читает/пишет `view` в URL + localStorage + `SavedFilters`; `CategoryTableRow` (~400 строк, switch по всем категориям), `handleColumnSort` и колоночные ветки сортировки — мёртвый код (~30% файла).
2. **Скрытые сохранённые фильтры → «почему пусто».** Дискета персистит `caliberFilter` и `activeArmorClasses` глобально; на чужой категории фильтрация применяется, а панель Advanced фильтр не показывает (`showCaliber=false`) → пустой список без видимой причины.
3. **Асимметрия `favoritesOnly`.** Есть в URL (`fav`) и в `resetFilters`, но НЕ в `SavedFilters` / `handleSaveFilters` / restore. Единственный фильтр, который дискета не сохраняет, хотя тост обещает «по умолчанию».
4. **«Невидимые» фильтры трейдеров и подтипа очков.** `selectedTraders` и `activeEyewearSubtype` режут список, но не входят в бейдж `activeAdvancedCount` и не сбрасываются кнопкой «Сбросить фильтры» (они в другом сторе / локальном стейте) → кнопка сброса не помогает.
5. **Класс брони — нет «снять/выбрать всё».** Сняв все 6 тумблеров, юзер прячет всю броню; вернуть можно только по одной иконке. Нет мастер-тумблера.
6. **Мелочи.** «Цена от/до, ₽» неоднозначно (это цена ПОКУПКИ `minPrice`) · `isFlVendor` пересоздаётся в `.filter` на каждой итерации.

**tarkov.dev** — «таблица на категорию + глобальные настройки». Категорийные страницы скупые (у оружия только колонки цен, без калибр/эрго/отдача). Чипы трейдеров (Любой…Реф). Чипы-теги (Избр., Ключи, Бартер, Кейсы, Прицелы, Глушаки…). Слайдер «Ур. барахолки 1–40». Колонки-тренды (Ср. цена 24ч/слот, Изм. 24ч, Изм. 7д) + профит-флип (часть за Pro). Тумблер PVP/PVE, валюта.

## Deep research 2: чего хотят игроки (фидбек из соцсетей и трекеров issue)

Reddit заблокирован для нашего веб-краулера → снято через браузер (old.reddit). GitHub issues `the-hideout/tarkov-dev` (16 открытых / 129 закрытых) = буквальные запросы игроков.

### Jobs To Be Done — зачем игрок вообще открывает агрегатор
Из гайдов для новичков (сотни upvotes) видно повторяющийся набор задач — по ним игроки описывают, ЗАЧЕМ идут на tarkov-market / tarkov.dev:
1. **«Стоит ли подбирать / держать этот предмет?»** — быстрый value-чек в рейде (цена, цена/слот). *«check for prices of items in raid — is this worth picking up?»*
2. **«Нужен ли он мне для квеста / убежища / бартера, и нужен ли FiR?»** — **самый частый юзкейс**, всплывает в каждом гайде. *«check whether or not you need an item for a specific quest or barter… if it needs to be found in raid»*, «Quest item chart to remember what to keep».
3. **«Какой патрон лучший под бюджет/ситуацию?»** — best-in-slot по пробитию/урону vs цена (ammo chart — обязательный инструмент в каждом гайде).
4. **«Какие моды подходят к моему стволу?»** — фильтр совместимости. Топ-саджест `«Add a "Compatible With" filter»` (65 upvotes, 15 комм.).
5. **«Выгоден ли крафт/бартер?»** — маржа/лучший margin для хайдаута.
6. **«Реально ли это купить/продать на барахолке?»** — ликвидность: GitHub #1050 «"Availability" metric for flea prices», #826 «Trade High, Low, Volume».

### needMe → расширен на убежище ✅ (2026-07-22)
Фильтр «Нужно мне» раньше = только незавершённые квесты. Теперь = квесты ИЛИ непостроенные модули убежища. Одна кнопка, шире данные, без нового UI.
- **Серверно:** `getHideoutRequirementMap()` (`db/hideout.ts`) — лёгкий `itemId → [{station, level, fir?}]` из зеркала `hideout_upgrades` (без join'ов имён/цен, валюта исключена). Прокинут в обе `page.tsx` (`[...category]` + корень), сужен `pickByIds`.
- **Клиент:** сверка с `useHideoutStore.levels` (ключ = `stationNormalizedName`): предмет «нужен», если любой требующий его уровень станции ещё НЕ построен (`level > levels[station]`). Данные пусты (синк не гонялся) → hideout-ветка молча false, остаются квесты.

- Тултип кнопки обновлён. `tsc`/`eslint` чисто.
