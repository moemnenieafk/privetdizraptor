# Vercel: пропуск билда для docs-only пушей

**Статус:** ✅ сделано — `ignoreCommand` в `vercel.json` (коммит `f1ee8ef`).
**Затрагивает:** `vercel.json`
**Процесс:** первый прогон через [[engineering-loop]].

## Контекст
После Фазы 2 ([[db-egress-reduction]], пререндер 76 категорий) каждый пуш в `main` гонит тяжёлый ребилд — билд-минуты + билд-egress из Supabase (`loadEnriched`/индикаторы читаются на билде). Но мы часто пушим **docs-only** (заметки-решения, валт) — таким пушам ребилд не нужен.

## Решение (v1 — имел яму, см. v2 ниже)
`vercel.json` → `"ignoreCommand": "git diff --quiet HEAD^ HEAD -- ':(exclude)docs/'"`.
Семантика Vercel: **exit 0 = skip**, **≠0 = build**.
- только `docs/` → diff пуст → `0` → skip
- есть код → diff непуст → `1` → build
- ошибка git (нет `HEAD^`) → `128` → build (**fail-safe**: лишний билд, не пропущенный нужный)

## Проверка (детерминированно, локально)
Команда прогнана на реальных коммитах:

| коммит | что | exit | вердикт |
|---|---|---|---|
| 117fa1b, 9f8c21a | docs | 0 | SKIP ✅ |
| f1ee8ef, 951c4fe, 697b711 | code | 1 | BUILD ✅ |

Прод `200` (vercel.json валиден). `buildId` в HTML App Router не отдаётся → внешняя прод-проба невозможна; логику покрывает локальный тест (это и есть детерминированный verifier).

## Кавеат (v1) → СРАБОТАЛ вживую, закрыт в v2
`HEAD^..HEAD` видит только **последний** коммит. Если в пуше несколько коммитов и последний docs-only, а ранний — code, билд пропустится ошибочно. ⚠️ Ровно это и случилось **2026-07-01**: fast-forward мерж `feat/maps-frame-sprint`→`main`, вершина = docs-коммит `bb171a0`, код стрима (`4cb80ca`) — ниже → SKIP → прод не собрался. Исправлено в v2 ↓.

## Подтверждение на проде
Этот пуш (заметка = docs-only) — живой тест: в Vercel → Deployments он должен быть **Skipped** (нового билда нет).

## v2 — устойчивый фикс (2026-07-01)
Яма из «Кавеата» сработала вживую (см. выше). Причина: `HEAD^..HEAD` смотрит только **вершину** пуша; при fast-forward мерже вершиной оказался docs-коммит, и весь код под ним стал невидим → SKIP.

**Фикс — смотреть весь диапазон от последнего задеплоенного коммита, а не одну вершину:**
```
"ignoreCommand": "[ -n \"$VERCEL_GIT_PREVIOUS_SHA\" ] && git diff --quiet \"$VERCEL_GIT_PREVIOUS_SHA\" HEAD -- ':(exclude)docs/'"
```
`$VERCEL_GIT_PREVIOUS_SHA` = SHA последнего успешного деплоя (даёт Vercel). Диапазон `PREV..HEAD` покрывает ВСЕ коммиты пуша — порядок и вершина больше не важны.

Семантика (exit 0=skip, ≠0=build):
- с последнего деплоя только `docs/` → пусто → `0` → **SKIP** (эконом сохранён)
- в диапазоне есть код → `≠0` → **BUILD** (яма закрыта — вершина-docs больше не обманывает)
- `$VERCEL_GIT_PREVIOUS_SHA` пуст (первый деплой) → `[ -n "" ]` ложь → **BUILD** (fail-safe)
- SHA вне shallow-clone → git error → **BUILD** (fail-safe: лишний билд, не пропущенный)

Проверено локально на реальных SHA:
| диапазон | что | exit | вердикт |
|---|---|---|---|
| `HEAD^..bb171a0` (v1) | вершина docs, код ниже | 0 | SKIP ❌ яма |
| `a17bd58..bb171a0` (v2) | релиз спринта | 1 | BUILD ✅ |
| `bb171a0^..bb171a0` (v2) | docs-only | 0 | SKIP ✅ |

Коммит этого фикса правит `vercel.json` (= не `docs/`) → сам триггерит прод-билд и доставляет застрявший спринт. Привычка «пушить docs отдельно от code» больше НЕ обязательна, но безвредна.
