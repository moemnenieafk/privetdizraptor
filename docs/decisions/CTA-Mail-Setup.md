# Почта на домене `cta.quest`

Инфраструктурная задача: поднять корпоративную почту на своём домене,
настроить доставляемость (SPF/DKIM/DMARC), развести публичные ящики
и транзакционную рассылку портала по разным доменам.

> [!important] Порядок жёсткий
> DNS → проверка доставляемости → ящики → регистрация соцсетей.
> Регистрировать площадки до появления рабочего `info@` — переделывать.

---

## 0. Исходные данные

| Параметр | Значение |
|---|---|
| Домен | `cta.quest` |
| Регистратор | *заполнить* |
| Хостинг сайта | VDS Timeweb |
| Где живут NS | *заполнить: Timeweb / регистратор* |
| Почтовый провайдер | Timeweb «Почта для домена» |
| Транзакционка | Resend (или Unisender) на поддомене |

---

## 1. Выбор провайдера — решение

Бесплатных вариантов почты на своём домене в РФ не осталось:

- **Яндекс 360** — бесплатный тариф закрыт в 2023, с 01.07.2026 базовый ~485 ₽/чел./мес.
  С 29.06.2026 IMAP/POP3/SMTP без подписки отключены.
- **VK WorkSpace** (бывш. Mail.ru для бизнеса) — от ~199 ₽/чел./мес.
- **Timeweb** — почта идёт услугой рядом с доменом/хостингом, дешевле, панель уже своя. ✅

> [!warning] Self-hosted mailcow на этом же VDS — не вариант
> IP облачных провайдеров часто уже в блок-листах. Уйдёт несколько недель
> на войну за доставляемость вместо работы над порталом.
> Возвращаться к этому — только если появится отдельный IP с чистой историей.

## 2. DNS

Все записи правятся там, куда делегированы NS. Если домен взят не в Timeweb —
проще переделегировать на их NS, чтобы DNS и почта были в одной панели.

### 2.1 Записи

| Тип | Хост | Значение | Прио | Статус |
|---|---|---|---|---|
| MX | `@` | почтовый хост Timeweb | 10 | [ ] |
| TXT | `@` | `v=spf1 include:<хост> ~all` | — | [ ] |
| TXT | `<селектор>._domainkey` | публичный ключ DKIM из панели | — | [ ] |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@cta.quest` | — | [ ] |

### 2.2 Правила, на которых чаще всего спотыкаются

- [ ] **SPF-запись ровно одна.** Две TXT со `v=spf1` = обе невалидны.
      Все отправители сводятся в один `include:`-список.
- [ ] `~all` (softfail), не `-all` — пока не убедимся, что все отправители учтены.
- [ ] DKIM-ключ копировать целиком, без переносов строк.
- [ ] DMARC стартует с `p=none` — это режим наблюдения, письма не режутся.
      Ужесточать до `p=quarantine` через 2–3 недели по отчётам `rua`.
- [ ] TTL на время настройки поставить 300, потом вернуть в норму.

## 3. Ящики

| Адрес | Назначение | Публичный |
|---|---|---|
| `info@cta.quest` | основной, указывается во всех профилях площадок | да |
| `support@cta.quest` | фидбек и баг-репорты с портала | да |
| `dmca@cta.quest` | претензии по контенту (BSG, правообладатели) | да |
| `dmarc@cta.quest` | приём агрегированных DMARC-отчётов | нет |
| `postmaster@` → алиас на `info@` | ждут почтовые провайдеры | — |
| `abuse@` → алиас на `info@` | ждут хостеры и регистраторы | — |

> [!note] `noreply@cta.quest` пока не создаём
> Транзакционка уезжает на поддомен, см. §5.

- [ ] Создать ящики
- [ ] Настроить алиасы `postmaster@`, `abuse@`
- [ ] Подключить `info@` и `support@` по IMAP в почтовый клиент
- [ ] Автоответ/подпись для `info@` — единый шаблон

---

## 4. Проверка доставляемости

- [ ] `mail-tester.com` — цель **10/10**, разобрать каждое замечание
- [ ] Тестовое письмо на **Gmail**, **Яндекс**, **Mail.ru**, **Outlook** — проверить папку «Спам»
- [ ] В полученном письме глазами проверить заголовки: `spf=pass`, `dkim=pass`, `dmarc=pass`
- [ ] Проверить домен по блок-листам (`mxtoolbox.com` → Blacklist Check)
- [ ] Через 2 недели — посмотреть DMARC-отчёты, поднять политику до `quarantine`

---

## 5. Транзакционная почта портала — отдельный домен

Письма Supabase (регистрация, сброс пароля, уведомления) шлются **не** с `cta.quest`,
а с поддомена. Если рассылка словит жалобы — репутация основного домена не пострадает.

- **Поддомен:** `send.cta.quest`
- **Провайдер:** Resend (либо Unisender / SMTP.bz)
- **From:** `noreply@send.cta.quest`, `Reply-To: support@cta.quest`

- [ ] Завести домен в панели провайдера
- [ ] Прописать выданные SPF/DKIM/return-path записи **на поддомене**
- [ ] Отдельный DMARC на `_dmarc.send`
- [ ] Прописать SMTP-креды в Supabase Auth → Custom SMTP
- [ ] Проверить сценарии: регистрация, сброс пароля, письмо-уведомление
- [ ] Ключи API — в переменные окружения, не в репозиторий

## 6. Доступы и гигиена

- [ ] Отдельная SIM под проект (не личная, не [[fullkamen|Димина]]) — нужна для TG, инсты, VK, Twitch
- [ ] Общий сейф паролей (Bitwarden / 1Password), доступ равный у обоих
- [ ] 2FA только через TOTP-приложение, **не SMS**
- [ ] Коды восстановления — в сейф, сразу при включении 2FA
- [ ] Записать, на какой ящик и номер зарегистрирована каждая площадка

## 7. Что дальше — регистрация площадок

Только после рабочего `info@`. Подробности — отдельной заметкой.

**Ники.** Точка в нике проходит только в Instagram, TikTok, YouTube.
В Telegram, VK, Twitch, X — только буквы/цифры/подчёркивание.

- Канон: `ctaquest`
- Запасной: `cta_quest`
- Полный: `cta.quest` — где разрешено

**Порядок захвата:** Instagram → Threads (создаётся из инсты, наследует ник) →
Telegram-канал → YouTube → Twitch → X → TikTok → VK-сообщество → Discord → Reddit → Boosty.

> [!tip] Discord важнее инсты
> Для хардкорного экстракшн-шутера комьюнити живёт в Discord.
> Сервер стоит поднимать в первой пятёрке, а не в конце списка.
