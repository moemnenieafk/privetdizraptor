# РЕШЕНИЯ GRILL (2026-07-28)

## Эпик E11 — архитектура
1. **Источник маркеров — сосуществуют.** tarkov.dev-синк = авто-слой (LOD/иерархия, крон §10); `map_markers` (CMS) = editorial-слой (карточка/комменты/скрины/UGC). Рендер вместе через юнион `auto | editorial | user`. Ручного переавторинга 500+ точек нет.
2. **UGC отложен до домена** (как SMTP). Фазы 2-4 (загрузка скринов, личные маркеры) ждут домена под `ugc.cta.*` (§15.3). Near-term — **только Фаза 1**: editorial-маркеры + карточка + официальные скрины + комментарии текстом.
3. **Порядок:** каркас (зон-скелет) → P0-контент §12 → Фаза 1.
4. **Рендер §10:** LOD + виртуализация по viewport на текущем Leaflet-DOM. Canvas/WebGL — только если замеры покажут нехватку.
5. **Сторы §18:** `useMapViewStore` (эфемерный вид + двусторонний URL-синк → permalink) — **уже в каркасе**. Каноничные — RSC без стора. `useUserMarkersStore` — с UGC (отложен).
6. **Топонимы §4/§7:** редакционные editorial-маркеры `kind='landmark'` под NIGHTFALL, слой-тумблер. Не из tarkov.dev.
7. **Клик по авто-маркеру:** лёгкий actionable-поповер (лут→ссылка на предмет, выход→название+условия), не тупиковый тултип (§2). Полная правая карточка §19 — только editorial. Два уровня глубины.
8. **Пресеты §5/§13:** 5 штатных **бесплатны всем**; лимит «3» — на **пользовательские** пресеты (сверх — Оперативник+). Данные не запираем (§11).

# РЕШЕНИЯ GRILL-2 — ФИНАЛЬНЫЙ UI ИЗ FIGMA (2026-07-28)

## Финальная модель экрана
- **Верхний бар:** `поиск` (лево, открывает левый drawer) · `линейка` · **выпадашка карт** (иконка+имя+игроки+время+▼, заменяет `MapNavStrip`) · `фуллскрин` · `слои` (право, открывает правый drawer). **Кнопки «Позиция» в баре НЕТ.**
- **Выпадашка карт** — вертикальный список, **data-driven** (только карты, что у нас реально есть; вишлист Figma типа Терминал/Лабиринт/Конец пути не показываем до данных/страницы). Дубль с хедерным «КАРТЫ ▾» допустим (глобальная навигация vs контекстный свитч; ROW 2 на картах и так скрыт).
- **Левый drawer «ПОИСК НА ЛОКАЦИИ»** — **тоггл `Предметы | Задания`** (компонент `quest-toggle-btns`), каждый режим на всю высоту:
  - *Предметы:* инпут мульти-поиска → сетка КОНТЕЙНЕРЫ (типы на этой карте) → сетка СЛУЧАЙНАЯ ДОБЫЧА (категории). Клик по результату/тайлу = **подсветка/подлёт на карте**, страница предмета — вторичным шевроном (§4.9 соблюдён, карту не бросаем). Loose-лут = точки (`itemSlug`); контейнеры = эвристика по типу.
  - *Задания:* инпут → чипы `ВСЕ / СЮЖЕТ / Каппа% / Смотритель%` (семантика из QuestMap; голым «%» не оставлять — подписи/тултипы) → **лента торговцев** (только те, у кого квесты НА этой карте) → список квестов.
- **Третий drawer «Подробности задания»** — клик по квесту открывает его **рядом** с поиском (master-detail: список жив, деталь обновляется). **Переиспользуем компонент из QuestMap.** Пины задач → подлёт на карте; «Отметить выполненным» → существующий стор прогресса. Мобилка — bottom sheet.
- **Правый drawer «ЛЕГЕНДА КАРТЫ»** — слои + легенда + счётчики СЛИТЫ (**поглощает старый каркас #4 «оверлей-легенда»**): текст-фильтр «по маркерам» + дерево групп с чекбоксами, **иконками-маркерами (= легенда)** и счётчиками. Группы: ВЫХОДЫ / СПАВНЫ / ИНТЕРАКТИВ / ДОБЫЧА / ЗАДАНИЯ / ОПАСНОСТИ.
- **Оверлеи карты:** этажи — **компактный степпер С ИМЕНЕМ** низ-лево (`-1 ▲▼ ПОДВАЛЫ`; заменяет «левый вертикальный список» из §8 — претензия §8 снята, имя есть); боссы — **низ-центр** (аватары + спавн%); **трекер + координаты — низ-право** (locate = вкл/следовать, X/Y = позиция игрока при трекинге).

## Правила поведения (форки grill)
1. **Раскладка — оверлей/float:** карта край-в-край, drawer'ы всплывают поверх с blur (НЕ двигают карту).
2. **Перекрытие:** угловой контрол, накрытый drawer'ом, **прячется** пока drawer открыт. Смену этажа страхует клавиатура (Alt+Scroll / ↑↓ — уже в коде).
3. **Единое состояние фильтра:** левая сетка (Предметы) и правая легенда пишут ОДИН `activeFilters` (`useMapViewStore`). Левая = визуальный быстрофильтр по карте; правая = полное дерево+счётчики. Синхрон автоматом.
4. **Левый + правый — независимые тогглы.** На <1440 открытие противоположной авто-закрывает первую; мобилка — всё bottom sheets.
5. **Данные (§4.11):** весь поиск/фильтр — из зеркала Supabase, никакого runtime tarkov.dev. Типы контейнеров и категории лута — из зеркалимых маркеров `loot_container`/`loot_loose`. Богаче («в какой куртке предмет») — отдельный mirror-датасет = отдельная задача.

## P0 §12 — иерархия маркеров: срез 1 «LOD по зуму» ✅ (2026-07-29)
§12 разложен на 5 под-кусков; сделан первый — зум-зависимый рендер слоёв.
- **`map-layers.ts`:** `lodTierForKey` (тир по ключу слоя) + `lodVisibleAt(key, frac)`. Тиры по §4 с поправкой GRILL-1 (спавны = z4): выходы/переходы = 0 · quest_zone/hazard/**босс** = 1 · спавны/замки/рычаги/стационарки = 2 · контейнеры/loose = 3. Порог = **доля зум-спана карты** (`{0:0, 1:.34, 2:.56, 3:.78}`), т.к. абсолютные z-уровни непереносимы (диапазоны −5…2 против 2…6).
- **`MapViewerClient`:** `applyLayerVis()` — слой на карте ⟺ `фильтр × зум-тир`; одна точка правды, дёргается на `zoomend` / смене фильтра / после `invalidateSize`. LOD перебивает ручной тумблер (включённый слой ждёт своего бэнда). Убран ставший мёртвым `rebuildLooseRef` (§10).

## P0 §12 — иерархия маркеров: срез 2 «соседние этажи» ✅ (2026-07-29)
- **`applyFloor`:** чужой этаж не `display:none`, а класс `cta-mk-offfloor` → 20% opacity + `pointer-events:none` (пространственный контекст сохраняется, §8). `applyLayerVis` в конце переприменяет затемнение — LOD/фильтр при re-add пересоздают DOM маркеров, класс иначе слетал бы.
- **`globals.css`:** `.cta-mk-offfloor` рядом с `is-dimmed`; `soloFloors` (Ледокол) прячет чужие маркеры совсем, как и подложку.
- Композиция: маркер виден ⟺ `фильтр` × `зум-тир` × `активный этаж (иначе призрак 20%)`.

**Осталось по §12** (2 под-куска): #2 размер по тиру — уже в резолвере (`size` на тип + `--marker-scale`), не трогаем · **#3** фоновые точки плоскими без обводки/тени — *спорно: конфликтует с крупным webp-артом контейнеров (56px), обсудить* · **#5** топонимы (`landmark`) — нужен источник (`labels.json` из пака / editorial). ## 1. Конкуренты: что у кого есть

### eft.su
Плотная левая панель-счётчик по категориям (`Квесты 45`, `Куртка 16`, `Деревянный ящик 44`). Справа — свёрнутые аккордеоны «Уровни», «Отряд», «Слои», «Квесты (23)». Переключение этажей через `Alt + Scroll`. Уникальное: **линейка**, **«Где я?»**, **совместная сессия отряда**, тумблер «Спутник / Схема», «Спрятать панели», полноэкранный режим.
Слабость: интерфейс перегружен, две панели одновременно съедают ~35% ширины, эстетика нулевая.

### Tarkov.Help
Правая панель, сгруппированная по смыслу: Контейнеры / Лут / Враги / Выходы. **Счётчик прямо в чипе** (`17 x Куртка`), «Выбрать все / Очистить все» на каждую группу, отдельная крупная кнопка «79 x Квест». Есть премиум-подписка, мобильное приложение, RU-аудитория (проект стримера Dunduk), ежедневное обновление данных.
Слабость: карта — серое аэрофото с пиксельными иконками, всё вываливается на экран разом, читаемость на Улицах нулевая. На мобиле нечитаемо вообще.

### tarkov.dev
Открытый код, тёмная тайловая карта, **подписи топонимов** (Main Working Area, Warehouse, Barracks, Server Room). Панель информации о рейде (длительность, число игроков). Слои этажей, поиск. Уникальное: **live-позиция игрока** через связку с TarkovMonitor + удалённое управление картой по ID (телефон как второй экран).
Слабость: маркеры одинаковые и мелкие, нет группировки фильтров, нет персонализации.

### MapGenie
Quicksearch по названию точки с моментальным зумом, **progress tracker** (отметить точку как найденную), **заметки на карте**, пресеты фильтров, хитмапы, quest tool с деревом зависимостей, гайды, синк веб ↔ мобильное приложение. Pro-подписка $4.99/год.
Слабость и урок для нас: часть карт и фич заперта за Pro — из-за чего существует популярное расширение free-map-genie, которое эти фичи разблокирует. **Вывод: запирать данные нельзя, запирать можно только персональные инструменты.**

### TarkovQuestie
Десктоп-приложение (€3.75/мес): live-позиция по чтению скриншотов игры, авто-синк квестов из логов, позиции отряда, идентификация предметов по Shift+Click, кастомные маркеры, «какие ключи взять в рейд».
Не наш путь: требует десктоп-агента, чтения логов и серой зоны с ToS BSG.

## 2. Диагноз по текущей карте ЦТА

У нас лучшая графика из всех — стилизованный вектор в NIGHTFALL читается на порядок приятнее серого аэрофото Tarkov.Help и тёмного тайла tarkov.dev. Но карта **не работает как инструмент**:

1. **Нет визуальной иерархии.** Все маркеры одного размера, с обводкой и тенью, в 7+ оттенках (красный, оранжевый, жёлтый, зелёный, розовый, бежевый, серый). Глаз не отделяет «куда бежать» от «где лежит куртка». Улицы превращаются в сыпь.
2. **Нет топонимов.** Ни одного названия района на карте. А карта нужна в том числе чтобы сказать в отряде «я на Чекпоинте».
3. **Нет управления информацией.** Фильтры спрятаны за кнопкой «СЛОИ», нет счётчиков, нет легенды, нет поиска. Tarkov.Help выигрывает не красотой, а тем, что видно «17 x Куртка» и это выключается одним кликом.
4. **Мелочи:** степпер этажей `^ 1 v` слишком тихий для локаций с 4 уровнями; `0/29` и два аватара с `75%` внизу слева не читаются как что-либо осмысленное; тултип «ЗАКОПАННАЯ БОЧКА» — тупик, из него никуда нельзя перейти.

## 4. Иерархия маркеров — фикс №1

Три тира, различаются **формой и размером**, не только цветом:

| Тир | Что | Форма | Размер | Видимость |
|---|---|---|---|---|
| Якоря | Выходы, переходы, спавны, топонимы районов | Щит / стрелка + текстовая подпись | 32px | Всегда, на любом зуме |
| Цели | Задания, ключи, боссы, опасные зоны | Ромб | 28px | По фильтру, с zoom ≥ 2 |
| Фон | Контейнеры, лут, трупы, куртки | Круг-точка | 16px | Только с zoom ≥ 4 |

**Палитра маркеров — схлопнуть с 7 оттенков до пяти семантических:**

| Цвет | Значение |
|---|---|
| Амбер `--primary` | Цель, задание |
| Красный | Опасность: боссы, снайперы, мины, зоны обстрела |
| Зелёный | Выход, переход |
| Стальной серо-синий | Лут, контейнеры |
| Циан | Ключи |

Остальное — монохром. Обводка и тень остаются **только** у тиров 1 и 2; фоновые точки плоские, без stroke. Форма важнее цвета: карта читается и при дальтонизме, и на мелком зуме, и на мобиле.

**Zoom-dependent rendering (LOD) — обязательно.** Без него Улицы нечитаемы физически:

| Зум | Что показываем |
|---|---|
| z1–z2 | Топонимы районов, выходы, границы зон |
| z3 | + задания, боссы, опасные зоны |
| z4 | + ключи, спавны |
| z5+ | + контейнеры, лут, мелочь |

Этого нет ни у кого из конкурентов — у всех всё вываливается сразу.

## 7. Утилиты, которых нет вообще

По приоритету:

1. **Поиск по карте** — fuzzy по названиям точек, заданиям, ключам, топонимам, с зумом и подсветкой результата. Самая частая операция на любой игровой карте, у нас только пустая лупа в углу.
2. **Permalink** — `?z=4&x=..&y=..&floor=2&filters=quests,keys`. Без него нельзя сослаться на точку из статьи Кодекса, из гайда или из описания видео. Прямой рост трафика.
3. **Легенда** — сейчас иконки нечитаемы без неё. Кнопка в нижней панели, оверлей поверх карты.
4. **Топонимы районов** отдельным переключаемым слоем.
5. **Линейка** — нишевая, но фанаты любят, делается дёшево.
6. **Fullscreen / скрыть панели** — режим «второй монитор».

## 8. Этажи

Степпер `^ 1 v` слишком тихий. Нужен вертикальный список с **названиями** (Подвал / 1 / 2 / 3 / Крыша), активный подсвечен амбером.

Маркеры соседних этажей **не исчезают**, а гаснут до ~20% opacity — иначе теряется пространственный контекст (у eft.su через `Alt + Scroll` теряется полностью).

Подсказку «Используй ALT + Scroll» показывать один раз тостом при первом заходе, а не держать постоянной строкой под шапкой.

## 10. Производительность

- **500+ маркеров на Улицах** — DOM-маркеры не потянут. Canvas/WebGL-слой либо виртуализация по viewport bounds.
- **Кластеризация только для фонового тира** (лут, контейнеры). Никогда для заданий — сгруппированный квест это баг, а не фича.
- Тайлы карты предгенерировать (`z0–z5`), отдавать WebP через CDN, а не один гигантский PNG.
- Данные маркеров — в БД с cron-синком, не рантайм-запросы к tarkov.dev.

## 11. Чего делать не надо

- **Live-позиция игрока** (tarkov.dev + TarkovMonitor, TarkovQuestie за €3.75/мес). Требует десктоп-агента, чтения логов и скриншотов, серой зоны с ToS BSG. Мобильный воркфлоу это не покрывает, поддержка съест месяцы. Максимум P3 — опциональное подключение уже существующего открытого TarkovMonitor по их протоколу.
- **Спутник vs схема** (eft.su). Два комплекта арта на 14 локаций — утонем. Наш стилизованный вектор и так лучше их спутника.
- **Запирать данные за подписку** — за это в EFT-комьюнити бьют, см. историю free-map-genie.

# ЧАСТЬ II. ТЕХСПЕКА: КАРТОЧКА МАРКЕРА, UGC, ЛИЧНЫЕ МАРКЕРЫ

## 13. Ключевое решение

Разделить две сущности, которые легко перепутать:

| | Канонический маркер | Пользовательский маркер |
|---|---|---|
| Источник | CMS, редакция | Сам пользователь |
| Видимость | Публичная, SEO | Приватная (опц. «поделиться по ссылке») |
| Скриншоты | Загружает редакция | Загружает автор |
| Комментарии | Да, `entity_comments` | Нет (это личная заметка) |
| Доступ | Все, включая гостей | Оперативник / Ветеран |

**Что бесплатно, что платно:**

- Читать карту, фильтры, пресеты (до 3), карточки маркеров, комментарии — **бесплатно**.
- Писать комментарий текстом — **бесплатно** (иначе убиваем UGC-маховик и SEO).
- **Прикреплять скриншот** к комментарию — Оперативник+.
- **Свои маркеры и заметки на карте** — Оперативник+.
- Кастомные пресеты фильтров сверх 3 — Оперативник+.

Логика: платим не за доступ к данным, а за персональные инструменты и хранилище.

## 14. Схема БД

```
map_markers                     -- канон, из CMS
  id uuid pk
  map_slug text
  floor smallint
  x, y numeric                  -- в координатах игрового мира, не пикселях
  kind text                     -- 'extract' | 'spawn' | 'quest' | 'key' | 'loot' | 'danger' | 'landmark'
  title_ru, title_en text
  body_md text
  key_item_id text null         -- fk на предметы
  quest_ids text[]
  published boolean

marker_attachments              -- официальные скрины (редакция)
  id, marker_id fk, storage_path, width, height, blurhash, sort_order

entity_comments                 -- СУЩЕСТВУЮЩАЯ, добавить target_type='map_marker'
  ... target_type, target_id ...

comment_attachments             -- скрины в комментариях (UGC)
  id uuid pk
  comment_id fk
  owner_id fk
  storage_path text             -- относительный, без домена
  width, height int
  blurhash text
  bytes int
  status text                   -- 'pending' | 'approved' | 'rejected'
  moderated_by, moderated_at

user_map_markers                -- личные маркеры
  id uuid pk
  owner_id fk
  map_slug text
  floor smallint
  x, y numeric
  icon text                     -- из фиксированного enum, не свободная строка
  color text                    -- из enum токенов NIGHTFALL, не hex от клиента
  label text (<=64)
  note_md text (<=2000)
  visibility text               -- 'private' | 'unlisted'
  share_token text null         -- для 'unlisted'
  created_at, updated_at

user_marker_attachments
  id, user_marker_id fk, owner_id fk, storage_path, width, height, blurhash, bytes, status

upload_quota
  owner_id fk, period date, files_count int, bytes_total bigint
```

`color` и `icon` — **enum на стороне БД**, не произвольный ввод. Иначе через них приезжает XSS в inline-стили и ломается NIGHTFALL.

## 15. Безопасность загрузки скриншотов

Загрузка UGC-картинок — самая опасная поверхность на портале. Схема двухфазная: `sign` → загрузка в staging → `commit`.

### 15.1 Поток

```
1. Клиент  : ресайз в canvas -> WebP, max 2560px, quality 0.82, EXIF отваливается сам
2. POST /api/maps/uploads/sign
             сервер: сессия -> тир -> квота -> rate limit
             сервер: генерирует путь staging/{ownerId}/{uuid} и signed upload URL, TTL 60s
3. Клиент  : PUT напрямую в Storage по signed URL
4. POST /api/maps/uploads/commit  { uploadId }
             сервер: скачивает из staging
             сервер: sniff magic bytes, проверка размеров, re-encode через sharp
             сервер: кладёт в media/{ownerId}/{uuid}.webp, удаляет staging
             сервер: пишет строку в *_attachments со status='pending'
```

Клиент **никогда** не получает service key и не определяет путь — путь целиком генерирует сервер по `ownerId` из сессии. Подставить чужую папку невозможно.

### 15.2 Обязательные проверки на сервере

| Проверка | Значение |
|---|---|
| MIME | По magic bytes (`file-type`), не по `Content-Type` и не по расширению |
| Разрешённые типы | `image/png`, `image/jpeg`, `image/webp`. **SVG запрещён полностью** |
| Размер файла | 8 МБ hard cap (после клиентского ресайза реально ~500 КБ) |
| Разрешение | max 4096×4096, min 320×180 |
| Re-encode | Всегда. `sharp(...).rotate().webp({ quality: 82 }).withMetadata(false)` |
| EXIF | Вырезается принудительно на re-encode |
| Оригинал | **Никогда не отдаётся**, удаляется после commit |

Re-encode — не оптимизация, а санитайзер: убивает polyglot-файлы (PNG с PHP-хвостом), zip-бомбы, битые заголовки. Это единственная надёжная защита.

### 15.3 Отдача

- Приватный бакет, отдача через CDN на **отдельном поддомене** (`ugc.cta.*`), не на основном. Тогда любой промах в контенте не имеет доступа к кукам портала.
- Заголовки: `Content-Type` ставит сервер, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`.
- CSP: `img-src 'self' https://ugc.cta.*` — и всё.
- Storage RLS: `bucket_id = 'media' AND (storage.foldername(name))[1] = auth.uid()::text`.

### 15.4 Приватность игрока

Скриншот EFT содержит ник, время, иногда чат и состав отряда. Перед загрузкой:

- В UI — предупреждение одной строкой: «Проверь, что на скрине нет твоего ника и чата».
- Инструмент замазывания (прямоугольник-заливка поверх canvas) — P1, не блокер.
- EXIF вырезается всегда, координаты и имя ПК не утекают.

### 15.5 Квоты и rate limit

| Тир | Файлов/сутки | Всего файлов | Общий объём |
|---|---|---|---|
| Боец | 0 | 0 | — |
| Оперативник | 10 | 200 | 200 МБ |
| Ветеран | 30 | 1000 | 1 ГБ |

Проверять **до** выдачи signed URL, читая `upload_quota`. Плюс жёсткий rate limit 20 запросов `/sign` в час на `ownerId` независимо от тира.

### 15.6 Модерация

- Скрин в **комментарии** (публичный) → `status='pending'`, не показывается до апрува. Очередь в существующую панель модератора.
- Скрин на **личном маркере** (приватный) → `status='approved'` сразу, виден только автору. Модерация включается только если маркер переводят в `unlisted`.
- Кнопка «пожаловаться» на каждом публичном вложении → `status='rejected'` по решению модератора, файл удаляется из Storage cron-джобой.
- Сироты (staging без commit, rejected старше 7 дней) — чистит `workflow_dispatch` GitHub Action по `CRON_SECRET`.

## 16. Тир-гейтинг: где проверяем

Три рубежа, клиент — **только косметика**:

1. **UI** — `useEntitlements()` рисует замок и CTA апгрейда. Не рендерит форму загрузки. Это UX, не защита.
2. **Route handler** — `assertTier(session, 'operative')` в начале каждого мутирующего маршрута. Единственная точка истины.
3. **RLS** — политики на `user_map_markers` и `*_attachments`. Второй рубеж на случай бага в коде.

Тир читать **из активной подписки в БД**, не из JWT-клейма без TTL. Клейм допустим только с `expires_at` и перепроверкой при мутации — иначе отменённая подписка живёт до ротации токена.

## 17. API

```
POST   /api/maps/uploads/sign            -> { uploadId, url, path, expiresAt }
POST   /api/maps/uploads/commit          -> { attachmentId, storagePath, width, height, blurhash }

GET    /api/maps/[slug]/user-markers     -> список своих маркеров на локации
POST   /api/maps/[slug]/user-markers     -> создать
PATCH  /api/maps/user-markers/[id]       -> обновить
DELETE /api/maps/user-markers/[id]       -> удалить (soft, 30 дней)

POST   /api/comments                     -> существующий, + attachmentIds[]
```

`commit` идемпотентен по `uploadId`. `POST user-markers` принимает `Idempotency-Key` — на мобиле дубли при плохой сети реальны.

## 18. Zustand: три стора, не один

Разделять по жизненному циклу. Смешивать в `useMapStore` нельзя — разная частота инвалидации и разные права.

### 18.1 `useMapViewStore` — эфемерное состояние вида

```ts
interface MapViewState {
  zoom: number;
  centerX: number;
  centerY: number;
  floor: number;
  selectedMarkerId: string | null;
  activeFilters: Record<string, boolean>;
  activePresetId: string | null;
}
```

Не персистится. Двусторонний синк с URL search params (для permalink). Селекторы возвращают примитивы.

### 18.2 Канонические маркеры — **без стора**

Server Component + React `cache()`. Данные иммутабельны в рамках сессии, тащить их в клиентский стор незачем — это лишние сотни килобайт в бандле и лишние ре-рендеры. Клиенту уходит уже отфильтрованный по этажу и LOD срез.

### 18.3 `useUserMarkersStore` — CRUD с оптимистикой

```ts
// src/store/user-markers.store.ts

type UserMarkerIcon = 'pin' | 'loot' | 'danger' | 'camp' | 'sniper' | 'stash';
type UserMarkerColor = 'amber' | 'red' | 'green' | 'cyan' | 'steel';

interface UserMarker {
  id: string;
  mapSlug: string;
  floor: number;
  x: number;
  y: number;
  icon: UserMarkerIcon;
  color: UserMarkerColor;
  label: string;
  noteMd: string;
  visibility: 'private' | 'unlisted';
  attachmentIds: string[];
  updatedAt: string;
}

type PendingOp =
  | { op: 'create'; tempId: string; payload: Omit<UserMarker, 'id'> }
  | { op: 'update'; id: string; patch: Partial<UserMarker> }
  | { op: 'delete'; id: string };

interface UserMarkersState {
  byId: Record<string, UserMarker>;
  idsByMap: Record<string, string[]>;
  syncState: 'idle' | 'syncing' | 'error';
  pendingOps: PendingOp[];
  hydrate: (mapSlug: string, markers: UserMarker[]) => void;
  create: (draft: Omit<UserMarker, 'id' | 'updatedAt'>) => string;
  update: (id: string, patch: Partial<UserMarker>) => void;
  remove: (id: string) => void;
  flush: () => Promise<void>;
}
```

**Правила:**

- `create` возвращает `tmp_${nanoid()}`, рисует маркер немедленно, кладёт op в `pendingOps`. После ответа сервера — реконсиляция id. При ошибке — откат и тост.
- `flush` дебаунсится на 800 мс и вызывается на `visibilitychange`. На мобиле рейд заканчивается закрытием вкладки — терять заметки нельзя.
- **Селекторы возвращают примитивы или стабильные ссылки.** Производные списки (`markersOnFloor`) — через `useMemo` в компоненте или `useShallow`. Не хранить в сторе то, что выводится.
- Стор монтируется только для платных тиров. Для Бойца не подключается вообще: маркеры не рисуются, вместо кнопки «Добавить» — апселл.
- Persist в `localStorage` только `pendingOps` (оффлайн-очередь), не весь `byId`. Полный слепок приезжает с сервера.

### 18.4 Дискриминированный юнион для рендера

Слой маркеров должен уметь рисовать оба типа без `any`:

```ts
type RenderableMarker =
  | { kind: 'canonical'; data: MapMarker }
  | { kind: 'user'; data: UserMarker };
```

## 19. Карточка маркера — UI

Правая панель (десктоп) / bottom sheet (мобайл). Порядок блоков:

1. Заголовок: `title_ru`, ниже мелким `title_en` (половина комьюнити гуглит по-английски).
2. Тип и этаж, чипами.
3. Галерея скриншотов — горизонтальный скролл, blurhash-плейсхолдер, лайтбокс по тапу. Скелетон, не спиннер.
4. Требуется ключ → карточка предмета со ссылкой в раздел Ключи, окрашена по владению.
5. Связанные задания → ссылки в раздел Заданий.
6. Комментарии (`entity_comments`, `target_type='map_marker'`).
7. Кнопки: «Поделиться» (permalink с координатами), «Добавить свою заметку здесь» (Оперативник+).

Комментарий рендерится через markdown-санитайзер с allowlist-тегами. Никакого `dangerouslySetInnerHTML` на сыром вводе.

## 20. Чего делать нельзя

- Доверять `Content-Type` или расширению файла.
- Отдавать оригинал загруженного файла.
- Проверять тир только на клиенте.
- Пускать SVG в загрузку.
- Хостить UGC на основном домене без `nosniff`.
- Хранить произвольный hex-цвет от клиента — только enum токенов.
- Хранить подписанные URL в состоянии дольше их TTL.

## 21. Порядок работ по Части II

**Фаза 1 — фундамент**
`map_markers` + `marker_attachments` в CMS, карточка маркера, официальные скриншоты, комментарии через `entity_comments`. Всё публичное, без UGC-загрузки.

**Фаза 2 — загрузка**
`sign` / `commit`, sharp-пайплайн, квоты, rate limit, RLS, очередь модерации. Скриншоты в комментариях для Оперативник+.

**Фаза 3 — личные маркеры**
`user_map_markers`, `useUserMarkersStore`, оптимистика, оффлайн-очередь, редактор маркера, вложения к своим маркерам.

**Фаза 4 — шеринг**
`visibility='unlisted'`, `share_token`, OG-превью для расшаренного маркера, экспорт набора маркеров.

Каждая фаза — атомарный коммит на фичу, файлы группируются семантически. `npx tsc --noEmit` зелёный до пуша в `main`. Миграции — через `workflow_dispatch` на API-роут под `CRON_SECRET`.
