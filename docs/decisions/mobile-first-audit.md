# Mobile-first аудит (E8) — проход 1

Статический аудит всего `src` (стратегия брейкпоинтов, ширины, таблицы, тач-таргеты, оверфлоу) + выборочная проверка ключевых зон. Цель — инвентарь мобильных проблем с приоритетами. Первый проход, не поэкранно исчерпывающий: визуальные баги добираются живым смоком на устройстве.

## Вывод
**Мобильный фундамент есть, лаунч-блокеров не найдено.** Tailwind по умолчанию mobile-first (база = мобилка, `lg:`/`xl:` = десктоп-оверрайды), и проект этим пользуется корректно. Есть бургер-меню (`BurgerMenu` + `MobileMenuStats`), дровера (`CompareDrawer`, `QuestDrawer`, `MapLayersDrawer`). Находки — уровень доводки (P1/P2), не блокеры.

## Что уже хорошо
- **База mobile-first.** Десктоп-раскладки через `lg:`/`xl:` (149 + 80 использований), мобилка — база.
- **Мобильная навигация есть** — бургер + мобильная статистика; десктоп-навбар `hidden xl:flex`, бургер `xl:hidden`.
- **Фикс-px ширины безопасны** — либо декоративные (`w-[300px]` glow, `w-[160px]` лого), либо `lg:`-гейтед (`lg:w-[522px] lg:shrink-0`, на мобилке `w-full`). Оверфлоу не создают.
- **Широкий контент обёрнут** — 14× `overflow-x-auto`, контейнер разделов `max-w-275 px-4` (без краевого прилипания).

## P1 — доводка (юзабилити, не блокеры)
1. **Тач-таргеты < 44px** — ✅ **СДЕЛАНО (2026-07-08).** Пер-инстансный проход: 15 настоящих иконочных кнопок подняты до 44px на мобилке (`h-11 w-11 lg:h-8/9…`, десктоп без изменений) — карты (floor-switcher, follow-тоггл), Story-навигация, StoryQuestMap, контролы items/achievements, нав квестов, кнопка «На главную». Из ~46 файлов-кандидатов остальные подтверждены декором (иконки предметов в кликабельных строках, аватары, бейджи — тап-таргет там вся карточка/строка). Коммиты: `eb7935a6`, `003f8170`, `4d365961`. Слепой sweep был бы ошибкой (напр. `h-8 w-8` в MapLayersDrawer — `<img>` слоя).
2. **Дата-таблицы на мобилке.** `ItemsTable` — `table-fixed w-full` (не оверфлоит, но столбцы сжимаются → нечитаемо на узком экране). `ItemsCategoryClient` — таблицы в `overflow-x-auto` + `whitespace-nowrap` (гориз. скролл — функционально, но mediocre UX). Рекомендация: **card-reflow** на `<sm` для ключевых таблиц (карточки вместо строк), гориз. скролл оставить как фолбэк.

## P2 — полировка
1. **Проверить `AchievementsClient` (таблица `w-full` на стр. 350)** — обёрнута ли в скролл-контейнер; иначе на узком экране возможен оверфлоу.
2. **Средний диапазон брейкпоинтов.** 149 `lg:` + 80 `xl:` — проверить sm–lg (планшет / крупный телефон) на неловкие промежуточные состояния (напр. навбар прячется на `xl`, но контент раскладывается на `lg` — есть ли «дыра» на 1024–1279px).
3. **`whitespace-nowrap` (23×)** — точечно проверить, что все вне скролл-контейнеров не переполняют (большинство внутри `overflow-x-auto`, но не все).

## Порядок фиксов (рекомендация)
1. **P1.1 тач-таргеты** — системно и дёшево, ощутимый прирост мобильного UX. CI-проверяемо.
2. **P1.2 таблицы → card-reflow** — по одной ключевой таблице за коммит.
3. **P2** — точечные проверки/фиксы.
