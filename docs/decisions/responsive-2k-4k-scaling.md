## 1. Как устроено масштабирование (контракт)

Портал масштабируется через **root-rem**, а не медиазапросы на каждый элемент:

```
html { font-size: clamp(1rem, 0.25rem + 0.625vw, 1.75rem); }
   → 16px @1920 · ~20px @2560 · 28px @3840
```

Всё, что задано в **rem / Tailwind-шкале** (`text-sm`, `h-10`, `w-40`, `gap-7`, `p-4`, `size-6`),
масштабируется автоматически от root. Плюс:
- `--type-*` — fluid-типографика `clamp(min, base+vw, max)` (заголовки, тело);
- `.max-w-275` (контентная колонка 1100px) расширяется медиазапросами до **1600px @2560** и **2200px @3840**.

**Нарушитель контракта = сырой px в видимой размерности:** `text-[28px]`, `h-[240px]`,
inline `fontSize:'11px'`, фикс-px в JS-константах сеток. Такое НЕ растёт за root → на 4K
остаётся мелким рядом с выросшим rem-контентом (рассинхрон масштаба).

**Приём фикса:** `[Npx] → [(N/16)rem]`. Пиксель-в-пиксель на 1920, масштабируется выше.
Именно поэтому эталон 1920 не двигается (проверено live: h1 = 28px и до, и после).

## 2. Deep-research: a11y-фикс фундамента (сделано)

Старая формула `clamp(16px, 0.833vw, 28px)` использовала **чистый vw** в preferred —
антипаттерн доступности: браузер не тянет vw при зуме страницы, текст не доезжает до 200%
(**WCAG SC 1.4.4 Resize Text**). Первоисточники: Smashing (Fluid Type a11y), ntgard,
Chip Cullen, Josh Comeau, W3C csswg #6869.

Замена с rem-якорем — **поведенчески тождественна** на концах диапазона:
`clamp(1rem, 0.25rem + 0.625vw, 1.75rem)` → 16px@1920, 28px@3840; `max/min = 1.75 < 2.5`
(порог прохождения SC 1.4.4). В середине рампа чуть положе (линейно до 3840, а не кэп ~3360px).

**Прочие рекомендации research (на потом, не в этой ветке):**
- `next/image`: верхняя ступень `deviceSizes` под 4K + обязательный `sizes` на крупных ассетах
  + пониженный `quality` для высоких DPR; фикс-ассеты (аватары/лого/арт наград) — исходник ×2.
- Рассмотреть fluid-grid (Utopia) вместо ступенчатых `max-width` брейкпоинтов — опционально.
- Зафиксировать инвариант `max ≤ 2.5×min` для всех `--type-*` как правило дизайн-системы.

## 4. Что НЕ тронуто — нужен разбор V4DYA (осознанный skip)

Связанные системы, где слепая px→rem конверсия сломает вид. Оставлены как есть:

1. **Сетки предметов под фикс-спрайты** — `SlotGrid.tsx` (cell 6px), `StashGrid.tsx` (CELL=53),
   `SeasonBuildGallery.tsx` (CARD_W/H 184×328), item-грид `ContainerContents`.
   Ячейки завязаны на растровые иконки предметов фикс-разрешения. Масштабировать ячейку без
   масштабирования спрайта = рассинхрон. Решение: либо привязать и спрайт к rem (проверить мыло),
   либо оставить пиксельными осознанно. **Твой дизайн-колл.**

2. **Leaflet-маркеры карт** — inline `font-size:Npx` в `MapViewerClient`, `manual-marker-icon.ts`,
   и `.cta-*` в globals.css (`.cta-cluster` 12px, `.cta-transit` 22px, `.cta-hazard`, `.cta-ex-name`).
   Маркеры уже масштабируются своей системой `--marker-scale` (по зуму карты). Наложение root-rem
   поверх = двойной масштаб. Карта — near-fullscreen, живёт вне 1100px-колонки. **Трогать отдельно.**

3. **Turnstile** `min-h-[65px]` — сторонний виджет-iframe фикс-размера, не наш.

## 5. Ограничение верификации

`resize_window(2560/3840)` через браузер-автоматизацию не даёт истинный CSS-viewport >1920
(физический экран 1920, DPR=1 → медиазапрос `min-width:2560px` не срабатывал). Поэтому 2K/4K
подтверждены **математикой формул + live-пробой** (симуляция root=28px: h1→49px, nav→26.25px),
а не скриншотом на реальном 4K. Пиксельная сверка «красоты» на 2K/4K — за тобой на реальном мониторе.
