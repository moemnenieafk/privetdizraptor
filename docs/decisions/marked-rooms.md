# Меченые и цветные комнаты — трекер открытий

## Цель
Меченые комнаты и цветные комнаты Лаборатории получают на карте подсвеченные границы, а по клику — отдельную страницу с экономикой ключа, лут-таблицей и живой статистикой открытий от сообщества. «Какой ключ брать и стоит ли» → один экран с готовым вердиктом.

## Границы
- **В scope сейчас (бэкенд-first, от макета не зависит):** модель данных → таблицы (DDL-модуль) → RLS → сид реестра из `map_markers` → ридеры страницы (лут-таблица + экономика ключа).
- **Ждёт макета V4DYA (Фаза 2):** страница комнаты, подсветка границ на карте, лента открытий, UI модерации.
- **НЕ трогаем:** обмен репутации на Premium (гейтит [[feature-gating-entitlements]]); раздел модерации/«колокольчик» целиком (аккаунт-центр); синканный рендер карты; near-fullscreen раскладку карты (сырой источник 2026-07-25 содержит и её — это отдельная задача [[Карты — интерактивные]]); схему через `db:push` (идём DDL-модулем).

## Модель данных (ратифицирована, DDL-ready)
Конвенции — по `markers-ddl.ts`: uuid PK, FK→games/maps/profiles, `create if not exists`.

**`marked_rooms`** — реестр (сущность страницы + подсветка):
`id uuid pk` · `game_id`→games · `map_id`→maps · `slug` (маршрут `/eft/maps/<map>/rooms/<slug>`) · `kind` ('marked'|'lab_color') · `color?` (цветные Лабы) · `key_item_id?` (id зеркала цен → экономика ключа) · `polygon jsonb?` (границы) · `title` · `description?` · `created_at/updated_at`.
Индексы: `unique (game_id, map_id, slug)`, `(map_id)`.

**`room_opens`** — одно открытие (заявка сообщества):
`id uuid pk` · `room_id`→marked_rooms (cascade) · `author_id`→profiles? · `is_anonymous bool default false` (юзер выбрал аноним — `author_id` храним для модерации/антиабуза, на странице скрываем) · `status` ('pending'|'approved'|'rejected', default pending) · `moderator_id`→profiles? · `moderated_at?` · `proof_youtube_url?` · `proof_screenshot_key?` (ключ ВРЕМЕННОГО бакета; →null после авто-удаления) · `game_version?` · `opened_at?` · `created_at`.
Индекс: `(room_id, status, created_at desc)` — витрина «последние N».

**`room_open_items`** — предметы открытия (M:N, для ленты + пересчёта шанса):
`open_id`→room_opens (cascade) · `item_id` (id зеркала) · `qty int default 1`. PK `(open_id, item_id)`.

**`reputation_events`** — леджер (не денормализованный баланс):
`id uuid pk` · `user_id`→profiles (cascade) · `delta int` · `reason` ('room_open_approved'…) · `ref_type?` · `ref_id?` · `created_at`. Индекс `(user_id)`. Баланс = `sum(delta)`.

## RLS (defense-in-depth; пишет сервер owner-ролью, обходит RLS)
- `marked_rooms` — read-all публично (`using(true)`).
- `room_opens` — read публично ТОЛЬКО `status='approved'`; INSERT заявки — авторизованный юзер (rate-limit через mirror-таблицу, §4.11); модерация/начисление — owner-роль (сервер).
- `room_open_items` — read-all (значимы только в join с approved-открытием).
- `reputation_events` — read своей строки (`auth.uid() = user_id`); лидерборд-публичность — позже, если понадобится.

## Экономика страницы (вычисляется на рендере, не хранится)
Заголовочный вывод страницы — «выгодно ли брать ключ прямо сейчас»:
- **Цена ключа на барахолке** + **способы получения** (бартер / крафт / места спавна) — из зеркала цен и item-ридеров; переиспользуем карточку Замок→Ключ.
- **Средняя стоимость одного открытия** = средний суммарный ₽ по **approved**-открытиям (join `room_open_items` → цены, avg по открытию). Не хранится — считается на рендере, как EV heatmap.
- **Вердикт окупаемости** «Выгодно» / «В минус» = `средняя стоимость открытия − цена ключа`. Динамический, на живых ценах. 0 открытий → «нет данных» (graceful).
- **Динамический шанс редких предметов** — частоты по последним 100 approved (см. ниже).

## Витрина «последние 100» → шанс выпадения
Пересчёт по последним 100 **approved**-открытиям комнаты: `limit 100` + агрегат частот `room_open_items`. Materialized view на старте НЕ нужен; если ленты станут горячими → materialized + refresh по факту принятия. Лента «1 мин назад — …» = approved-опены `order by moderated_at desc`.

## Пайплайн модерации медиа
Скрин → приватный **временный бакет** Storage (`room-proofs/`), ключ в `proof_screenshot_key`; после вердикта — **немедленно удалить объект**, ключ→null («даже гиг много»). Видео — только `proof_youtube_url`. Модератор: заявка+медиа → выбор найденных предметов из `getEftCatalog` → «Принять» (INSERT `room_open_items` + `reputation_events` +N, `status=approved`) / «Отклонить».

## Регламент пруфов (критерии модерации — что проверяет модератор)
Накрутка отсекается строгой валидацией; на слово не верим. Открытие засчитывается, если пруф показывает:
1. **Дверь до отпирания** — в руках/контекстном меню виден ключ или карта ПЕРЕД открытием.
2. **Процесс** — заход в комнату и подбор всех предметов.
3. **FIR** — открыт инвентарь, у всех найденных предметов галка «Найдено в рейде».
4. **Тех-данные** — на видео/скрине видны текущая **версия игры, дата и время** (→ поле `game_version`).
Видео — только ссылкой на YouTube; скрин — временно, удаляется сразу после вердикта.
