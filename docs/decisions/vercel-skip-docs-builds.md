# Vercel: пропуск билда для docs-only пушей

**Статус:** ✅ сделано — `ignoreCommand` в `vercel.json` (коммит `f1ee8ef`).
**Затрагивает:** `vercel.json`
**Процесс:** первый прогон через [[engineering-loop]].

## Контекст
После Фазы 2 ([[db-egress-reduction]], пререндер 76 категорий) каждый пуш в `main` гонит тяжёлый ребилд — билд-минуты + билд-egress из Supabase (`loadEnriched`/индикаторы читаются на билде). Но мы часто пушим **docs-only** (заметки-решения, валт) — таким пушам ребилд не нужен.

## Решение
`vercel.json` → `"ignoreCommand": "git diff --quiet HEAD^ HEAD -- ':(exclude)docs/'"`.
Семантика Vercel: **exit 0 = skip**, **≠0 = build**.
- только `docs/` → diff пуст → `0` → skip
- есть код → diff непуст → `1` → build
- ошибка git (нет `HEAD^`) → `128` → build (**fail-safe**: лишний билд, не пропущенный нужный)

## Проверка (детерминированно, локально)
Команда прогнана на реальных коммитах:

| коммит | что | exit | вердикт |
|---|---|---|---|
| 117fa1b, 9f8c21a | docs | 0 | SKIP ✅ |
| f1ee8ef, 951c4fe, 697b711 | code | 1 | BUILD ✅ |

Прод `200` (vercel.json валиден). `buildId` в HTML App Router не отдаётся → внешняя прод-проба невозможна; логику покрывает локальный тест (это и есть детерминированный verifier).

## Кавеат
`HEAD^..HEAD` видит только **последний** коммит. Если в одном пуше несколько коммитов и последний docs-only, а ранний — code, билд пропустится ошибочно. **Норма: пушить docs-коммиты отдельно от code** (так и делаем).

## Подтверждение на проде
Этот пуш (заметка = docs-only) — живой тест: в Vercel → Deployments он должен быть **Skipped** (нового билда нет).
