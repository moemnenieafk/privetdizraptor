# Система управления контентом (CMS)

## Цель
Редактор (не программист) должен добавлять и править контент сам — без коммитов в репозиторий.

## Что уже работает (сверка с кодом 14.07)
| Контент | Кто правит | Чем |
|---|---|---|
| Блог · Мастер-классы · Разборы патчей | admin | `ArticleEditor` (инлайн в «Связи») + `POST /api/admin/articles`, markdown, черновик/публикация |
| Каталог предметов | admin | `/admin/items` |
| Форум, жалобы | admin · moderator | pin/lock/hide + очередь жалоб |
| Цены, бартеры, карты, оружие | — | кроны-синки (tarkov.dev / SPT) |

**Дыра:** Кодекс (8 лор-статей), сюжетные гайды (10 историй), события, loot-контейнеры — живут в `src/data/*.ts`. Публикация = правка TypeScript + коммит. Для стороннего редактора это неприемлемо.

## Решения (V4DYA, 14.07)
1. **Контент из `src/data` переезжает в БД** — Кодекс И истории редактируются через UI.
2. **Нужна роль `editor`** — пишет контент, не лезет в предметы/роли/настройки.
3. **Модель редактирования — гибрид: инлайн на живой странице + `/admin` как хаб.** Обоснование и разбор рынка 2026 → [[deep-research-cms-editing-model]].
   - Инлайн («✎» на странице) — правка существующего: контекст, шрифты, сетка, мобилка — настоящие. Живая страница = превью, потому что рендер — наши же компоненты.
   - `/admin` — создание, списки, фильтры по статусу/автору, удаление, медиа, модерация.
   - Черновики — через нативный **Next.js Draft Mode** (`draftMode()`), публикация — `revalidateTag` (без ребилда).
4. **Готовый headless (Payload/Directus/Strapi/Sanity) — отклонён:** второй рантайм и схема, чужая админка = второй визуальный язык против NIGHTFALL. Своя CMS уже наполовину есть (`ArticleEditor`).
5. **Rich-text:** сначала markdown + живой предпросмотр (0 зависимостей); Tiptap — только если редакторы попросят WYSIWYG.

## План (фазы E10)
- ✅ **E10.1 · Роли и гейты** — сделано 14.07 (`c3e62163`, `56c949b6`). `src/lib/auth/roles.ts` — канон прав (`canEditContent` / `canModerate` / `canManageCatalog` / `canAccessCms`), `getCmsUser()`, `/admin` пускает editor'а (каталог остался за админом, страницы закрыты своим гардом), `set-role` умеет выдавать `editor`.
- ✅ **E10.2 · Draft Mode + публикация** — сделано 14.07 (`66e094a9`, `32e39e72`, `c8045f04`). `POST/DELETE /api/draft` — гейт по **сессии**, не по secret-токену (CMS своя, редактор залогинен). Тумблер «Черновики» смонтирован в layout «Связи», **не в корневом** — иначе cookies+БД в root layout сделали бы динамическими все страницы и убили ISR ([[db-egress-reduction]]). Статьи читаются с `includeDrafts`, публикация — `revalidatePath` (без ребилда).
  - Попутно закрыт **баг потери контента**: кнопка «Править» в ленте открывала форму с пустым `bodyRu` и `published: true` (лента не тащит тела) → сохранение затирало разбор и публиковало черновик. Теперь материал догружается через новый `GET /api/admin/articles?id=`.
- **E10.3 · Кодекс → БД** `M` — таблица `codex_articles` (+ RLS), скрипт-миграция 8 существующих статей из `src/data/codex/`, инлайн-редактор на странице статьи + создание из `/admin`.
- **E10.4 · Медиа-библиотека** `M` — загрузка изображений в Supabase Storage (`cta-media/content`), пикер, привязка к статьям/шагам. Закрывает и [[story-content-assets]] (галереи историй грузятся через UI, а не коммитом).
- **E10.5 · Истории → БД** `L` — таблица `story_guides` (JSONB-дерево шагов/веток/медиа), **структурный конструктор** дерева (не WYSIWYG: шаги → под-этапы → развилки, drag-and-drop), миграция 10 историй, инлайн-кнопка «править этот шаг» с гайда.
- **E10.6 · Версии и аудит** `M` — `content_versions` (кто/когда/что), откат, история правок.

## Границы
- **НЕ трогаем:** синкаемые данные (цены/карты/оружие) — они из кронов, редактор их не правит.
- **НЕ строим:** drag-and-drop page-builder. Контент структурный, а не лендинги.

## Порядок
E10.1 → E10.2 (фундамент) → E10.3 (Кодекс — самый простой контент-тип, обкатка) → E10.4 (медиа) → E10.5 (истории — самое сложное) → E10.6.

## Гарды
- ⚠ БД: новые таблицы (`codex_articles`, `story_guides`, `content_versions`) + RLS — через DDL-роут (паттерн `migrate-comlink`), не `db:push`.
- Миграция контента из `src/data` — скриптом, старые файлы удаляются только после проверки, что БД отдаёт то же самое.
