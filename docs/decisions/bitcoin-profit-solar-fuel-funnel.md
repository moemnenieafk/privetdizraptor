# Прибыль Bitcoin — Солнечная батарея + учёт канистр по «воронке добычи»

Правим `/eft/progress/hideout/bitcoin-profit`. Два содержательных изменения из макета node 3054-933,
меняющих **логику калькуляции**: (1) **Solar Power** как тумблер ×2 длительности бака, (2) цена канистры —
через **рекурсивный движок «воронки добычи»** (barter→craft→инпуты) из `ideas/2026-08-23-0352`, число
канистр = ёмкость Генератора. Грил-развилки закрыты V4DYA 2026-08-23 (журнал §10).

## 1. Что решено (свод грила)

### Фуел-блок (UI, колонка «Убежище ЧВК» → «Учёт топлива»)
1. Опция **«Нет топлива» удалена** — без топлива Bitcoin-ферма не работает.
2. Первая ячейка = **тумблер Solar Power** (глиф «солнце»). Независимый от выбора бака, `durationMs ×2`.
   Дефолт из профиля (`useHideoutStore.levels['solar-power'] ≥ 1`) + ручной override (гибрид C).
3. Канистры **Expeditionary / Metal** — single-select, **всегда одна выбрана**. Бак по умолчанию —
   **автодешёвый по воронке** (как tarkov.dev выбирает дешевле из двух), игрок может переключить.
4. Бейдж «xN» на активной канистре = **ёмкость Генератора** (слотов на построенном уровне).
   Модель A: N = слоты Генератора → «полная заправка = N × ценаКанистры» + автономность.
   ⚠️ **Факт к подтверждению:** слоты Генератора по уровням — заложить **L1:2 / L2:3 / L3:4**
   («x4» в состоянии L3 макета = L3 Генератора). Проверить при реализации / у V4DYA.

### Экономика топлива (формула 1:1 tarkov.dev — наш эталон сверки)
5. `rateУУ = min(0.005 · lvlУУ, 0.25)`
   `effDurationMs = tankBaseDurationMs / (1 − rateУУ) × (solarActive ? 2 : 1)`
   `fuelCostPerDay = ценаКанистрыЗаШт / effDurationMs × 86_400_000`
   — **Solar ×2 добавляется** (сейчас в коде его НЕТ). Элита УУ отдельным множителем **не моделируется**.
6. **ценаКанистрыЗаШт = `bestAcquisitionCost(tankItemId)`** (движок §2). Одна цена питает и `₽/сут`,
   и «полную заправку» (N слотов × цена) в блоке «что нужно купить».
7. Буфер несобранных биткоинов **3→5** — только справочной строкой (как сейчас), в профит не входит.

### Профиль-синк (гибрид C, как у фермы/навыка)
8. Уровень фермы, навык УУ, **Solar Power**, **уровень Генератора** (для ёмкости) — дефолт из профиля,
   override-контролами. До маунта — гард (persist-сторы только на клиенте).

## 2. Движок «воронки добычи» — `src/lib/acquisition-funnel.ts` (НОВЫЙ, переиспользуемый)

`bestAcquisitionCost(itemId): { total, perUnit, path }` — «как выгоднее всего получить предмет ПРЯМО СЕЙЧАС».
Первое применение — топливо в этом калькуляторе; дальше тот же движок пойдёт на карточку предмета
`/eft/items/item/[slug]` (это его настоящее место по ideas).

Правила (решено грилом):
1. **Полная рекурсия** barter→craft→инпуты→… . Сравниваемые пути на каждом узле:
   - **покупка у торговца** (константа) = `min(buyFor)` **без флиа**;
   - **барахолка** = флиа-оффер из `buyFor` (если есть);
   - **бартеры** (по всем LL торговцев);
   - **крафты** (по станциям/уровням).
2. **Теоретический минимум** — все пути **независимо** от прогресса игрока (LL/построенные станции),
   с пометкой источника/LL в `path`. (Гейт «только доступное мне» — потенциальный follow-up тумблер.)
3. **Оценка узла** (бартер/крафт): цена **за 1 штуку** = `Σ(стоимость инпутов, рекурсивно) / countНаВыходе`.
4. **Инпуты-инструменты** (`attributes.tool` в зеркале — не расходуются) — **исключаем** из стоимости.
5. **Время крафта игнорируем** — считаем только материальную (денежную) стоимость.
6. **Циклы** — множество `visited` по текущему пути (предмет уже в пути → ветку не разворачиваем);
   **кэш** цены на предмет в пределах прогона.
7. **База** (лист рекурсии) — предмет, который только «купить у торговца / на барахолке» и не
   бартерится/не крафтится: его цена = `min(доступные buyFor)`.
8. **Данные — только зеркало** (§4.11): `barters` + `crafts` (топология уже зеркалится,
   `src/db/barters-crafts.ts`) + `prices` (цены/buyFor). Новых внешних источников НЕТ.

## 3. Данные — БЕЗ миграции

- Топология бартеров/крафтов **уже в зеркале** (`barters`/`crafts`, `minTraderLevel`, `requiredItems`/
  `rewardItems`, `attributes.tool`). Цены/`buyFor` — в `prices`. Слоты Генератора и ×2 Solar в зеркале
  **отсутствуют** (в `hideout_upgrades` только требования апгрейдов, не бонусы) → зашиваем константами
  в `bitcoin-profit.ts` (как `BTC_BASE_SEC`).
- Ридер воронки (RSC-only) строит граф из `barters`/`crafts`/`prices` для gameId EFT; отдаёт клиенту
  готовую `perUnit`-цену + `path` выбранного бака (клиент не гоняет граф).

## 8. tarkov.dev как эталон (сверено по `data.js`)
- Solar Power L1 → `durationMs ×2`. УУ → `durationMs /(1−rate)`, `rate = min(0.005·lvl, 0.25)`.

## 12. Фуел-блок v2 — дропдаун типа + сетка количества (грил 2026-08-23, вечер)

Смена логики после live-обкатки: вместо single-select 2 ячеек + бейдж=ёмкость →
**дропдаун выбора ТИПА** канистры + **отдельная сетка выбора КОЛИЧЕСТВА** (как GPU-грид).
Design-to-code: node 3058-2875 (дропдаун «выбор канистры») + node 3054-933 (сетка справа).
Скрины: `.autopilot/.../dropdown_3058.png`, `grid_3054_L3.png`.

**UI:**
- Solar-тумблер — остаётся (×2).
- **Дропдаун типа** (node 3058-2875): триггер = выбранная канистра (иконка + бейдж кол-ва), клик →
  список типов (Экспедиционная/Металлическая). Дефолт-тип = дешевейший по воронке.
- **Сетка количества** (node 3054-933, зеркало GPU-грида): иконки `full-tank-icon.svg`, одна маска,
  3 цвета по состоянию — installed `bg-(--primary)` / free `bg-text-muted` / locked `bg-lines-hover/50`.
  Клик по слоту → N = i+1; клик за ёмкость Генератора → авто-поднять уровень Генератора (what-if).
  Максимум сетки 6 (L3). Дефолт N = **×1 канистра**.

**Экономика (число канистр N):**
- N **не влияет** на ₽/сутки топлива, чистую прибыль, окупаемость (расход фиксирован; payback GPU-only).
- N двигает: разовую заправку = N × цена-по-воронке (в «что нужно купить») + автономность строкой
  «хватит на ~M дней», M = N × длительность_бака_с_Solar/УУ ÷ сутки.
- Один тип × N (без микса).

**Профиль-синк (гибрид C):** тип (дефолт по воронке), уровень Генератора (профиль + override через сетку),
Solar (профиль + override).

**Убираем:** прежний single-select 2 ячеек + бейдж=ёмкость. Реализация — §13.
