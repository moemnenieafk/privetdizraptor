# 3D clay-карты: второй режим, платный

**Статус:** 🟢 решено · грилл с V4DYA 2026-09-05, 14 развилок закрыто
**Исследование:** [[docs/research/deep-research-3d-clay-maps.md]] (~1490 строк, с замерами на наших артефактах)
**Затрагивает:** [[docs/decisions/eft-map-layers.md]] · [[docs/decisions/feature-gating-entitlements.md]] · [[docs/decisions/monetization-subscriptions.md]] · [[docs/decisions/customs-tile-promote.md]] · скиллы `/map-stitch`, `/map-tile-promote`, `/game-asset-extraction`, `/cta-backend`

## Суть решения одной фразой

Плоская карта остаётся для всех и никуда не девается; **3D — второй режим, только для просмотра, платный, флагман нового верхнего тира**.

## Контекст

Из клиента EFT извлечена геометрия десяти карт. Возник вопрос: раз геометрия есть, нельзя ли
рендерить саму сцену в браузере — с вращением и зумом, как карта в Doom: The Dark Ages
и в The Division.

Первая формулировка была «автоматическая ретопология в лоуполи» — отклонена, см. «Поправка».
Рабочая формулировка V4DYA: без текстур, всё в clay, метки — 3D-экструзия иконок со свечением,
вращение вместо плоскости. Итоговая, после грилла: **два режима, 3D платный и дорогой**.

## Визуальный референс

Три референса от V4DYA, положить в `docs/decisions/3D/refs/`:

1. **Постер марша 7.7 (Гонконг).** Тёмная монохромная clay-карта сверху под углом. Здания —
   тёмно-сине-серые объёмы без деталей. Дороги — тонкой светлой контурной линией. Поверх
   ярко-жёлтый **светящийся маршрут** и два пина-капли.
2. **Ночной лоуполи-город.** Синий clay + оранжевое свечение окон, tilt-shift.
3. **Логистическая карта.** Тёмная подложка, красные светящиеся трассы, пины, DOF.

### 🔑 Что из них следует

**Геометрия не старается быть узнаваемой — она приглушена до фона.** Читаемость держат
светлые контурные линии, свечение слоя данных и edge/rim на гранях. Отсюда: **AO вторичен,
outline первичен** — вопреки тому, как задача ставилась изначально.

## Решения грилла (канон)

| # | Решение | Почему |
|---|---|---|
| 1 | **Два режима**, 3D не заменяет 2D | 3D платный; 2D остаётся для всех и для мобилок |
| 2 | 3D — **только просмотр**: геометрия, этажи, метки, маршруты, комнаты, heatmap | Визард, редактирование, отряд, drawer остаются в 2D — клик там однозначен, а в 3D raycast даёт неоднозначную глубину |
| 3 | **Новый верхний тир**, 3D — его флагман; демо: одна карта без слоя данных | 449 ₽ Ветерана 3D бы растворило. Платишь не за 3D, а за **данные** в 3D |
| 4 | Платный релиз — **Таможня, Резерв, Улицы** | Карты с настоящей вертикалью. Лес и Берег от 3D выигрывают мало |
| 5 | Подложка — **чистый clay**, рисованный арт в 3D не участвует | Арт фотореалистичный и цветной, clay тёмный монохром — два разных языка в одной сцене |
| 6 | Слой данных — **по умолчанию не светится ничего** | 446 меток на самой маленькой карте. Включи всё — bloom склеит их в световую кашу |
| 7 | Сцена в **игровых метрах**, без пикселей и проекций | Расхождение 7.6 м рождалось при проекции в px; нет проекции — нет расхождения |
| 8 | Этажи — **фокус + призраки** | Честный срез по высоте невозможен: этажи в EFT не лежат на общих отметках, уровень оценивается модой низов |
| 9 | Камера — **орто**, свободное вращение вокруг вертикали, наклон 30–75° | Макетный вид референсов даёт именно орто; единый масштаб по кадру = можно прикидывать дистанции |
| 10 | **Маршруты по графу проёмов — флагманская фича**, внутри зданий | У нас есть граф проёмов → есть светящаяся линия из референса. Навсетку по местности НЕ строим |
| 11 | Heatmap — **текстура, проецируемая на рельеф** | `leaflet.heat` в three.js не существует; расчёт EV переиспользуется один в один |
| 12 | Геометрия — **гибрид A+C** | Массовая застройка экструзией силуэтов, знаковые строения реальными мешами |
| 13 | Градация цвета **по классам** | Бесплатно: `building/props/fence/plant/stone/openings` уже размечены в SVG |

## Решения второго круга (детализация, тот же грилл)

| # | Решение | Почему |
|---|---|---|

| 15 | Цвет — **лестница NIGHTFALL**, свечение единым `var(--primary)` | `darkbase → base → card-menu → lines-hover` под классы геометрии. Ни одного нового HEX. `--primary` меняется по игре → слой данных сам перекрасится для GZW/ABI |
| 16 | Свечение **не кодирует тип метки** | Следует из №6: светится одна категория за раз, различать нечего. Разноцветность вернёт кашу |
| 17 | Сцена — **рельеф + камни объёмом, растительность плоскими пятнами** | Кроны сверху закрывают землю и метки. Радиус кроны из габарита у нас уже есть |
| 18 | Метка — **объёмный пин-капля + плоская иконка к камере** | У пина есть **остриё** → привязка к точке. Парящая иконка на наклонной камере неоднозначна. Экструзия переезжает на саму каплю (offline, один раз) |
| 19 | Маршрут **не подчиняется фокусу этажа**, прошивает насквозь + бегущее свечение | Иначе главная фича рвётся на куски. Этажи гаснут ради маршрута, а не наоборот. Анимация задаёт направление — это функция, не декор |
| 20 | Роутинг — **`/eft/maps/[slug]/3d`** отдельным сегментом | Гейт резолвится в RSC **до загрузки бандла** three.js; URL шарится (маркетинг премиума); 2D не тяжелеет и не ломается |
| 21 | `.glb` — **на R2** рядом с тайлами через `mapAssetBase`; пересборка скриптом руками | Геометрия меняется раз в патч игры, крон не нужен |
| 22 | Клик по комнате — **строит маршрут + карточка рядом** | Один клик отвечает и «как дойти», и «что там». Клик по метке — карточка как в 2D, по зданию — ничего |
| 23 | Старт маршрута — **живая позиция Track-1**, фолбэк вход в здание, третьим ручной выбор | См. находку ниже |
| 24 | Демо — **Ground Zero**; на платных картах гейт в режиме **`lock`** | Вне платной тройки → не каннибализирует. Стартовая карта новичка = естественная точка входа. `lock` показывает витрину, `hide` спрятал бы само существование фичи |
| 25 | Tilt-shift — **в настройки, по умолчанию ВЫКЛ** | ⚠️ Решение V4DYA против моей рекомендации: карта прежде всего инструмент, размытые края — потеря информации |
| 26 | Качество — **три пресета, автоопределение + ручное** | Деградирует **вид, не данные**: метки, маршруты и комнаты живут на всех пресетах. Демо-карта работает тестом железа ДО покупки |
| 27 | 2D ↔ 3D — **контекст переносится, слои нет** | Едут центр, этаж, выбранная метка. Категории в 3D свои, с нуля — последовательно с №6 |

### 🔑 Находка: Track-1 меняет сценарий маршрутов

**Трекер позиции игрока уже в проде** (`PlayerTracker.tsx`, коммит `06bfbeaf`, 2026-07-08,
[[docs/decisions/done/player-position-tracking.md]]). Читает скриншоты, которые EFT сам пишет
в `Documents/Escape from Tarkov/Screenshots/`, через File System Access API — координаты
лежат в имени файла. Без .exe, без чтения памяти, BattlEye-safe.

Значит маршрут строится не от абстрактной точки, а **от места, где игрок стоит прямо сейчас**,
с автопереключением этажа по мере движения. В плоской карте это не работает: путь через
лестницу на третий этаж на плоскости — линия, упирающаяся в стену.

**Воронка, которую мы не проектировали:** Track-1 бесплатен сознательно (паритет с
Tarkov-Pilot у конкурентов), но проводка от позиции в 3D — премиум. Бесплатная фича
становится входом в платную, причём естественным.

## Поправка: ретопология — не тот инструмент

Автоматическая ретопология (Instant Meshes, QuadriFlow, ZRemesher) строит квад-сетку по
поверхности **одного замкнутого органического меша**. Наша сцена — десятки тысяч
hard-surface инстансов, не-манифолдных, с дырами. Ремешер даёт на них мусор и, главное,
**не тот порядок экономии**. Карты в Doom: The Dark Ages и The Division тоже не ретоплены
автоматически — это отдельные прокси-модели уровня.

### Замеры research (на наших артефактах, не из чужих статей)

- **Экструзия всей застройки:** Развязка 456 тыс. треугольников (худшая), Таможня 367 тыс.,
  Улицы 314 тыс. Страх «Улицы не влезут» относился к геометрии клиента, не к экструзии.
- **Собранный `.glb`:** наземный этаж Таможни — 65 148 tri, **1 draw call**,
  3.91 МБ → **139 КБ** meshopt+brotli (Draco 156 КБ, декодер 73 КБ против 7.5 КБ у meshopt).
- **🔴 Узкое место — подготовка контуров, а не рендер.** 88.8 % контуров мельче 0.5 м².
  Фильтр по площади + Дуглас-Пекер 15 см: **829 510 → 88 774 треугольника (×9.3)**,
  ни один силуэт не потерян.
- **`EdgesGeometry` с инстансингом не работает** (`USE_INSTANCING` ставится только от
  `object.isInstancedMesh`). Но контур считать не нужно: **рёбра призмы = исходный 2D-полигон**,
  он уже во входных данных. `LineSegmentsGeometry extends InstancedBufferGeometry` → вся сеть
  контуров в 1 draw call.
- **`BatchedMesh` ≠ 1 draw call в Firefox** — `WEBGL_multi_draw` там WONTFIX (Bugzilla #1536673).
  Не нужен: merged geometry на этаж честнее.
- **Selective bloom одним проходом через MRT** (`webgpu_postprocessing_bloom_emissive`)
  против официального WebGL-примера с двойным рендером сцены. Главный аргумент за
  `WebGPURenderer` (он сам фолбэчит на WebGL2).
- **`TiltShiftEffect` вместо `DepthOfFieldEffect`** — экранная полоса без depth-текстуры,
  один блюр против семи проходов, ноль артефактов при вращении.
- `SVGLoader` в r185 **умеет** дыры и `evenodd` (`ShapePath.toShapes()` по числу оборота) —
  прежнее утверждение устарело.

### Инфраструктура платности — уже есть

Тиры `free` «Боец» (0 ₽), `operative` «Оперативник» (199 ₽), `veteran` «Ветеран» (449 ₽).

## 🖼 Превью вида (2026-09-06)

![[docs/decisions/3D/preview/customs-floor0-clay.png]]

Наземный этаж Таможни, экструзия из наших контуров, тон по лестнице NIGHTFALL,
Freestyle-контур, светящийся маршрут `--primary` с двумя пинами.
Инструмент: `scripts/eft-map-layers/clay-preview.py` (+ `-blender.py`).

**Это НЕ прототип** — офлайновый рендер Blender, three.js тут ни при чём. Единственная
задача — показать язык до того, как в него вложены дни работы. Что подтвердилось:
приглушённая застройка + светлый контур + одна светящаяся линия читаются ровно так,
как обещали референсы. Маршрут доминирует, не борясь с фоном.

Что в кадре ненастоящее: маршрут — заглушка между двумя крупными постройками
(настоящий строится по графу проёмов), рельефа нет, растительность не отделена.

### Итерация 3: разделение построек и предметов + поэтажность (2026-09-06)

Идея V4DYA — «разделить obstacles на постройки и предметы, потом сделать
поэтажность в общагах». Оба пункта закрыты, но не так, как ожидалось.

**Разделять по форме не понадобилось — нашлась готовая разметка.**
`<карта>-rooms.json` содержит `buildings` с именами и габаритами: **129 построек**
на Таможне (`KPP`, `Market_Small_01`, `obshezhitie_1/2`, `Old_Construction_site`).
Контур внутри bbox постройки — здание, снаружи — предмет. Это точный признак,
а не эвристика.

Проверка осмысленности классификации — доля построек растёт с этажом:

| Этаж | Постройки | Предметы |
|---|---|---|
| `underground` | 49 | **201** |
| `main` | 202 | 313 |
| `2nd` | 104 | 91 |
| `3rd` | **68** | 25 |
| `4th` | **42** | 11 |

Предметы стоят на земле и в подвалах, наверху остаются только конструкции —
ровно то, чего ждёшь от реальной карты.

**🔴 Но `obstacles` не годится для стен зданий.** Он режется поверхностью
«земля+1 м» и заливает силуэты — это работает для отдельно стоящих объектов
(бочки, машины, штабели), а ВНУТРИ здания даёт крошки: в районе общаг крупнейшие
контуры 0.6–1.8 м², и порог шума их выбрасывает. Первый прогон по общагам дал
пустой кадр именно поэтому.

**Стены живут в `walls`, и поэтажность там настоящая.** Я отверг этот слой
рано, посмотрев на всю карту (россыпь обрезков), — в масштабе ЗДАНИЯ те же
сечения складываются в планировку. У общаг:

| Этаж | Контуров | Площадь |
|---|---|---|
| `main` | 482 | 1 946 м² |
| `2nd` | 1 992 | 1 754 м² |
| `3rd` | 892 | 776 м² |
| **`4th`** | **0** | — |

Пусто на четвёртом — здание трёхэтажное, и слой это знает. Совпадает с выводом
замера (`obshezhitie_2` — трёхэтажка h=12.4 м, `obshezhitie_1` — двухэтажка h=9.1 м).

**Итоговая раскладка источников:**
- **стены и планировка** → `walls` по этажам, порог 0.4 м²;
- **предметы** → `obstacles`, порог 2 м², отфильтрованные по bbox построек;
- **классификация** → `buildings` из `<карта>-rooms.json`.

![[docs/decisions/3D/preview/customs-dorms-clay.png]]

Две общаги Таможни с внутренней планировкой — ряды комнат вдоль коридоров.
Чёрных провалов практически нет: они были следствием неверного источника, а не
рендера.

### Поэтажность в кадре

![[docs/decisions/3D/preview/customs-dorms-floors.png]]

Фокус на `2nd`, шаг между этажами растянут (`--explode 2.6`), камера опущена до 34°.

Две вещи, без которых поэтажность не читалась:

1. **Разнести этажи по вертикали.** При реальном шаге 3.2 м и взгляде сверху
   уровни накладываются и сливаются в один силуэт. Растягивается только зазор,
   сами объёмы остаются высотой в этаж — иначе здание перестаёт быть зданием.
2. **Призраки полупрозрачные, а не просто тёмные.** Разницы в яркости материала
   (0.085 против 0.150) не хватало: при общем освещении фокусный этаж и призрак
   сливались. Работает `Alpha = 0.22` — нижний уровень просвечивает сквозь верхний.

Итог: решение №29 («фокус + призраки контуром») проверено на картинке и работает,
но с поправкой — призрак это **полупрозрачный объём**, а не только рёбра.

### Итерация 4: лестницы. Порог шума был ни при чём (2026-09-06)

Замечание V4DYA: «металлических лестниц не видно сбоку общаг, надо снижать порог
шума». Порог действительно был слишком груб, но **лестницы он не вернул бы**.

**Что дал порог.** Фильтр по площади убивал длинные тонкие контуры: у лестницы
в сечении это косоуры и ступени — каждая полоска меньше 0.4 м² при длине 2–5 м.
Замер по общагам: терялось **26 контуров на 1-м этаже и 41 на 2-м**. Фильтр
заменён на «площадь **ИЛИ** габарит» (`--wall-span`, по умолчанию 1.4 м), после
чего число контуров у общаг выросло вдвое (2 299 → 5 163 на `main`) и появились
опоры, перила и решётчатые конструкции.

**🔴 Но сама лестница так не восстанавливается.** `walls` — это сечение на ОДНОЙ
высоте, а маршевая лестница пересекает плоскость реза в одном месте и оставляет
огрызок. Никакой порог этого не исправит: данных просто нет.

**Лестницы надо брать мешами.** В дампе есть объект `Hostel_02_hallway_ladder_01`
(6.9 × 3.4 × 5.8 м), и внутри его габарита лежат **163 экземпляра / 55 388
треугольников** реальной геометрии.

![[docs/decisions/3D/preview/customs-stairs-clientmesh.png]]

Лестничная клетка общаги: дверные проёмы, полотна дверей, козырёк, ступени.
Инструмент: `clay-preview.py --meshes 'ladder|stair'`.

**Это первое практическое подтверждение части C гибрида.** Массовая застройка
идёт экструзией, а то, что экструзией принципиально не выражается — лестницы,
фермы, сложные узлы, — подтягивается настоящей геометрией по маске имени.
Правило отбора получается не «крупное берём мешами», а **«берём мешами то,
что теряется в сечении»**.

Гоча по дороге: дамп клиента в осях Unity (Y вверх), сцена превью — в осях
Blender (Z вверх). Без перестановки `(x, z, y)` лестница ложится набок и кадр
выходит пустым.

### 🔴 Незакрытое: чёрные провалы в крупных помещениях

Перебрано и **не помогло** — восемь гипотез, каждая проверена отдельным прогоном:

1. ngon без явной триангуляции → заменено на `tessellate_polygon`;
2. направление обхода контура → нормализация по знаковой площади;
3. ориентация нормалей → `bmesh.ops.recalc_face_normals`;
4. глухая тень → ambient поднят в 4.6 раза (фон стал светлее, провалы — нет);
5. ручная сборка призм → заменена на модификатор `SOLIDIFY`;
6. вырожденные полигоны → проверено: из 436 ни одного, площади 11–5662 м²;
7. z-fighting совпадающих крышек → крышки разведены по трём высотам;
8. невыпуклые ngon → `bmesh.ops.triangulate` до Solidify.

Наблюдение, которое должно навести: чернеют **именно крупные** помещения
(>300 м²), мелкие рисуются нормально. Похоже, крупные контуры в `rooms` — это
не помещения, а внешние обводы корпусов, и внутри них лежат остальные; но почему
при этом чернеет именно верхняя грань, а не нижняя, я не понял.

**Это дефект превью, не архитектуры.** В боевой сцене геометрия придёт из
экструзии силуэтов по этажам, а не из полигонов помещений. Но диагноз стоит
довести до конца, прежде чем строить веху 1: тот же класс ошибки может всплыть там.

### Гочи Blender, стоившие пяти чёрных кадров

Записаны в шапках скриптов, здесь — списком, потому что каждая стоила отдельной итерации:

1. **`clip_end` камеры по умолчанию 100 м.** Карта в игровых метрах, орто-камера стоит
   в ~3 км — вся геометрия отсекалась дальней плоскостью. Проекция при этом была
   идеальной (`u[0.03..0.97]`), поэтому подозрение долго падало на свет и материалы.
2. **Компоузер через новое API Blender 5** (`scene.compositing_node_group` +
   `NodeGroupInput`) отдавал ПУСТОЙ кадр. Убран: bloom для превью не нужен.
3. **EEVEE в `--background`** без GPU-контекста даёт чёрное. Cycles на CPU работает.
4. **Честный перевод токенов в линейное пространство** добивает и без того почти чёрную
   лестницу NIGHTFALL: #141416 → 0.0065 → 1/255 на выходе. Для превью берём sRGB как есть.
5. **В питоне Blender нет PIL** — первый пробник децимации падал молча именно на нём.
   Маски читаются через `bpy.data.images` + `pixels.foreach_get`.

Плюс: `BLENDER_EEVEE_NEXT` в 5.1 снова называется `BLENDER_EEVEE`, а центр кадра надо
брать по медиане вершин, а не по середине габарита — выносные постройки уводят камеру
в пустое поле.

## Риски и гочи — из нашего же опыта

- `coordinateRotation: 180` — **отражение, а не поворот**. В растре было невидимо
  (статистики к отражению инвариантны), в 3D карта выйдет зеркальной.
- Артефакты, отфильтрованные в 2D, в 3D станут видны: купол неба (заливал 97 % рамки),
  объекты мимо рамки (Терминал), пол, оценённый модой низов.
- В клиенте каждая сцена встречается **дважды** (находка по Терминалу) — счётчики удваиваются.
- **Два режима = соблазн сделать 3D клоном 2D.** Решение №2 существует именно против этого:
  каждая фича, написанная дважды, оплачивается временем навсегда.

## ✅ Веха 0 ВЫПОЛНЕНА (2026-09-06) — гибрид A+C проходит

Инструмент: `scripts/eft-map-layers/decimate-probe.py` + `decimate-probe-blender.py`.
Метод: собрать здание из дампа окклюдеров по bbox из `<карта>-rooms.json` → Blender
Decimate COLLAPSE (тот же класс, что `gltfpack -si`) → орто-рендер силуэта сверху и под
45°/315° → сравнение масок с оригиналом по **IoU** и по длине контура.
Мерили силуэт, а не «качество меша»: в clay без текстур видно ровно его.

### 🔴 Главная находка: децимировать надо ПОСЛЕ отсева мелочи

Первый прогон «всё, что в пятне» (4 994 171 tri, 9 481 экземпляр) уткнулся в пол:
коэффициенты 0.006, 0.003 и 0.001 дали **одинаковые 32 643 треугольника** и силуэт-кашу.

**32 643 / 9 481 = 3.4 треугольника на объект.** Мы жали не единый меш, а девять с
половиной тысяч несвязных, и на пределе каждый схлопывался в вырожденный.

| Вход | Экземпляров | Треугольников | При ~30 тыс. на выходе |
|---|---|---|---|
| Всё в пятне | 9 481 | 4 994 171 | IoU **0.159** — каша, периметр +98 % |
| Фильтр `--min-span 3` | 667 | 744 366 | IoU **0.988** |

Разница в шесть раз по качеству **при том же числе треугольников**.

### Замер по трём зданиям Резерва

| Здание | Вход после фильтра | ≈30 тыс. tri | IoU сверху | IoU 45° |
|---|---|---|---|---|
| Академия (`Reserv_academy_w_kitchens`) | 744 366 | 29 773 | **0.988** | 0.989 |
| Казарма-пешка (`Casarm_right`) | 750 227 | 29 854 | **0.970** | 0.983 |
| Вагоносборочный (`Reserve_train_assembly_factory`) | 825 641 | 33 025 | **0.965** | 0.977 |

При 15 тыс. tri: казарма 0.932 / 0.971, завод 0.953 / 0.960 — годится как дальний LOD.

### Выводы

1. **Часть C гибрида живёт.** Знаковое здание укладывается в **30 тыс. треугольников**
   с сохранением силуэта (IoU 0.965–0.988). Допущение из geometry-audit подтвердилось,
   но **только вместе с предварительным отсевом**.
2. **Порядок операций критичен и идёт в канон:** фильтр по габариту (`min-span` 3 м) →
   децимация. В обратном порядке или без фильтра — обрыв.
3. **Импостеры BSG не нужны.** Наш конвейер даёт тот же результат на любом здании,
   а импостеры есть не у всех и лежат только у карт, которых нет в экспорте (Улицы).
   Решение №30 закрыто: проверять их отдельно смысла нет.
4. Силуэты для визуальной сверки: `.tmp-3d/decimate-shell/`, `.tmp-3d/dec-Casarm_right/`,
   `.tmp-3d/dec-Reserve_train_assembly_factory/`, затенённые — `.tmp-3d/shaded/`.

### 🔴 Что показала визуальная сверка, а IoU скрыл

Первая версия пробника рендерила плоскую маску (FLAT) — по ней считается площадь, но
**узнаваемость по ней оценить нельзя**. Добавлен второй режим (STUDIO с тенями), и на
затенённом сравнении оригинала с `r0.04` видно главное:

- **Архитектура держится отлично.** Корпус, скатная крыша, ряды надстроек на ней, стены,
  дороги — всё читается после сжатия в 25 раз. По зданию децимация практически не видна.
- **Растительность разваливается.** Округлые кроны превращаются в угловатые кристаллы —
  органика переносит quadric collapse куда хуже, чем hard-surface.

**Следствие: растительность нельзя оставлять внутри знакового здания.** Она и бюджет ест,
и вид портит после сжатия. По решению №17 деревья и так рисуются плоскими пятнами —
значит из выборки здания их надо исключать отдельным фильтром, а не только по габариту
(крона крупнее 3 м и текущий `--min-span` её не ловит).

### Долг пробника (не блокирует, но чинить перед продакшеном)

Отбор по bbox из `rooms.json` захватывает куски соседей — на рендерах видны полосы дорог
и часть ограды. Для замера «до/после» это безвредно (набор один и тот же), но для сборки
боевого знакового здания нужен отбор **по сцене** (`path` в `rooms.json` содержит ветку
сцены), а не по прямоугольнику.

### Что это меняет в бюджете

30 тыс. на здание — измеренная величина, а не допущение. При экструзии Таможни
**276 863** tri (исправленное число) и потолке 410 тыс. остаётся ~133 тыс. →
**четыре знаковых здания** полной детализацией, при восьми высокого приоритета.
Разрыв закрывается дальним LOD на 15 тыс. либо повышением потолка сцены.

Офлайн-пайплайн: фильтр контуров по площади (0.5 м²) → Дуглас-Пекер 15 см → экструзия
по этажам → merged geometry на этаж → `.glb` с `EXT_meshopt_compression` + brotli → R2.

Рантайм: `/eft/maps/customs/3d`, `next/dynamic` с `ssr: false` по паттерну
`MapViewerLoader.tsx`, r3f + drei, орто-камера с ограниченным наклоном, clay по лестнице
NIGHTFALL, контуры из исходных 2D-полигонов через `LineSegmentsGeometry`, selective bloom
только на маршруте и метках.

**Замер:** `render.triangles` ≈ 410 тыс. при `render.calls` ≤ 12 и 60 fps.
**Главное:** показать вид V4DYA — все решения грилла про вид, а вида никто ещё не видел.
