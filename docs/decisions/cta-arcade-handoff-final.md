## Что это

Раздел с мини-играми на портале ЦТА — занять игрока, пока он чего-то ждёт.
Игра идёт «внутри» аркадного автомата: фотореалистичное изображение корпуса,
в экран которого подставляется канвас.

Два ракурса:
- фронтальный, автомат целиком — обычный вид в ленте, рядом селектор игр
- клоузап, «игрок наклонился к автомату» — полноэкранный режим игры

Figma: файл Z1c9wK3AtqBrBhSwNt8qZz, секция `CTA - ARCADE GAMES`, нода 2115:1203.

## 1. Ключевое архитектурное решение — не переизобретать

Экран НЕ вырезается из плиты и НЕ маскируется через SVG/clip-path.

Причины:
1. Камера строго по оси, экран — прямоугольник по осям с прямыми углами.
   Проверено по пикселям: верхняя кромка стекла на 827, нижняя на 1786,
   одинаково по всей ширине. Схождения нет ни на пиксель. Маска для такого
   прямоугольника это absolute + overflow-hidden, SVG-маска добавила бы слой
   отрисовки ради нуля.
2. При вырезанной дырке игра оказывается ПОД плитой, и над ней уже ничего не
   положить. А положить надо потемнение по кромке стекла — без него канвас
   читается как вклеенный прямоугольник.

Порядок слоёв:
  1. плита — цельная картинка в потоке
  2. канвас игры — absolute по процентам от плиты
  3. стекло — absolute, pointer-events-none, поверх канваса

## 2. Ассеты

Фронтальная плита готова: 1770x4096, WebP с альфой, 179 КБ.
  -> public/images/arcade/cabinet-front.webp

Клоузап ЕЩЁ НЕ ЭКСПОРТИРОВАН. Взять из ноды `arcademachine_cleanplate_closeup_bg`
(2115:870). Обязательное условие: пропорция файла должна выйти 1.38127.
  -> public/images/arcade/cabinet-closeup.webp

Требования к обоим:
- WebP с альфой, качество ~80. Фон вырезан, силуэт корпуса идёт по прозрачности.
- PNG в репозиторий не класть: исходник фронтальной плиты весит 9 МБ.
- AVIF не использовать: на силуэте альфа плывёт до 22 единиц и на светлом фоне
  даёт ореол по контуру. Экономия 70 КБ того не стоит.
- Не обрезать прозрачные поля. У фронтальной плиты снизу 12 px прозрачной
  полосы, она учтена в пропорции ноды. Кроп сдвинет всю сетку координат.
- Рендерить только через next/image с корректным `sizes`. Прямой <img src> с
  одним размером даёт браузерный даунскейл 1770 -> 280 на мобиле, и точечный
  шрифт ARCADE в маркизе замылит.

Маркиза (лого ЦТА + словомарк ARCADE) ЗАПЕЧЕНА в изображение. Отдельным слоем
не выводится, меняться не будет, под конкретную игру не подставляется.

## 3. Геометрия — обмерено, не пересчитывать

Проценты считаются от плиты, то есть от экспортированной картинки. Проверено
на пяти брейкпоинтах в каждом режиме, значения совпадают до третьего знака —
медиазапросы под координаты НЕ нужны, констант ровно две.

  site        left 15.962%  top 21.035%  height 22.067%
  fullscreen  left 13.801%  top 13.668%  height 75.000%

Ширина НЕ задаётся, вместо неё `aspect-ratio: 4/3` на боксе экрана.
В макете фронтальная рамка имеет пропорцию 1.33526 вместо 1.33333 — дрейф
0.145%, от 0.3 до 0.9 px. Двигать ноды на полпикселя смысла нет, но канвас
обязан быть строго 4:3, поэтому ширину выводим из пропорции. Правый край сядет
на 0.7 px левее макета, это не видно.

Контрольные пропорции плит: site 0.43213, fullscreen 1.38127. Сверить с
фактическим width/height экспортированных файлов. Разойдётся больше чем на
0.001 — экспортировали не ту ноду, координаты поедут.

Проверено по картинке: рамка садится внутрь борта с запасом около 20 px по
каждой стороне. Канвас встаёт на стекло и не задевает фаску.

## 4. Управление

Мышь и клавиатура на десктопе, тап по канвасу на тач-устройствах.

Кнопки, стики и монетоприёмник на плите — ДЕКОРАЦИЯ. Они запечены в
изображение, хит-зон над ними не делать, кликов не вешать, курсор над ними не
менять. Тапают по САМОМУ ЭКРАНУ, не по органам управления.

Реализация: только Pointer Events (`pointerdown` / `pointermove` / `pointerup`).
Одна ветка кода на мышь и тач, отдельных `touch*`-обработчиков не заводить.

Координаты указателя переводятся из CSS-пикселей в логические пиксели канваса
простым масштабом от `getBoundingClientRect()`. Никаких обратных матриц не
нужно — к боксу экрана НЕ применяется ни один transform (см. раздел 6).

### На тачах играть можно ТОЛЬКО в полноэкранном режиме

Считанные размеры:

  мобила, лента          экран 191 x 143 CSS px — тач-цель 44 px это 23% ширины
  мобила, полный экран   экран 320 x 240 CSS px — тач-цель 44 px это 14% ширины

В ленте экран 191 px шириной. Попасть пальцем во что-то мельче четверти экрана
невозможно, играть там нельзя. Канвас в ленте на тач-устройстве НЕ запускается.

Сценарий на мобиле, по макету 2115:890:
1. игрок листает `games-selector` и выбирает игру
2. в экране автомата появляется иконка поворота, канвас ещё не создан
3. игрок поворачивает телефон
4. открывается полноэкранный ландшафтный режим, там игра и идёт

На десктопе ограничения нет, в ленте играется мышью и клавиатурой сразу.

Минимальный игровой элемент в полноэкранном на мобиле — 88 логических пикселей
канваса при разрешении 640x480. Это ограничение для авторов игр, а не для
вёрстки.

### Скролл и зум

`touch-action: none` вешать на бокс экрана ТОЛЬКО когда игра активна и только
в полноэкранном режиме. В ленте страница обязана скроллиться пальцем поверх
автомата, иначе пользователь застрянет.

Плюс на боксе экрана: `user-select: none` и `-webkit-touch-callout: none` —
иначе долгий тап в iOS Safari выделяет область и открывает системное меню.

## 5. Поворот экрана на мобиле

Сценарий: игрок выбирает игру в портретной ленте кнопками, затем получает
экран с просьбой повернуть телефон, и уже в ландшафте играет в полноэкранном.

### Повернуть ПРИНУДИТЕЛЬНО нельзя, и рассчитывать на это не надо

`screen.orientation.lock()` в Safari на iOS не поддерживается вообще, а в
Chrome на Android работает только когда элемент уже в `requestFullscreen()`.
На iPhone программного способа развернуть экран не существует. Поэтому экран
с иконкой — не «пока не сработал лок», а основной и единственный механизм.

Допустимо попробовать `screen.orientation.lock('landscape')` как прогрессивное
улучшение внутри `try/catch`, но поведение обязано быть одинаковым и без него.

### Детект ориентации

Только `window.matchMedia('(orientation: landscape)')` с подпиской на `change`.
Не `window.orientation` — он объявлен устаревшим. Не голый `resize` — на iOS
он срабатывает и при появлении адресной строки, будет ложное срабатывание.

Пока портрет — показывается экран с иконкой поворота. Стало ландшафт —
показывается автомат.

### Тупик, который надо предусмотреть

Если у игрока включена системная блокировка ориентации, он физически не сможет
повернуть экран, и упрётся в иконку навсегда. На экране поворота ОБЯЗАТЕЛЬНА
кнопка выхода назад к списку игр. Без неё это ловушка.

### Ландшафт на телефоне

- высоту считать в `100dvh`, не `100vh`. С `100vh` в iOS Safari адресная
  строка срежет низ автомата.
- `env(safe-area-inset-left)` и `env(safe-area-inset-right)`: в ландшафте
  вырез камеры съедает боковую сторону, и с какой именно — зависит от
  направления поворота. Без отступов челка отрежет край корпуса.
- `navigator.wakeLock` запрашивать на старте игры, отпускать на паузе и при
  уходе со страницы. Иначе экран погаснет посреди партии. Обернуть в
  `try/catch`, поддержка не везде.

### Старт после поворота

Игру запускать НЕ автоматически по факту поворота, а по тапу «Старт». Поворот
занимает секунду-полторы, телефон в это время в движении, и первые кадры
игрок гарантированно пропустит.

Канвас на мобиле создаётся только на шаге 4, уже в ландшафте. Пока игрок в
портрете и смотрит на иконку — игрового модуля в памяти быть не должно, его
догружает `next/dynamic` при входе в полноэкранный.

### Иконка

Нода `rotate-screen-icon` (2116:1487) в мобильном фрейме 2115:890 — уже вектор,
экспортировать как SVG. Цвет линий задать `currentColor`, чтобы иконка брала
токен, а не хардкод. PNG-версию не использовать: у неё непрозрачный чёрный фон,
она ляжет чёрным прямоугольником поверх подложки.

Иконка лежит ВНУТРИ бокса экрана и отцентрована в нём до сотых доли пикселя:
её центр 160.153 / 398.029 против центра экрана 160.153 / 398.030. Поэтому
никаких координат не нужно, достаточно центрирования флексом внутри бокса
экрана.

Размер: 57.6% ширины бокса экрана, высота по пропорции. Собственная пропорция
иконки 1.3095 — не растягивать, `preserveAspectRatio` оставить по умолчанию.

Анимацию поворота глушить под `prefers-reduced-motion`. Рядом с иконкой —
текстовая подпись, одной картинкой обходиться нельзя.

## 6. Игровой цикл и состояние

- Цикл на `requestAnimationFrame`, дельта времени передаётся в кадр. Никаких
  `setInterval`.
- Покадровое состояние живёт в `useRef`, НЕ в Zustand и НЕ в `useState`.
  Иначе каждый кадр перерисовывает дерево.
- В стор уходит только мета: выбранная игра, статус (`idle | playing |
  paused | over`), счёт, рекорд. Стор строго в `src/store/`.
- Пауза обязательна при `document.visibilityState === 'hidden'` и когда
  автомат ушёл из вьюпорта (`IntersectionObserver`). Это виджет ожидания, он
  не должен жечь батарею в фоне.
- `cancelAnimationFrame` в клинапе. Проверить, что при размонтировании не
  остаётся висящих слушателей клавиатуры.
- Пока модуль игры грузится — скелетон `animate-pulse` в габаритах экрана,
  не спиннер.

## 6. ЭЛТ-эффекты

Плита намеренно сгенерирована БЕЗ сканлайнов, кривизны и пиксельной сетки —
эти эффекты живут в слое игры, где их можно настраивать.

Реализовывать ТОЛЬКО как пост-обработку отрисованного битмапа внутри канваса.
Не как CSS-трансформ на элементе: под `transform` ломается попадание кликов,
нужна обратная матрица на каждое событие, а канвас идёт через ресемплинг и
пиксельная графика мылится. При пост-обработке DOM-бокс остаётся честным
прямоугольником 4:3, искажается только картинка.

Перспективу и наклон к боксу экрана НЕ применять. Плита снята строго по оси,
стекло — прямоугольник. Наклонённая игра отойдёт от борта по углам и
прочитается как сломанная вёрстка, а не как аутентичность.

Всё, что мерцает или дрожит, глушить под `prefers-reduced-motion`.

## 7. Контракт игрового модуля

Игры подключаемые, каждая — отдельный модуль с одинаковым интерфейсом.
Логическое разрешение 640x480 у всех, масштабирование делает CSS.
Для пиксельной графики `image-rendering: pixelated` — в полноэкранном апскейл
около x2.25 без сглаживания выглядит намеренным.

  export interface ArcadeInput {
    readonly keys: ReadonlySet<string>;
    readonly pointer: { readonly x: number; readonly y: number; readonly down: boolean } | null;
  }

  export interface ArcadeFrameContext {
    readonly ctx: CanvasRenderingContext2D;
    readonly width: 640;
    readonly height: 480;
    readonly input: ArcadeInput;
  }

  export interface ArcadeGame {
    readonly id: string;
    readonly title: string;
    readonly logo: string;
    init(c: ArcadeFrameContext): void;
    frame(c: ArcadeFrameContext, dtMs: number): void;
    dispose(): void;
  }

Модули игр грузить через `next/dynamic` с `ssr: false` — канвас на сервере
не нужен, а бандл не должен тащить все игры сразу.

Звук, если будет: инициализировать AudioContext только по жесту пользователя,
иначе браузер заблокирует. Мьют по умолчанию, тумблер рядом с автоматом.

Размеры клоузапа проставить после экспорта.

### src/components/ui/ArcadeFrame.tsx

Тупой атом, без клиентского состояния, серверный компонент.
Принимает `view: ArcadeView` и `children` — то, что ляжет в экран.

Критично: плита рендерится ОБЫЧНЫМ элементом в потоке (`block h-auto w-full`),
а не через `fill`. Тогда высота контейнера равна высоте картинки и проценты
всегда точны. С `fill` + `object-cover` при малейшем расхождении пропорции
контейнера координаты уедут.

Бокс экрана: left/top/height из констант, плюс `aspect-ratio: 4/3`, плюс
overflow-hidden. Ширину не задавать.

Слой стекла — CSS-приближение, отдельного ассета не заводить:
`shadow-[inset_0_0_0_1px_rgb(0_0_0/0.6),inset_0_3px_14px_rgb(0_0_0/0.5)]`
плюс `pointer-events-none`.

### src/components/features/arcade/

Хост игры, переключение site <-> fullscreen, селектор, реестр игр.
Zustand только здесь и только через стор из `src/store/`.

Переход site -> fullscreen должен быть чистым scale контейнера: пропорция
экрана одинаковая в обоих режимах, канвас НЕ пересобирается, состояние игры не
теряется. Не размонтировать канвас на переходе.

## 12. Правила проекта

- Next.js 16 App Router, по умолчанию серверные компоненты
- Tailwind v4: `bg-(--color-base)`, не `bg-[var(--token)]`; `bg-linear-to-b`,
  `rounded-xs`, `stroke-3`; если N делится на 4 — класс шкалы (`h-15`)
- только токены дизайн-системы, сырой HEX запрещён
- типографика: тело `font-blender-book`, заголовки
  `font-blender-medium uppercase tracking-widest`, числа
  `font-blender-medium text-xs`; `font-mono` запрещён по всему проекту
- порядок утилит: позиция -> размер -> типографика -> цвет -> брейкпоинты
- FSD-lite: `ui/` тупые атомы, `features/` логика, `layout/` оболочка
- Zustand строго в `src/store/`
- `any` запрещён, для компараторов сортировки `string | number`
- скелетоны `animate-pulse`, никаких спиннеров
- тяжёлые модули через `next/dynamic` с `ssr: false`
- каждый коммит в main обязан проходить `npx tsc --noEmit`

## 13. Чего не делать

- не резать дырку в плите
- не вешать SVG-маску или clip-path на экран
- не применять CSS-перспективу, наклон или любой transform к боксу экрана
- не выводить маркизу отдельным слоем, она запечена
- не делать кнопки и стики на плите интерактивными
- не заводить отдельные touch-обработчики, только Pointer Events
- не вешать `touch-action: none` на автомат в ленте, страница перестанет скроллиться
- не запускать канвас на тач-устройстве в ленточном виде
- не полагаться на `screen.orientation.lock()`, на iOS его нет
- не использовать `window.orientation` и голый `resize` для детекта поворота
- не оставлять экран поворота без кнопки выхода
- не задавать боксу экрана ширину, только aspect-ratio
- не подставлять свои координаты «на глаз»
- не задавать плите `object-cover`
- не пересчитывать проценты под каждый брейкпоинт, они одинаковые
- не обрезать прозрачные поля у плит
- не держать покадровое состояние в Zustand или useState
- не размонтировать канвас при переходе в полноэкранный режим
