# SPEC — `cta-mapper`

> [!info] Как читать
> Заметка написана в отдельном исследовательском чате и самодостаточна: всё,
> на чём держатся решения, изложено здесь, историю того чата поднимать не нужно.
> Вики-ссылки проставлены по предполагаемым именам — сверить с графом хранилища.

> [!warning] Точка стыковки с [[map-stitch]]
> В исследовательском чате скилл `map-stitch` **не был загружен** — его нет в аккаунте
> на момент написания. Поэтому раздел [[#S1 — Сегментация]] спроектирован с нуля.
> Первое, что нужно сделать в основном чате: сверить S1 с тем, что уже зафиксировано
> в `map-stitch`, и выкинуть дубль. Если `map-stitch` описывает **сшивку** тайлов
> в единый растр — он встаёт стадией S0 перед конвейером. Если он описывает **нарезку
> на объекты** — S1 отменяется и заменяется его правилами.

Конвейер: растровая карта → набор векторных объектов в токенах палитры → собранная SVG-карта.
Продолжение ручного пайплайна из [[CTA-MAP-OBJECTS]] (Gemini → трассировка → Figma), но
автоматизированное и без Illustrator.

**Разведка (основной чат):** `map-stitch` = сшивка/нарезка тайлов, не сегментация → S1 остаётся,
дубля нет; VTracer `convertPixels`+`palette` реальны, но **только в `@visioncortex/vtracer@1.0.0-alpha.3`**;
`gemini-3-pro-image` реален и уже в репо (`scripts/gemini-upscale-icon.mjs`), **SDK не нужен — сырой REST**;
`gemini-3.1-flash` **не существует**; «слот style-reference только у Pro» — **ложь наоборот**;
целевые токены `--object-*`/`--cnt-*` в `globals.css` **отсутствуют**.

### Решения

| # | Развилка | Выбор |

### Изменённый конвейер

`S0` fetch (`fetch-tiles.mjs`) → `S1` сегментация + физ-порог + грубый угол → `S2` гейт неоднозначности →
`vision` `{typeKey, material, subjectSeed, clutter}` → `S3` кластеризация по типу → `S5` ручной финальный
`subject` на ~12 кластеров → `S6` Pro 4K, слова+число+анкер → `S7` VTracer palette-lock (сабсет материалов
объекта) → `S8` сборка `<symbol>`+`<use>`, только Figma-версия. *(vision переехал ДО кластеризации.)*

### Палитра — материальная, Завод-выверенная (замена «12 хексов»)

### OKLab-замер — выводы (2026-08-13)

60 цветов, 1710 межсемейных пар. **Палитра валидна при сабсет-дисциплине S7.** Тени контейнеров
углублены (Blue `#284559`→`#102737`, Red `#5C2E29`→`#33130F`, Green `#4A482A`→`#272D0A`) — их
SH→DEF вырос до **0.185 / 0.211 / 0.293** (было 0.07 / 0.09 / 0.15), объём читается; новых коллизий
тени не создали.

- **Правило S7 (жёсткое):** объект трассируется только против сабсета своих материалов + нейтрали + матовый. 28 пар ближе 0.040 — полный 60-список снапнет в кашу.
- **Watch-list гейта** (близки И реально co-occur): нейтрали Concrete/White-Plastic/Rubber/Wooden (0.023–0.034) и тёмно-зелёные Khaki/Green-Mil/Green-Container (0.033–0.035). 2+ из группы в одном сабсете → метка «могут слиться, доцветить в Figma».
- **Самые близкие пары (0.012–0.022) — межкатегорийные** (техника↔террейн: Khaki/Swamp/Dirt): в один объект-сабсет не попадают, база карты тулом не рисуется.
- **Матовый:** до ближайшего цвета палитры magenta **0.240** vs green **0.119** → маджента вдвое безопаснее, оставлена.

## Модель данных

Единственный источник правды — `mapper.json` рядом с исходной картой. Каждая стадия читает его
и дописывает своё поле. Падение на 30-м объекте не роняет первые 29.

```ts
// src/lib/mapper/types.ts
export type ObjectType = 'isolated' | 'tile';
export type Matte = 'magenta' | 'green';
export type Stage = 'segmented' | 'described' | 'generated' | 'traced' | 'rejected';

export interface MapperObject {
  id: string;                    // sha1(bbox+mapId).slice(0,8)
  bbox: { x: number; y: number; w: number; h: number };
  angle: number;                 // градусы, на которые кроп повёрнут ПЕРЕД отправкой
  pixelCount: number;
  dedupKey: string;              // dHash нормализованного кропа
  isDedupSource: boolean;        // false → переиспользует SVG объекта с тем же dedupKey
  type: ObjectType;
  matte: Matte;                  // из гистограммы кропа, не из ответа модели
  subject: string | null;        // англ. строка в слот {SUBJECT}
  stage: Stage;
  paths: { crop?: string; generated?: string; svg?: string };
  error?: string;
}

export interface MapperManifest {
  mapId: string;
  source: string;
  sourceSize: { w: number; h: number };
  background: string;                // #rrggbb, определён автоматически
  palette: string[];                 // 12 хексов
  tokenMap: Record<string, string>;  // '#4E5A3A' → 'mass-deck'
  anchorPath: string | null;
  objects: MapperObject[];
}
```

## Стадии

### S1 — Сегментация

Сверить с [[map-stitch]] прежде чем писать код.

1. Декод в RGBA через `sharp().raw().ensureAlpha()`.
2. **Фон определяется, а не хардкодится:** модальный цвет пикселей по периметру кадра.
3. Маска фона: евклидово расстояние в RGB ≤ `bgTolerance` (дефолт 12) — порог нужен из-за
   сглаживания и артефактов PNG.
4. Морфологическое замыкание маски 2px заклеивает разрывы по сглаженному контуру.
   Пиксели при этом не меняются, замыкание работает только по маске.
5. Связные компоненты — **итеративная заливка с явным стеком `Int32Array`**, не рекурсия:
   на карте 12000×12000 рекурсия положит стек.
6. Отбраковка компонент < `minArea` (дефолт 400px).
7. Кроп по bbox. Пиксели чужих компонент внутри bbox заливаются фоном — иначе сосед
   протечёт в силуэт.
8. Угол: `minAreaRect`. Неоднозначность ±90° разрешается правилом «высота ≥ ширины»,
   одинаково для всего набора. Поворот применяется к кропу, угол пишется в манифест.

Сегментация неизбежно ломается на двух случаях: соприкасающиеся объекты слипаются в одну
компоненту, объект из несвязных частей распадается на две. Отсюда гейт S2.

### S2 — Ревью сегментации (гейт)

Грид превью. Действия: **merge** (объединить bbox выделенных), **reject**, **toggle type**,
**toggle normalizeRotation**. Split не делаем — расщеплённый объект проще отклонить и
вырезать руками, чем строить под это UI.

### S3 — Дедуп

> ▲ Протокол (решение 2): первичный ключ схлопывания — **`typeKey`** от vision-прохода, не dHash. dHash остаётся вторичным сигналом слияния заведомо идентичных экземпляров ВНУТРИ типа. Генерим один канон на тип, а не на бакет внешнего вида.

dHash 16×16 по нормализованному кропу, бакеты по расстоянию Хэмминга ≤ 4. Один объект бакета —
`isDedupSource: true`, остальные ссылаются на него.

**Главная экономия.** На игровых картах ассеты повторяются десятками: 400 найденных объектов
реалистично схлопываются в 50–80 уникальных. Бюджет считается по уникальным, в SVG они идут
через `<symbol>` + `<use>`.

### S4 — Описание

`gemini-3.1-flash`, вход = кроп, выход = строгий JSON `{ name, subject, type }`.
`matte` берётся из гистограммы кропа (есть ли пиксели в hue 60–180°), а не из ответа модели —
код определяет точнее.

### S5 — Ревью описаний (гейт)

Таблица «превью | subject | type | matte», subject редактируется inline.
Неверное имя объекта = неверный силуэт на выходе. Самая дорогая ошибка конвейера, ловится
только глазами.

### S6 — Генерация

> ▲ Протокол (решения 3, 5): генерим от **слов + пропорция-числом + анкер**; кроп — НЕ вход генерации, а замер S1, вкладывается лишь как фолбэк для непроизводных пропорций. Промт даёт **одну материальную триаду** (SHADOW/DEFAULT/HIGHLIGHT), не список 60 цветов. Модель одна — `gemini-3-pro-image`; фаза Flash-анкера убрана.

`gemini-3-pro-image`, 4K, 1:1. Первым вложением кроп (GEOMETRY SOURCE), вторым анкер
(STYLE ANCHOR), роли названы словами внутри промта. Тело промта — [[CTA-MAP-OBJECTS-vector-prompts]],
подставляются `{SUBJECT}`, `{MATTE}`, `{PALETTE}`.

Конкурентность 2–3, экспоненциальный бэкофф на 429. Кэш по `sha1(crop + promptText)` —
повторный прогон не тарифицируется. Обрезка угла с меткой SynthID.

### S7 — Трассировка

У VTracer есть опция **`palette`** — список `#rrggbb`. Отдельный проход квантования не нужен,
хексы на выходе ровно те, что мапятся в токены [[NIGHTFALL]].

```ts
vtracer.convertPixels(rgba, w, h, {
  palette: [...manifest.palette, MATTE_HEX],
  hierarchical: 'cutout',        // бесшовная мозаика без наложений
  mode: type === 'tile' ? 'polygon' : 'spline',
  simplify: type === 'tile' ? 2.0 : 1.2,
  filterSpeckle: 16,             // при 4096px порог 1/40 = 102px, 16 безопасно
  cornerThreshold: 60,
  optimize: 2,
  pathPrecision: 1,
});
```

Дальше: удалить пути с заливкой матового цвета, переименовать заливки в токены, проставить
`id` группам (Figma читает `id` как имя слоя).

**Почему выбор матового цвета важен второй раз:** сглаженные пиксели на границе снапятся к
ближайшему цвету палитры. Если матовый максимально далёк по тону от всей палитры, они уходят
либо в цвет объекта, либо в матовый — третьего не появляется, бахромы нет. Зелёный рядом с
оливой такой гарантии не даёт, отсюда маджента по умолчанию.

### S8 — Сборка

`<symbol>` на каждый `isDedupSource`, `<use transform="translate(x y) rotate(-angle)">` на
каждое вхождение. Угол из манифеста с обратным знаком — растр повёрнут один раз, обратный
поворот вектора точен.

Два выхода: Figma-версия (литеральные хексы, `id` = имя слоя) и web-версия (CSS-переменные).
