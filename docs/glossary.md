# Глоссарий ЦТА

Единый словарь терминов портала. **Правило: новый термин в UI или в имени поля БД сначала попадает сюда, потом в код.**

Зачем: без словаря одно и то же называется по-разному в макете, в базе и в интерфейсе, и расхождение всплывает уже после коммита. Реальный случай — блок эффектов предмета: сначала `medEffects` и «Медицинские эффекты», через два часа выяснилось, что эффекты есть у еды и ножей, и пришлось переименовывать семь файлов уже после пуша.

Процесс: [[engineering-loop]] · Правила кода: `../CLAUDE.md`

## Портальные термины (все игры)

| Термин | Значение |
|---|---|
| **Зеркало** | Наша копия игровых данных в Supabase. UI читает **только** его — рантайм-фетч наружу запрещён (CLAUDE.md §4.11) |
| **Синк** | Серверный крон, наполняющий зеркало из внешнего источника (`/api/cron/sync-*`, `scripts/sync-*.ts`) |
| **Дамп** | Разовый серверный сбор данных в файл-каталог. В отличие от синка запускается руками, а не по расписанию (`scripts/dump-*.mjs`) |
| **Каталог** | `public/images/items/eft/items_database.json` — промежуточный файл между дампом и базой. В базу его льёт `npm run db:etl` |
| **Макет** | Фрейм в Figma. Источник **раскладки**, но не данных: цифры берём из зеркала, при расхождении выигрывает игра |
| **Плитка** (tile) | Горизонтальный блок 48px: иконка, подпись слева, значение справа |
| **Строка** (row) | Строка списка 24px: иконка 24, подпись, уточнение, значение справа |
| **Реестр иконок** | `src/styles/icons.css` — все классы `.icon-*`, импортируется первой строкой `globals.css` |
| **Маска против растра** | SVG-иконка красится через `bg-*` (это маска), цветной webp рисуется через `icon-bg` (это фон). Перепутать → залитый одноцветный квадрат |
| **Открытие (комнаты)** | Одна заявка сообщества: игрок открыл меченую/цветную комнату и записал, что выпало. В статистику идёт только с пруфом и после модерации. Код: `room_opens` |
| **Пруф** | Скриншот или видео-доказательство открытия (видны версия игры, дата, FIR-метка). Скрин — во временное хранилище, удаляется сразу после модерации; видео — только ссылкой на YouTube |
| **Репутация** | Очки за принятые модератором вклады (напр. открытие комнаты). Леджер `reputation_events`, баланс = сумма дельт; обмен на бонусы портала (Premium) — через энтайтлменты |
| **Чекпоинт** | Снимок прогресса на сервере в **фикс-слоте**, к которому игрок возвращается с любого устройства. Слоты: **3 ручных** (1–3) + **1 авто** (0, пишется перед restore/сбросом — страховка-undo). Сохранение = upsert по слоту. Отличать от живого авто-синка (`quest_progress`, одна перезаписываемая строка = текущий стейт) и от файлового экспорта/импорта (офлайн-бэкап). Код: `cta_quest_checkpoints` (колонка `slot`) |

## Escape from Tarkov

| Термин | Значение |
|---|---|
| **Ресток** | Обновление ассортимента у торговца по таймеру |
| **FIR** (Found in Raid) | «Найдено в рейде» — метка предмета, обязательная для части квестов |
| **Цель квеста** (objective) | Одно требование квеста; тип по `__typename` (`TaskObjectiveItem` — сдать/найти предметы; `Mark`/`Shoot`/`PlayerLevel`/`TraderLevel`/`Basic` — прочее). Item-цель трекается счётчиком предметов, остальные — галкой |
| **Завершение цели** | Item-цель завершена ⟺ счётчик `itemProgress ≥ нужного`; прочие ⟺ прожата галка (перс. `checkedObjectives`, только localStorage — Tier 1). Галка item-цели = заполнить/обнулить счётчик. **Авто-закрытие**: все цели завершены → квест закрывается (`toggleQuest`); откат цели → авто-реопен (если закрылся авто) |
| **Бартер** | Обмен предметов у торговца без денег |
| **Крафт** | Производство предмета в убежище |
| **Воронка добычи** | Движок `src/lib/acquisition-funnel.ts`: рекурсивно сравнивает все способы получить предмет (покупка у торговца / барахолка / бартеры по LL / крафты) и для каждого инпута спускается «а его дешевле добыть иначе?», пока не упрётся в лист. Возвращает теоретический минимум ₽ и дерево выбранного пути. Граф из зеркала — `src/db/acquisition-funnel.ts` |
| **Выгодный источник** | Оптимальный (самый дешёвый) путь получить предмет прямо сейчас: сравнение покупки у торговца / барахолки / бартеров по LL / крафтов рекурсивно по инпутам (движок `src/lib/acquisition-funnel.ts`, «воронка добычи»). Первое применение — топливо в калькуляторе биткоин-фермы (`/eft/progress/hideout/bitcoin-profit`), рендерится теми же карточками бартера/крафта, что и страница предмета |
| **SPT** | Single Player Tarkov — источник снимка игровой базы (`items.json` + `globals.json`). Автономная альтернатива api.tarkov.dev |
| **Стим-бафф** | Эффект инъектора из `globals.json` → `Health.Effects.Stimulator.Buffs`. В api.tarkov.dev их нет |
| **Эффект предмета** | Нормализованные эффекты в зеркале. Покрывает медикаменты, провизию и холодное оружие |
| **Меченая комната** | Запертая комната под «маркированный ключ» с ценным лутом (общаги Таможни, Резерв, Улицы…). На карте — подсвеченные границы, по клику — страница с лут-таблицей и экономикой ключа. Код: `marked_rooms.kind='marked'` |
| **Цветная комната** | Комната Лаборатории под цветную ключ-карту (чёрная/фиолетовая/зелёная…). Тот же модуль, что меченые. Код: `marked_rooms.kind='lab_color'` + `color` |
| **«Я в рейде»** | Эфемерная read-only линза: скрин экрана инвентаря (Tab) → матч иконок против наших 5044 канонических → бюджет по барахолке + флаги нужности (квест/убежище/«уже сдавал»/FIR). **Ничего не пишет** (Tab-скрин = что несёшь, а не что вынес). Синк-термины «Найдено в рейде»/«Твой схрон» — v2, ещё НЕ определены (не плодить раньше кода). План: [[Я в рейде — киллер-фича]] |
| **Лут-пул** | Editorial-маркер карты категории «Лут», где один спот = **несколько** возможных предметов (напр. в одной точке спавнится разный плакат). Хранение — `meta.lootItems: string[]` в `markers` (`source='user'`); `category = lootItems[0]` (иконка капли + обратная совместимость со старыми одиночными метками). На карте — капля с бейджем **«+N»** (N сверх первого), в карточке-показе — список «Возможные предметы», поиск на локации находит спот по **любому** предмету пула (не только по заголовку). Код: `EditorialMarkerCard` (визард-мультивыбор), `editorial-bridge.ts` (`lootItemNames` для поиска) |

## Имена в коде

| Имя | Где | Значение |
|---|---|---|
| `properties_raw` | `item_properties` | Сырьё tarkov.dev плюс наши добавки. Из него читает карточка предмета |
| `itemEffects` | внутри `properties_raw` | Эффекты предмета. **Бывший `medEffects`** — переименован, когда охват вышел за медицину |
| `LIVE_FIXES` | `scripts/dump-item-effects-spt.mjs` | Правки, проверенные в живой игре поверх отстающего снимка SPT. Живут в дампе, а не в UI — чтобы источником правды осталось зеркало |
| `target: true` | внутри `itemEffects` | Эффекты вешаются на цель, а не на владельца (холодное оружие) |
| `marked_rooms` | новая таблица | Реестр меченых/цветных комнат: сущность страницы + границы подсветки на карте. Сид из `map_markers` (lock, `lockKind='marked'`) |
| `room_opens` / `room_open_items` | новые таблицы | Заявка-открытие + её предметы (M:N). Витрина «последние 100 approved» → пересчёт шанса выпадения |
| `reputation_events` | новая таблица | Леджер репутации (`delta`+`reason`). Баланс = `sum(delta)` |
| `lootItems` | `markers.meta` (jsonb) | Массив itemId лут-пула. Таблицу `markers` не трогали (frozen-снапшот) — пул живёт в уже существующей `meta jsonb`; `category = lootItems[0]` дублирует первый для иконки/back-compat |
| `lootItemNames` | `MapViewMarker` (рантайм) | Имена предметов пула, срезолвленные из каталога на сервере (`page.tsx`) — чтобы поиск на локации матчил по каждому. Аддитивно: у не-пул меток поля нет |

## Что делать при новом термине

1. Проверить, нет ли уже похожего здесь — половина конфликтов это два имени для одного.
2. Решить охват заранее: «медицинские эффекты» звучало точно, пока не выяснилось, что эффекты есть у еды и ножей. Спрашивать себя: это про весь класс явлений или про частный случай?
3. Записать сюда, потом использовать в коде и UI.
