# ПЛЕЙБУК: АРХИТЕКТУРА АГЕНТОВ В CLAUDE CODE (CTA)

Это не абстрактная теория, а рабочая шпаргалка: **какой паттерн под какую задачу и каким инструментом его исполнять**. Основа — канон Anthropic «Building Effective Agents», примеры — из проекта CTA.

---

## 1. БАЗОВЫЕ ПРИНЦИПЫ

- **Agent, не чат.** Цикл: задача → выбрать инструмент → оценить результат → следующий шаг. Не «болтать», а действовать и проверять.
- **Начинай с простого (Workflow), а не с автономии.** ~80% задач — это фиксированный путь шагов (Workflow). Полную автономию (агент сам решает ветвление) включай только там, где путь заранее неизвестен. Лишняя автономия = «чёрный ящик» и слив токенов.
- **Контроль контекста.** Окно ограничено. Большие разноплановые задачи дроби и изолируй в субагентов — иначе галлюцинации и потеря правил (CLAUDE.md).
- **Анти-рекурсия (важно).** НЕ перепроверяй «для надёжности» по кругу, если паттерн Evaluator-Optimizer не задан явно. Одна проверка с чёткой целью — да; бесконечный цикл «ещё разок» — нет.

---

## 2. РЕАЛЬНЫЕ ПРИМИТИВЫ (что есть в Claude Code СЕЙЧАС)

Выбирай минимально необходимое, не всё сразу.

| Примитив | Инструмент | Когда |
|---|---|---|
| **Skills (Навыки)** | `Skill` + авто-триггер по описанию | Типовые повторяемые задачи со своими правилами. **Это и есть «реестр» (RULE 05 устарел — отдельный `registry.md` не нужен): скиллы авто-роутятся по описанию.** В CTA: `cta-backend`, `nightfall`, `figma`, `tarkov-api`, `scaffold`, `page`, `tw-fix`, `refactor`, `project-index`. |
| **Subagents (Субагенты)** | `Agent` (типы: `Explore`, `Plan`, `general-purpose`, `claude`…) | Изолированный контекст под подзадачу. Несколько в ОДНОМ сообщении = параллельно. `Explore` — read-only разведка; `Plan` — проектирование. |
| **Workflow (Оркестрация)** | `Workflow` | Детерминированная многоэтапка: `pipeline()` (цепочка без барьеров), `parallel()` (барьер), фан-аут на десятки агентов, циклы. Требует явного opt-in («ultracode»/прямая просьба). |
| **Hooks (Хуки)** | `settings.json` | Авто-поведение в жизненном цикле («каждый раз когда X»), точки апрува. Настраивается скиллом `update-config`. |
| **MCP** | внешние tools через `ToolSearch` | Связь с внешними данными/API (Notion, Figma, БД). Тулзы грузятся по запросу. |
| **ToolSearch** | `ToolSearch` | Подгрузка отложенных инструментов по имени/ключевым словам перед вызовом. |
| **Plan Mode / TodoWrite** | встроенные | Plan mode — исследовать+согласовать ДО правок; TodoWrite — трекинг многошаговой работы. |

## 3. 5 ПАТТЕРНОВ → ИНСТРУМЕНТ → ПРИМЕР ИЗ CTA → КОГДА

1. **Prompt Chaining (Цепочка).** Выход шага = вход следующего.
   - *Инструмент:* `pipeline()` в Workflow ИЛИ последовательные фазы.
   - *Пример CTA:* research карт — `читать источник → дистиллировать поля → синтез дизайна`.
   - *Когда:* задача линейна и каждый шаг зависит от предыдущего.

2. **Routing (Маршрутизация).** Анализируешь вход → направляешь в нужный пайплайн.
   - *Инструмент:* **Skills** (авто-триггер). `CLAUDE.md` — верхнеуровневый путеводитель.
   - *Пример CTA:* работа по `src/db/*` → авто-скилл `cta-backend`; стилизация → `nightfall`; GraphQL к tarkov.dev → `tarkov-api`.
   - *Когда:* всегда на старте — определи тип задачи и нужный скилл, не сканируй всё подряд.

3. **Parallelization (Параллелизм).**
   - *Sectioning:* разбей на независимые куски, запусти агентов разом.
     - *Инструмент:* несколько `Agent` в одном сообщении (или `parallel()` в Workflow).
     - *Пример CTA:* **3 `Explore`-агента параллельно** размечали бартер-кросс-линки (карточка предмета / модель данных / квест-карта) — карта поверхности за один проход.
   - *Voting:* сгенерь N вариантов → выбери/сведи лучший.
   - *Когда:* части независимы; нужна широта или несколько мнений.

4. **Orchestrator-Workers (Оркестрация).** Дирижёр раздаёт подзадачи воркерам и собирает итог.
   - *Инструмент:* `Workflow` (фан-аут + синтез).
   - *Пример CTA:* воркфлоу `maps-phase4-scope` — 4 разведчика (схема tarkov.dev / рендер the-hideout / наш код / объём-лицензия) → агент-синтезатор → дизайн-документ.
   - *Когда:* сложное ТЗ дробится на параллельные специализированные куски с финальной сборкой.

5. **Evaluator-Optimizer (Генератор-Критик).** Один создаёт, второй жёстко оценивает; цикл до одобрения.
   - *Инструмент:* агент-скептик (в Workflow — стадия `verify` после `find`).
   - *Пример CTA:* контент кодекса — research-агент собрал лор → **адверсариальный фактчек** (скептик пытается опровергнуть) → только подтверждённое пошло в статьи. Так же: «проверь находку, прежде чем утверждать».
   - *Когда:* цена ошибки высока (факты, безопасность, необратимые операции). **Только тут разрешена управляемая рекурсия.**

## 4. РЕШАЮЩЕЕ ДЕРЕВО (дано задачу → что брать)

- Задача типовая, есть скилл? → **Skill** (Routing). Ничего больше не надо.
- Нужно понять незнакомый код/широкую область? → **`Agent: Explore` ×N параллельно** (Sectioning).
- Линейная многошаговка с зависимостями? → **pipeline** (Prompt Chaining).
- Большой аудит/миграция/research с фан-аутом? → **Workflow** (Orchestrator-Workers) — но только с явным opt-in.
- Высокая цена ошибки (факты/безопасность/`db:push`)? → добавь **Evaluator-Optimizer** (скептик-проверка).
- Тривиальная правка (typo, один файл)? → **просто сделай сам**, без агентов и воркфлоу.

## 5. РОУТИНГ В ЭТОМ ПРОЕКТЕ (вместо `registry.md`)

- **`CLAUDE.md` (корень) — верхнеуровневый путеводитель.** Читается всегда. В нём роли, тех-стек, правила (FSD-lite, NIGHTFALL-токены, **правило 11 BACKEND AUTONOMY**, опасность `db:push`) и указатели на скиллы (`/nightfall`, `/tw-fix`, `/scaffold`, `/tarkov-api`…).
- **Skills = живой реестр.** 12 скиллов авто-срабатывают по описанию — это и есть триггер-роутинг из RULE 05, реализованный нативно. Отдельный `registry.md` дублировал бы их и устаревал бы.
- **Память** (`~/.claude/.../memory/MEMORY.md`) — кросс-сессионный контекст (состояние спринтов, решения). Аналог «переиспользования контента между средами» (RULE 06).

---

## 6. БЕЗОПАСНОСТЬ И АНТИ-ПАТТЕРНЫ

- **Не уходи в рекурсию** без явного Evaluator-Optimizer (см. §1).
- **`db:push` (`--force`) — необратимая операция**, сносит RLS/триггеры/FK. Только с подтверждения владельца при нём на связи; после — сразу `db:sql`. В автономном/ночном режиме — НЕ запускать.
- **Backend autonomy (правило 11 CLAUDE.md):** UI читает только нашу Supabase; рантайм-вызовы `api.tarkov.dev` запрещены (единственная точка — крон). Новый датасет → mirror-таблица + синк.
- **Чужая логика/конфликты:** при работе в общем дереве учитывай возможные конфликты; если чужая логика конфликтует — остановись и согласуй.
- **Приоритет архитектуре, а не уговорам.** «Думай лучше / не ошибайся» не работает; работает правильный выбор паттерна и инструмента.
