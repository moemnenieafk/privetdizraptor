# SPRINT (план): проверка ракурсов и материалов иконок по категориям

> Статус: **PLANNED** — отдельный спринт после базового рендер-пайплайна (`docs/SPRINT-ICON-RENDER-PIPELINE.md`).
> Заведён 2026-06-24 по наблюдению V4DYA: у золотой цепи ракурс/pivot отличается → нужна СИСТЕМАТИЧЕСКАЯ сверка углов и материалов по категориям, а не починка по одному предмету.

## Зачем

Базовый пайплайн рендерит иконку из бандла (меш + PreviewPivot.Icon + текстуры). Камера-конвертация `Icon.rotation` Unity→Blender = raw `Quaternion(w,x,y,z)` подошла под батарейку (наклон −51° vs эталон −41°, ~10°). Но:
- **`Icon.rotation` у КАЖДОГО предмета свой** (художники BSG задают позу индивидуально). Наш пайплайн читает его per-item → ракурс ДОЛЖЕН совпадать, ЕСЛИ конвертация универсальна. Надо доказать это по всем категориям, а не на одном примере.
- Золотая цепь даёт другой ракурс → возможно (а) остаточная ошибка конвертации, зависящая от ориентации, (б) влияние `pivotRotation`/трансформа меша, (в) просто иная поза, и проблема в материале, а не угле.

## Известные проблемы (вход в спринт)

1. **Выбор материала (НЕ угол).** У предметов с НЕСКОЛЬКИМИ материалами `extract_item.py` берёт `m_Materials[0]`, который может быть ТЕНЕВЫМ/прокси (`SHADOW_2SIDED`, `SHADOW_BACKFACE`, `shadow_03` …) без `_MainTex` → предмет рендерится тускло/без текстуры. Пример: золотая цепь — реальные текстуры `chain_d`(albedo)+`chain_nrm`(normal) есть, но взялся `SHADOW_*`. **Фикс:** выбирать материал с непустым `_MainTex`, пропускать `*shadow*`-материалы; поддержать мультиматериал/субмеши.
2. **Металлы (золото/сталь).** Кастомный EFT-шейдер: `_Shininess`, `_SpecColor`, `_SpecVals`, `_DefVals`, `_ReflectColor`, `_Cube`. У части материалов — стандартный Unity (`_Metallic`/`_Glossiness`/`_GlossMapScale`). Сейчас рендер считает всё диэлектриком → металл тусклый. **Фикс:** metalness из материала + извлечь `_Cube`-кубмапу (есть в `Windows.json`.Dependencies → `cubemaps`) как world-окружение/рефлекс.
3. **Ракурс per-item.** Проверить универсальность конвертации камеры по категориям; найти, нужен ли учёт `pivotRotation`/`scale`/трансформа меша.
4. **Edge-case текстур** (сигареты — `_MainTex` не нашёлся): связано с (1), мультиматериал.

## Метод (прогон по категориям)

Категории EFT (по `content/items/`): `ammo`, `barter`, `containers`, `equipment` (armor/rig/headwear/headphones/facecover/visobserv), `food`, `meds`, `mods`, `money`, `quest`, `infosubject`(notes), `spec`, `weapons`.

1. **Выборка:** 3–5 репрезентативных предметов на категорию (с известным `template-id` и эталоном tarkov.dev 512px).
2. **Рендер:** прогнать через пайплайн (`extract_item.py`→`render_item.py`).
3. **Авто-сверка:**
   - угол наклона силуэта (моменты изображения) наш vs tarkov.dev → таблица отклонений по категориям;
   - визуальный монтаж per-category (наш | tarkov.dev).
4. **Диагностика:** систематический сдвиг угла в категории? проблема материала? металл? Зафиксировать паттерн.
5. **Фикс по категории** → перепригон → подтверждение.
6. **Метрика готовности:** медианное отклонение угла ≤ ~5° и визуальное совпадение материала по всем категориям.

## Деливераблы спринта

- `scripts/icon-render/verify_angles.mjs` (или .py) — харнесс: список {id,category} → рендер → сверка угла с tarkov.dev → таблица + монтажи по категориям.
- Доработка `extract_item.py`: выбор реального материала (skip shadow, по `_MainTex`), мультиматериал, spec/gloss + metallic из материала, извлечение `_Cube`.
- Доработка `render_item.py`: metalness + cube-environment.
- Отчёт: таблица «категория → Δугла, статус материала/металла».

## 🎯 ПИКСЕЛЬ-ТОЧНЫЙ ПОДХОД: Unity (родной движок) — основной; Blender — фолбэк

Решение V4DYA (2026-06-24): для пиксель-точности рендерить в РОДНОМ движке Unity (как у EFT), а Blender-Python оставить быстрым фолбэком. Почему Unity снимает ОБА узких места разом:
- **Ракурс — точно:** координаты те же, `Icon.rotation` ставится в камеру БЕЗ конвертации (в Blender была приблизительная конвертация Unity→Blender — источник остаточных ~10° и расхождения цепи).
- **Материалы/металл — точно:** грузим РЕАЛЬНЫЕ шейдеры EFT (бандл `shaders`) + `cubemaps` → металл/золото/стекло как в игре, без PBR-аппроксимации и без ручного выбора материала под Blender.

**Версия:** EFT = Unity **2022.3.43f2**; ставим **2022.3.43f1** (в архивах Hub нет f2; f1↔f2 = микро-патч, бандлы/шейдеры совместимы). Unity 6 НЕ годится — шейдеры 2022.3 в нём не заработают.

**Реализация (готово, ждёт установки Unity для прогона):**
- `scripts/icon-render/unity/IconRenderer.cs` — C# batch-рендер: грузит бандл+зависимости (вкл. `shaders`/`cubemaps`), инстанцирует префаб, камера по Icon-параметрам (нативно), 512px прозрачный PNG.
- `scripts/icon-render/render_unity.mjs` (`npm run icons:render-unity`) — драйвер: resolve→extract(meta: prefabName/bundle/deps/icon-params)→jobs.json→Unity batch→PNG[→webp/upload]. Создаёт Unity-проект сам, кладёт скрипт в `Assets/Editor/`.
- `extract_item.py` дополнен: пишет в meta `prefabName`/`bundleKey`/`depKeys` для Unity.
- Запуск: `Unity.exe -batchmode -quit -projectPath <p> -executeMethod IconRenderer.RenderBatch -jobsFile jobs.json` (БЕЗ `-nographics`).
- **Прогон выполнен (2026-06-24):** ✅ шейдеры EFT загружаются в 2022.3.43f1 → материал точный (сочный, как tarkov.dev). ✅ **КАМЕРА РЕШЕНА ПИКСЕЛЬ-ТОЧНО**: перебрал 6 моделей композиции, замер наклона силуэта по моментам vs tarkov.dev. **Победитель — mode 5: предмет=identity, камера=`Quaternion.Inverse(Icon.rotation)`** → отклонение **0.0°** (батарейка −40.9° = эталон −40.9°), визуально 1:1. Вывод: `Icon.rotation` = поворот ОТ камеры К предмету, камере нужен ОБРАТНЫЙ (поэтому в Blender с «как есть» был остаток ~10°). `pivotRotation` в режиме иконки НЕ участвует (возможно — для 3D-инспекта). Зафиксировано в `render_unity.mjs` (`cameraMode:5`).
- **Осталось проверить per-категория:** универсален ли mode 5 (или часть категорий требует pivotRotation); освещение иконочной сцены BSG (сейчас ambient+directional — батарейка чуть темнее tarkov.dev); прозрачность альфы opaque-шейдеров.

## Не-цели

- Микрокосметика (точная насыщенность) — после геометрии/материала.
