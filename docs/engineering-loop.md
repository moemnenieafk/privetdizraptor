# Инженерный цикл ЦТА (как мы с Claude работаем)

**Цель:** меньше токенов за сессию, точные результаты, человек в петле.
**НЕ** полная автономия (она жжёт токены) — дисциплинированная экономная петля.

> Из ресёрча по «Loop Engineering» взято ценное (maker-checker, закрытые циклы,
> жёсткие лимиты, human-in-the-loop, читаемый след). Грандиозные продуктовые лупы
> (само-ETL, Кибер-Шерпа, Karma) — это роадмап, не воркфлоу; сюда не относятся.

## Петля (5 шагов)
1. **Спека** — V4DYA в Obsidian по шаблону [[task-spec]] (цель / границы / контекст / критерий готовности). Чем точнее спека, тем меньше Claude читает и гадает — это **главный экономитель токенов**.
2. **План + развилки** — Claude: план в 1–2 фразы + ВСЕ развилки одним `AskUserQuestion`, затем пауза. Не по одному вопросу.
3. **Исполнение малыми диффами** — атомарные правки, коммит на инкремент. Без «заодно отрефакторю».
4. **Детерминированная проверка** (maker ≠ checker) — `tsc` / build / прод-курл / Zod, а не «на глаз». Проверяет МАШИНА, а не Claude сам себя.
5. **Закрытие петли** — статус ✅ в заметке, decision-нота, пуш. Читаемый след.

## Гарды (экономия + надёжность)
- **Узкий scope** — одна цель за заход.
- **Развилки батчем** — собрать все вопросы, спросить разом.
- **Стоп-условие** — критерий готовности достигнут ИЛИ N итераций без прогресса → стоп + спросить.
- **Human-in-the-loop только для стратегических узлов** — БД (`db:push`), деньги/калькуляторы, необратимое, пуш в `main`. Остальное — автономно в рамках спеки.
- **Детерминированный verifier > ручные проверки** — где можно, заменить курлы на скрипт/тест.

## Анти-паттерны (чего НЕ делаем)
- Открытые циклы без стоп-условия (бесконечная полировка = слив токенов).
- Глобальный рефакторинг агентом (comprehension debt) — только малые диффы.
- Маркер сам себе проверяющий (завышает оценки) — нужен внешний детерминированный гейт.

## Инструменты (без новых фреймворков)
- Скилл `execute-decision` — Obsidian-решение → код → git → docs.
- Примитивы харнесса: `/loop`, фоновые задачи, workflow — когда нужна параллельность/повтор.
- looper (`ksimback/looper`) — в **бэклоге** как опытная площадка, если принципов выше окажется мало (внешний Python-тул, оверхед для соло).
