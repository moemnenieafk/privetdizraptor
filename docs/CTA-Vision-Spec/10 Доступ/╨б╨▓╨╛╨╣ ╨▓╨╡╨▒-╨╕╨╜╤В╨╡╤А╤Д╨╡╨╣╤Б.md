# Свой веб-интерфейс

Раз API живой, а блокируется только потребительский клиент Google — чинить чужой фронтенд бессмысленно. Поднимаем свой на уже оплаченном VPS.

**Что даёт:** браузерный доступ к Gemini без VPN вообще. Подключение идёт к собственному домену с валидным SSL, наружу с VPS уходит обычный серверный запрос.

## Локация сервера решает всё

> [!success] Амстердам
> `generativelanguage.googleapis.com` доступен с сервера напрямую. Релей не нужен, `.env` без прокси-настроек.

Для справки, если сервер когда-нибудь переедет в РФ: API вернёт `400 FAILED_PRECONDITION — User location is not supported for the API use`, и понадобится egress-релей — Cloudflare Worker как обратный прокси (бесплатный тариф, доверенный IP) либо второй VPS в ЕС. Ключ при этом остаётся на основном сервере, Worker только проксирует.

## Вариант A — готовый UI, быстро

Поддомен `ai.cta.quest`, docker, nginx reverse proxy, Let's Encrypt.

- **Open WebUI** — Gemini через OpenAI-совместимый слой, мультимодальность, история чатов
- **LibreChat** — больше провайдеров, тяжелее
- **LobeChat** — легче, приятный UI

> [!warning] Авторизация обязательна
> Ключ на публично доступном Open WebUI без авторизации выкачают за сутки. Basic-auth на уровне nginx или встроенная авторизация — до того, как поднимется DNS.

## Вариант B — раздел в CTA

Собственные route handlers и store в стилистике NIGHTFALL. Больше работы, но это и есть [[Механика распознавания инвентаря]] — то есть B нужен в любом случае, а A имеет смысл как затычка на неделю.
