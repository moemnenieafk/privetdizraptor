# Схема данных

Две таблицы, Drizzle + Supabase. Реализация — [[Код - schema vision]].

## item_icon_hashes

Справочник эталонов. Заполняется скриптом [[Код - seed-item-hashes]] из tarkov.dev.

| Поле | Тип | Смысл |
|---|---|---|
| `item_id` | text PK | id из tarkov.dev |
| `name` | text | отображаемое имя |
| `normalized_name` | text | ключ для цен и ссылок |
| `grid_w` / `grid_h` | smallint | габариты в ячейках |
| `dhash` | text | 16 hex-символов |
| `icon_url` | text | `gridImageLink` |
| `updated_at` | timestamptz | для переиндексации после вайпа |

Индекс `item_icon_hashes_dims_idx` на `(grid_w, grid_h)` — под фильтр по габаритам.

> [!note] Переиндексация
> После каждого патча или вайпа иконки могут поменяться. Скрипт идемпотентен, `onConflictDoUpdate` — можно гонять по расписанию.

## inventory_scans

Кэш результатов.

| Поле | Тип | Смысл |
|---|---|---|
| `image_hash` | text PK | sha256 файла |
| `user_id` | text nullable | для аналитики и лимитов |
| `result` | jsonb `ScanResponse` | полный ответ |
| `cell_pitch` | integer | шаг сетки, пригодится для калибровки |
| `vision_calls` | smallint | сколько раз дёрнули Gemini |
| `created_at` | timestamptz | |

Первичный ключ по хэшу изображения означает: один и тот же скриншот не биллится дважды. Для расшаренных в чате скринов это заметная экономия.

`cell_pitch` и `vision_calls` — не декор: по ним видно, на каких разрешениях [[Калибровка и пороги|пороги]] промахиваются чаще.
