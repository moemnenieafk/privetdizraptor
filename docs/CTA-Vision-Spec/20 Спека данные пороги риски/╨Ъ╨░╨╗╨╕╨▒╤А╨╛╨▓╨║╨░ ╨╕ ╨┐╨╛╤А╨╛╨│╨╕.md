# Калибровка и пороги

Все магические числа собраны в двух константах, чтобы не искать их по коду.

## GRID_TUNING — `lib/vision/grid.ts`

| Ключ | Значение | Что делает |
|---|---|---|
| `minPitch` / `maxPitch` | 38 / 110 | диапазон поиска шага сетки |
| `emptyStdDev` | 9 | ниже — слот считается пустым |
| `separatorDarkRatio` | 0.7 | доля тёмных пикселей на границе = разделитель |
| `separatorLuma` | 70 | что считать тёмным |
| `innerInset` | 0.16 | какую часть ячейки анализировать, чтобы не цеплять рамку |

## MATCH_TUNING — `lib/vision/item-index.ts`

| Ключ | Значение | Что делает |
|---|---|---|
| `acceptDistance` | 8 | уверенное совпадение, vision не дёргаем |
| `rejectDistance` | 22 | выше — в кандидаты не берём вообще |
| `candidateLimit` | 5 | сколько вариантов уходит в Gemini и на UI |
| `cacheTtlMs` | 1 час | переподтягивание индекса из БД |

## RATE_TUNING — `lib/vision/rate-limit.ts`

Token bucket: 12 сканов, полное восстановление за час.

## Что калибровать в первую очередь

> [!warning] Два числа зависят от разрешения и настроек графики
> `emptyStdDev` и `separatorDarkRatio`. Всё остальное можно не трогать.

Порядок:

1. Прогнать реальный скриншот, залогировать `geometry.pitch` — если он не бьётся с визуальным шагом сетки, проблема в диапазоне `minPitch`/`maxPitch`, а не в порогах
2. Посмотреть, сколько слотов ушло в `unknown`. Много — снижать `emptyStdDev`
3. Проверить склейку: два соседних 1×1, прочитанных как 2×1 → поднимать `separatorDarkRatio`; один 2×1, разрезанный надвое → снижать

Поле `cell_pitch` в [[Схема данных|inventory_scans]] копит статистику по разрешениям — по нему видно, где промахи систематические.

## Источник данных для калибровки

Слоты `kind: 'unknown'` возвращаются наружу со списком кандидатов. Ручной выбор пользователя на UI — это размеченный датасет, который приходит бесплатно. Стоит логировать выбор рядом с `distance` до правильного варианта: сразу видно, куда двигать `acceptDistance`.
