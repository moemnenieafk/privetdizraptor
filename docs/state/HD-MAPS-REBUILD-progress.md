# Пересборка HD-карт: план и прогресс

**Цель V4DYA:** все карты в слоях этажности + рендер камней и растительности,
на будущее — рендер объектов (машины и прочее, что мешает проходу).
Всё собирается **от геометрии клиента**, папка `raster` с артом больше не участвует.

## Почему пересобираем

Рамка строилась из арта: мировые границы натягивались на **вырезку растра**, отчего
пиксель выходил неквадратным — Развязка 11.6 %, Резерв 8.9 %, Лес 5.1 %, Лаборатория 90.4 %,
Ледокол 415.7 %. Отсюда «растянутость».

⚠️ При этом **границы мира из `EFT_MAP_CONFIG` оказались ЧЕСТНЫМИ** — проверено независимо:
габарит растительности (координаты из TerrainData, от рамки не зависят) совпал с границами
у Развязки до 0.4 м, у Леса до 10 м по X и точно по Z. Врала только пиксельная сетка.

## Конвейер на карту

```bash
python scripts/eft-terrain/make-manifest.py <карта> D:/eft-export/frames 16384
python scripts/eft-map-layers/apply-bands.py <карта> D:/eft-export/frames/<карта>/manifest.json
python scripts/eft-map-layers/run-all.py <карта> --raster-root D:/eft-export/frames \
    --only frame,zone,stones,walls,obstacles,vegetation,render --force-step ...
```

Проверки на каждой карте: **самопроверка камнями**, **привязка сверена с rooms-frame**,
покрытие слоёв, пересечение поэтажных слоёв с наземным.

### 🔴 Две ловушки, пойманные при пакетном прогоне

**Терминал: покрытие 0.00 % при 15 094 объектах.** Я собрал рамку из `boundsFromConfig`,
а у Терминала они описывают ДРУГОЕ МЕСТО (откалиброваны по спавнам зеркала, пересечение
с геометрией клиента ровно ноль — гоча 27). Лечится `make-manifest --from-rooms`.
**Вывод для новых карт: после прогона смотреть покрытие, ноль при живых счётчиках = рамка мимо.**

**Ледокол и Таможня: `bounds` в конфиге — не метры.** У Ледокола `[[0,0],[5000,8400]]`,
у Таможни `[[0,0],[256,256]]` — это canvas/SVG-координаты (`staticMap` и тайловая карта).
`make-manifest` отказался и назвал причину. Лечится тем же `--from-rooms`.

**🔴 ПОЛОСА БЕЗ ВЫСОТ ДАЁТ ОДИНАКОВЫЕ СЛОИ.** У Ледокола и Таможни в `EFT_MAP_CONFIG`
у слоёв есть `name` и `svgLayer`, но НЕТ поля `height`. Полоса без высот превращается
в «всю карту» (фолбэк `[-1e9, 1e9]`, задуманный для наземной), и все палубы выходят
идентичными: **Ледокол дал 14 слоёв по 1 110 экземпляров и 2.73 % каждый**, Таможня —
четыре по 9 701. Счётчики при этом бодрые, ошибка видна только по одинаковости чисел.

**Лечение — разделить источники.** Рамка (границы + crop) берётся из ГЕОМЕТРИИ, а высоты
полос — из лучшего доступного источника. В старых манифестах растра они ЕСТЬ и точные
(пришли из `maps.json` the-hideout): у Таможни 5 полос, у Ледокола 16 палуб с отметками
18.92–19.56, 19.57–22.1 и далее. `apply-bands.py` теперь подставляет `layers[]` оттуда,
если у не-главных полос высот нет, и говорит об этом вслух.
⚠️ То есть старый манифест плох как источник РАМКИ (неквадратный пиксель), но хорош
как источник ПОЛОС. Выбрасывать его целиком было бы потерей.

**Объёмы-обёртки в комнатах.** `--from-rooms` раздувал рамку Ледокола до 1831×2201 м
вместо настоящих 33×133: виновата звуковая зона `Icebreaker_outdoor` с полуразмером
789×949 м («всё снаружи»), у Развязки такая же `OUTDOOR` объёмом 3.25e8. Добавлен отсев
по медиане: комната крупнее 20 медиан — обёртка, а не помещение; отсеянные печатаются вслух.

Просканированы имена ВСЕХ объектов сцен Развязки — 503 579 штук, не только мешевых.

**9. Контейнеры — ДА, лежат в клиенте.** На Развязке 321 объект с меткой `lootable`:
`scontainer_bag_sport_lootable` ×177, `PC_block_01_lootable` ×59, `scontainer_medbag_smu06`
×20, куртки `jacket_0*_LOOTABLE` ×30, чемоданы ×28, трупы скавов ×6, плюс `LootGarbage` ×59.
Это физические объекты сцены с мировыми позициями — дампятся ровно как камни
(`dump-stones.py` как образец). ⚠️ Метка `lootable` покрывает не всё: сейфы, оружейные
ящики, комоды и `scontainer_toolbox_01` (×73) названы без неё — словарь имён надо собирать
по факту, как для камней и растительности.

**10. Loose loot — НЕТ в клиенте.** Ноль объектов `LootPoint`/`LooseLoot`/`ItemSpawn`.
Точки рассыпного лута задаются НА СЕРВЕРЕ, в конфиге локации. Но данные у нас УЖЕ ЕСТЬ:
таблица `loot_spawns` (28 484 точки из локального дампа SPT) + `loot_container_pools`,
ридер `src/db/loot-heat.ts` — это то, на чём работает heatmap. Слой рисуется из зеркала,
а не из клиента.

**11. Квесты — из зеркала, не из геометрии.** В сценах есть триггер-зоны, но 1 526 из 1 769
это `AudioTriggerArea` (звук), а остальное — `Triger_Zone_from_IDEA`, `IndoorTrigger` и
подобное, без признака квеста. Квестовые зоны тоже серверные. У нас есть `quest_zone`
в зеркале (`src/db/maps.ts`). Требует отдельной проверки: сходятся ли координаты зон
с нашей геометрической рамкой.

**Важное следствие геометрической рамки:** данные из зеркала (loose loot, квест-зоны,
спавны) лежат в МИРОВЫХ координатах игры. Раньше их надо было подгонять под кривую рамку
арта, теперь они проецируются той же аффиной, что и геометрия — без подгонки.
