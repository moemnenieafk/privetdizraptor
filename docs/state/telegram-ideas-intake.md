# Telegram → Ideas Intake (ЦТА)

Приём **идей по улучшению сайта** из ветки «идеи» приватного Telegram-чата в заметки валта.
Запускается **по триггер-фразе** V4DYA, не автономно. Зеркало bug-intake
([[docs/state/telegram-bug-intake.md]]) — та же механика, другой бот/ветка/папка.

## Триггер
> «новая ЦТА-идея в ТГ»

При этой фразе Claude:
1. Тянет новые сообщения ветки идей через Telegram Bot API (`getUpdates`, offset ниже — **свой, у этого бота отдельный поток апдейтов**).
2. Парсит/нормализует каждое сообщение как идею-улучшение.
3. На каждое сообщение заводит карточку-файл в папке `ideas/` (одно сообщение → один файл).
4. Постит нормализованную карточку обратно в чат ответом на исходное сообщение (через бота, `sendMessage`).
5. Обновляет watermark ниже и лог.
6. Показывает список заведённого. **Код не трогает** — реализация отдельной командой (как у багов: «только заметки»).

## Тайминг: вариант A — по триггеру

```
- **Компонент:** <компонент, если есть>
- **Идея:** <что улучшить/добавить — суть>
- **Зачем / польза:** <проблема, которую решает; ценность для игрока>
- **Как видит автор:** <референс/механика, если описано>

```
Поля, выведенные из свободного текста (не заданные явно), помечать `~вывод`.

## Как читать (команда для Claude)
```bash
# offset = last_update_id + 1 из watermark. Токен — из окружения, в файлы/лог НЕ писать.
curl -s "https://api.telegram.org/bot${TELEGRAM_IDEAS_BOT_TOKEN}/getUpdates?offset=<OFFSET>&allowed_updates=[\"message\",\"edited_message\"]"
```

## Маска сообщения (для парсера)
Маркер идеи — строка `#идея` (или `#idea`). Дальше поля `Ключ: значение`, порядок любой.
```
#идея
Игра: EFT                     # EFT | GZW | ABI (дефолт EFT; «—» если кросс-игровое)
Раздел: Карты — /eft/maps
Компонент: MediaLibrary        # если применимо
Идея: <что улучшить>          # ЕДИНСТВЕННОЕ обязательное поле
Зачем: <польза/проблема>
Как: <референс/механика>
Ценность: важно               # маст-хэв | важно | приятно | спорно (дефолт важно)
```
Синонимы ключей: `Идея`=`Что улучшить`=`Предложение`=`Хотелка`; `Зачем`=`Польза`=`Проблема`;
`Как`=`Реализация`=`Референс`; `Ценность`=`Приоритет`. Одно сообщение = одна идея. Скрин/референс — вложением к тому же сообщению.
Голый `#идея` + текст без полей → весь текст в «Идея», раздел/компонент угадать из текста (`~вывод`).

## Нормализация входа (любой формат → канон)
Как у багов: свободный текст/каша/голос приводим к канону всегда.
- **Дата/время** — из `message.date` (unix → локальное), НЕ из текста.
- **Свободный текст** — интерпретирую и раскладываю по полям маски. Чего нет — поле `?` (не выдумывать).
- **Голосовое (`voice`/`audio`)** — `getFile` → скачать `.ogg` → транскрибация скиллом `voice-notes` (faster-whisper large-v3, GPU) → нормализация. При наговоре автору называть **раздел**.
- **Флаг доверия:** выведенные поля помечать `~вывод` — где точные слова автора, а где интерпретация.

## Гочи (Bot API)
- Чат — **супергруппа**, сообщения приходят типом `message` (НЕ `channel_post`). Нужен выкл. приватности.
- ⚠️ **`allowed_updates` залипает между вызовами.** Всегда звать с `allowed_updates=["message","edited_message"]`, иначе `message`-апдейты молча отбрасываются. Проверка: `getWebhookInfo.allowed_updates`.
- `getUpdates` отдаёт сообщения **после** входа бота и хранит ~24 ч → бэклог до входа невидим (выгребать браузером).
- Нельзя одновременно с webhook — только long-poll.
- **Отдельный бот = отдельный offset.** Watermark этого бота НЕ связан с bug-ботом.
