## Что реализовано (по областям)

### Данные
- `dump-quests.mjs` параметризован (regular/pve), сохраняет `acceptedItems[]` для any-of. Оба режима свежие из `json.tarkov.dev`.
- Ридер `buildNeededItems(mode)`: single-item + any-of группы + квест-предметы («только рейд») + убежище (зеркало).
- **Консолидация квест-целей** (fix 5ad2c86a): один квест с find+give одного предмета = ОДИН источник, `count = max(сумма отдающих, max находящих)`. find+give → max (те же предметы), plant×N → sum (аддитив). Убрало дубль-чипы и двойной счёт в тоталах.
- FiR per-source (и квесты, и убежище). Убежище синкнуто (regular, 26 станций/68 апгрейдов).

## Пойманные баги (все починены)
1. **Валюта как предметы** — раздувала «Докупить» → `CURRENCY_IDS` фильтр на квест-стороне ридера.
2. **Дубли квест-чипов + двойной счёт** — find+give одного предмета = два источника → консолидация (см. выше).
3. **Декремент «залипал» на быстрых кликах** — `distribute`/QtyControl писали от рендер-значения → перевели на функциональный живой стор (`bump`/`onDelta`).
4. **⭐ RUNAWAY hold-repeat (главный)** — кнопка +/- становится `disabled` на границе (max/0), disabled-элемент НЕ получает `pointerup` → цикл авто-повтора инкремента зависал и вечно писал max; минус декрементил, зависший цикл возвращал max («восполняет в зелёную зону»). **Фикс:** отпускание слушаем на `window`, а не на кнопке. Диагностировано через инструментацию стека `Storage.setItem` (стек показал `useHoldRepeat.tick → bump → max`). Фикс в общем `QtyControl` — чинит везде.
