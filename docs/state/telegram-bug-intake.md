# Telegram → Bug Intake (ЦТА)

Приём багов из приватного Telegram-канала в заметки решений валта.
Запускается **по триггер-фразе** V4DYA, не автономно.

## Триггер
> «новый ЦТА-баг в ТГ»

При этой фразе Claude:
1. Тянет новые сообщения группы через Telegram Bot API (`getUpdates`, offset ниже).
2. Парсит/нормализует каждое сообщение как баг-репорт.
3. На каждое сообщение заводит карточку-файл в папке `bugs/` (одно сообщение → один файл).
4. Постит нормализованную карточку обратно в чат ответом на исходное сообщение (через бота, `sendMessage`).
5. Обновляет watermark ниже и лог.
6. Показывает список заведённого. **Код не трогает** — фикс отдельной командой (выбор V4DYA: «только заметки»).

## Тайминг: вариант A — по триггеру (выбор V4DYA)
Без фоновой инфры. Бот отвечает в чат и карточки заводятся в МОМЕНТ прогона по фразе-триггеру,
не мгновенно на каждое сообщение. Апгрейд до крона (B) или всегда-онлайн сервиса (C) — если понадобится мгновенность.

```bash
curl -s "https://api.telegram.org/bot${TELEGRAM_BUG_BOT_TOKEN}/getUpdates?offset=<OFFSET>&allowed_updates=[\"channel_post\"]"
```

## Маска сообщения (для парсера)
Маркер бага — строка `#баг` (или `#bug`). Дальше поля `Ключ: значение`, порядок любой.
```
#баг
Игра: EFT                     # EFT | GZW | ABI (дефолт EFT)
Раздел: Квесты — /eft/quests/questmap
Компонент: QuestMap, карточка квеста
Что не так: <суть>            # ЕДИНСТВЕННОЕ обязательное поле
Повтор: <шаги>
Ожидалось: <ожидаемое>
Критичность: серьёзный        # блокер | серьёзный | мелкий | косметика (дефолт мелкий)
Платформа: mobile             # desktop | mobile
```
Синонимы ключей: `Что не так`=`Проблема`=`Описание`; `Повтор`=`Как повторить`=`Ситуация`;
`Критичность`=`Приоритет`. Одно сообщение = один баг. Скриншот — вложением к тому же сообщению.
Голый `#баг` + текст без полей → весь текст в «Что не так», раздел/компонент угадать из текста.

## Нормализация входа (любой формат → канон)
Сообщение может прийти НЕ по маске: свободный текст, каша, расшифровка голоса. Приводим к канону всегда.
- **Дата/время** — из `message.date` (unix → локальное), НЕ из текста. Есть на каждом баге.
- **Свободный текст** — интерпретирую и раскладываю по полям маски. Чего нет — поле `?` (не выдумывать).
- **Голосовое (`voice`/`audio`)** — `getFile` → скачать `.ogg` → транскрибация скиллом `voice-notes`
  (faster-whisper large-v3, GPU) → затем обычная нормализация.
  ⚠️ Правило для авторов (закреп в чате, msg 326): при наговоре ОБЯЗАТЕЛЬНО называть **раздел** и что делаешь
  («я в разделе Карты, добавляю маркер через визард…») — иначе контекст теряется. Нет раздела в аудио → поле `Раздел: ?`.
- **Флаг доверия:** поля, выведенные из свободного текста (не заданные явно), помечать `~вывод`,
  чтобы автор видел, где его точные слова, а где интерпретация, и мог поправить.

## Гочи (Bot API)
- Чат — **супергруппа**, сообщения приходят типом `message` (НЕ `channel_post`). Админка не нужна, нужен выкл. приватности.
- ⚠️ **`allowed_updates` залипает между вызовами.** Один раз дёрнули `getUpdates?allowed_updates=["channel_post"]`
  — и он остаётся дефолтом, а `message`-апдейты молча отбрасываются (не удерживаются!). Всегда звать с
  `allowed_updates=["message","edited_message"]`. Проверка: `getWebhookInfo.allowed_updates`.
- `getUpdates` отдаёт только сообщения **после** входа бота и хранит их **~24 ч** → бэклог до входа невидим (выгребать браузером).
- Нельзя одновременно с webhook — только long-poll.
