# Сшивка карт ЦТА

Карты EFT раздаются кусками: облако отдаёт тайловую пирамиду по 256px, локальные
дампы — по файлу на этаж. Движку нужен один файл. Между этими двумя состояниями
лежит десяток мест, где всё ломается тихо: файл получается валидный, размеры
верные, а карта чёрно-белая или этажи разъехались на десять метров.

Этот скилл — накопленный список этих мест плюс два скрипта, которые их обходят.

## Сначала определи, какой из двух конвейеров нужен

| Признак в запросе | Конвейер |
|---|---|
| «выгрузи растр», «тайлы», «подложка», «максимальный зум», название карты + «картинка» | **облачный** |
| «сшей этажи», «файлы по этажам», «DynamicMaps», «из папки», уже есть локальные SVG | **локальный** |
| «маркеры не туда», «проверь проекцию» | ни тот, ни другой — иди в `references/projection.md` |

Спутать их дёшево: облачный даёт растр как референс для отрисовки, локальный
даёт вектор, который поедет в прод. Разные цели, разные проверки.

## Облачный конвейер: тайлы → одна картинка

Скрипт лежит в репозитории, не в скилле: `scripts/fetch-tiles.mjs`.

```bash
node scripts/fetch-tiles.mjs --list
node scripts/fetch-tiles.mjs --map factory --zoom 5
node scripts/fetch-tiles.mjs --map icebreaker --zoom 4 --layers 06_infirmary
```

Он сам тянет конфигурацию карт из `maps.json` the-hideout, качает с кэшем,
определяет занятую сетку, приводит тайлы к единому формату, сшивает, режет по
общему bbox и пишет WebP плюс `manifest.json` в `map-exports/raster/{карта}/`.

**Тайлы есть у всех десяти карт**, а не только у Labs, Labyrinth и Icebreaker,
как написано в README пака. У Customs пять слоёв, у Reserve шесть.

### Выбор зума — не «бери максимум»

Считай пиксели на метр, а не номер зума. Завод 142 метра в поперечнике: на z=6
это 15664 пикселя, то есть 110 px/м, и четыре слоя по 230 Мпикс каждый. На z=5
выходит 55 px/м — для подложки под обводку достаточно, а весит в двадцать раз
меньше. Максимальный зум оправдан там, где реально плотная застройка на большой
площади: Лабиринт, Улицы, Лаборатория.

Прикидка: сторона в пикселях ≈ `2^zoom × 256 × (доля занятой сетки)`.

### Что проверять после прогона

Сшивку нельзя принимать на глаз — ошибки позиционирования выглядят правдоподобно.
Сверь блок 2×2 сырых тайлов с тем же местом в результате:

- **альфа должна совпасть побайтно** — это доказывает позиционирование;
- RGB разойдётся на единицы (среднее 2–3) из-за потерь WebP, это норма;
- выбросы RGB под 200 бывают только там, где альфа ниже 64 — на полупрозрачных
  краях кодек не хранит невидимый цвет.

Готовый код проверки — в `references/verification.md`.

## Локальный конвейер: поэтажные SVG → один файл

```bash
python skills/map-stitch/scripts/stitch-svg-floors.py --in <папка> --dry-run
python skills/map-stitch/scripts/stitch-svg-floors.py --in <папка> --out Factory.svg \
    --order Basement,Ground_Floor,Second_Floor,Third_Floor
```

**Всегда начинай с `--dry-run`.** Он печатает таблицу «этаж / группа / исходный
класс / исходная заливка / назначенный класс». Эта таблица — единственное место,
где видно, что классы разъехались, потому что дальше исходные классы стираются.

### Почему прямая склейка не работает

`st0`, `st1`, `st2` в каждом файле значат своё — это локальная нумерация экспорта
Illustrator. На Заводе:

| | Basement | Ground / 2nd / 3rd |
|---|---|---|
| `st0` | заливка `#70777f` — **пол** | обводка `#000 .2px` — **стены** |
| `st1` | `gold` — лестницы | `#70777f` — пол |
| `st2` | `#1a2632` — стены | `gold` — лестницы |

Склеишь как есть — получишь подвал, где пол нарисован обводкой, а стены залиты
цветом пола. Файл при этом валидный. Поэтому скрипт назначает классы по **именам
групп**, а не по исходным классам, и печатает таблицу для проверки глазами.

Дополнительно: если исходная заливка оказалась `fill: none` со штрихом,
заливочный класс не подставляется — уходит в `cta_outline`. Иначе контурная
стена залилась бы сплошным силуэтом.

### Когда скрипт остановится

- **Разные `viewBox`** — этажи не в одной системе координат, сшивать бессмысленно.
  Печатает список и выходит с кодом 1.
- **Группа не опознана** — печатает `НЕ ОПОЗНАНЫ` и возвращает 1. Добавь имя в
  `GROUP_CLASS` в скрипте или переименуй группу. Без класса фигура не покрасится
  токенами и станет невидимой.

### Что получается на выходе

Структура по `docs/maps/SPEC-DRAWING.md` §2: группа на этаж, внутри `#Schematic`
с исходными подгруппами и пустой `#Detail` под спутниковый слой, один
`<style id="style_common">` на токенах, ноль HEX, ноль инлайновых заливок.

Считай фигуры до и после — их количество обязано совпасть. На Заводе это
34 + 137 + 41 + 14 = 226.

## Чего этот скилл не делает

- **Не заливает никуда.** Результат ложится в `map-exports/` (в `.gitignore`) и
  остаётся локальным. Растровые тайлы лицензии не имеют вовсе, зеркалить их в R2
  рядом с SVG под CC BY-NC-SA — заметно больший риск. Подробнее в
  `references/sources.md`.
- **Не правит проекцию.** Если маркеры не совпали с подложкой, дело не в сшивке.
- **Не решает за пользователя, что рисовать.** Растр — референс форм, а не
  основа для обводки: производное произведение от чужого арта остаётся
  производным.

## Справочники

Читай их по необходимости, не загружай все сразу:

- `references/failure-modes.md` — полный список тихих поломок с измеренными
  числами: обесцвечивание мозаики, пределы кодеков, память, размер тайла,
  регистрация слоёв. **Читай перед тем, как писать любой свой код сшивки.**
- `references/verification.md` — готовые проверки: побайтная сверка блока,
  сверка силуэта через IoU, признаки сломанной проекции.
- `references/sources.md` — где что лежит: тайловые пути, DynamicMaps, база SPT,
  что делать с лицензиями.
- `references/projection.md` — как игровые координаты попадают в SVG, развилка
  контрактов, почему `transform` нельзя мерить линейкой viewBox.
