# Тихие поломки при сшивке карт

Все числа здесь измерены на реальных картах ЦТА, а не оценены. Общая черта
этих поломок: файл получается валидный, размеры правильные, ошибка видна не
сразу или не видна вообще.

## 1. Мозаика обесцвечивается

**Симптом.** Карта серая, альфа обрезана на 173 вместо 255. Файл открывается,
размеры верные. На маленьком превью можно не заметить.

**Причина.** Тайлы приходят вперемешку в четырёх форматах PNG. Замеры:

| карта | RGBA | RGB | палитра | 1-битные |
|---|---|---|---|---|
| Лабиринт (z6, 1 слой) | 1094 | 603 | — | 1663 |
| Лаборатория (z6, 3 слоя) | есть | есть | есть | есть |

`vips arrayjoin` и `sharp.join` требуют одинакового числа каналов и берут
интерпретацию первого изображения в списке. Если первый тайл серый —
интерпретация `b-w` навяжется всему холсту.

**Лечение.** Приводить каждый тайл к sRGB + alpha ДО сшивки:

```js
const t = sharp(file);
if (t.hasalpha()) { /* вытащить альфу, RGB через toColourspace('srgb'), собрать */ }
else t.toColourspace('srgb').ensureAlpha();
```

Однобитные тайлы с прозрачностью через `tRNS` при этом обрабатываются
корректно — проверено сверкой девяти тайлов всех режимов против
`PIL.convert('RGBA')`, расхождение ноль.

**Как поймать.** У правильного результата средние по каналам RGB различаются.
Если они равны с точностью до десятых — картинка серая:

```
плохо:  [25.7 25.7 25.7]  alpha max 173
хорошо: [25.7 23.4 20.8]  alpha max 255
```

## 2. Пределы кодеков

**WebP.** Формально сторона до 16383 px. Но `libwebp` сдаётся раньше, по общему
числу пикселей:

| карта | Мпикс | итог |
|---|---|---|
| Лаборатория 15360 × 11008 | 169 | закодировалось |
| Лабиринт 15119 × 14003 | 212 | `webpsave: unable to encode` |
| Завод z6 15664 × 14928 | 234 | `webpsave: unable to encode` |

Порог между 170 и 210 Мпикс. Проверять надо и сторону, и площадь — при 234 Мпикс
обе стороны были в пределах 16383, и проверка по стороне пропустила.

Практический порог — 150 Мпикс, плюс `try/catch` вокруг кодирования с откатом в
PNG. Ошибка приходит из нативного кода и роняет процесс, если её не поймать.

**PNG.** Тянет 234 Мпикс, но растёт в весе: Лабиринт 212 Мпикс это 179 МБ.

## 3. Память

`PIL` держит холст целиком: 212 Мпикс RGBA это 847 МБ, плюс буфер кодировщика —
процесс убивают по OOM ещё до записи. Дополнительно `crop()` делает вторую
копию, то есть пик почти вдвое выше.

`libvips` (и `sharp` поверх него) стримит построчно, пик — десятки мегабайт.
Для карт крупнее сотни мегапикселей другого варианта нет.

Если всё же нужен PIL — собирать холст сразу нужного размера, а не строить
полный и потом обрезать.

## 4. Размер тайла из конфига врёт

У Лаборатории в `maps.json` стоит `tileSize: 175`, реальный файл — 256×256.
175 это параметр отрисовки Leaflet, а не размер картинки. Счёт по 175 сдвинет
всю сетку на 46%.

Брать размер из первого непустого тайла.

## 5. Этажи разъезжаются

Каждый слой карты занимает свою часть сетки. Если резать каждый по своему bbox,
слои перестанут совмещаться.

Пример, Ледокол (16 палуб, z5):

```
00_control_room    x 3808..4384  y 3040..3296
05_storage         x 3232..4928  y    0..7808
14_bridge          x 3232..4928  y 4768..6272
```

Резать все слои по **объединённому** bbox. У Ледокола это 1856 × 8192 —
корпус судна, узкий и длинный.

## 6. Пропущенный тайл роняет прогон

`sharp` бросает `Input file is missing` на отсутствующем файле. Если не поймать,
падает вся сшивка — причём уже после скачивания, в самый обидный момент.

Тайл может отсутствовать после таймаута загрузки: на 20 тысячах запросов это
вопрос времени.

Лечение: подставлять прозрачный тайл нужного размера. В результате остаётся
честная дыра, а не мусор и не падение.

## 7. Сеть

Часть прокси и корпоративных сетей отдаёт 403 на программные запросы к
`assets.tarkov.dev`, пропуская при этом `curl`. Заголовок `User-Agent` не
помогает. Держать `curl` как запасной путь.

## 8. Временный расход диска

Нормализованные тайлы пишутся на диск перед мозаикой. Замер: тайл 109 КБ против
68 КБ исходного, то есть примерно **436 МБ на слой** при полной сетке z6. Папка
чистится после каждого слоя, но пик надо иметь в виду.
