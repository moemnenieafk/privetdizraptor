# Коллекционер: дубли съедобных предметов (полное/съеденное состояние)

- **Раздел:** Прогресс — Коллекционер (`/eft/progress/collector` `~вывод`, из хлебной крошки EFT / ПРОГРЕСС / КОЛЛЕКЦИОНЕР)
- **Компонент:** список предметов Коллекционера (контейнер Карра) `~вывод`
- **Что не так:** съедобные предметы дублируются — по две карточки, т.к. предмет существует в двух состояниях «полное» и «съеденное». На скрине дубли: **Багет из французской пекарни** (Cocaoo_), **Бутылка воды YMXC** (YMXC), **Консервированное мясо GIGABEEF** (GigaBeef). Дубли завышают и счётчик (ВСЕГО: 48).
- **Повтор:** открыть `/eft/progress` → Коллекционер → у еды по две одинаковые карточки.
- **Ожидалось:** один предмет без дублей-состояний; счётчики Собрано/Осталось/Всего корректны.
- **Гипотеза (`~вывод`):** в источнике два itemId на «полное»/«съеденное» состояние одной еды → дедупить по базовому предмету (оставлять «полное»).

## Резолюция (2026-08-23, ветка `fix/collector-food-duplicates`, grill→code→live-verify)

**Гипотеза из ТГ неверна.** Дубли — НЕ два itemId «полное/съеденное» одной еды. Реальная причина:
курируемый оверрайд `src/data/eft-collector.ts` вручную добавлял 4 «стример-предмета патча»
(`COLLECTOR_EXTRA_ITEMS`: GigaBeef, KC-130, Багет, YMXC) в предположении, что их НЕТ в зеркале квеста.
С тех пор крон синканул корректные objectives — все 4 предмета (и снятие Evasion-повязки из
`COLLECTOR_DROP_ITEM_IDS`) уже есть в `eft-quests.json`. Каждая еда рендерилась дважды: раз из
objectives (`base`), раз из ручного extra. На скрине видно 3 из 4 — KC-130 («**М**одель самолёта»)
сортируется ниже и был под сгибом, но дублировался тоже. Счётчик 48 = 44 objectives + 4 extras.

**Условие снятия оверрайда, записанное в самом файле («когда крон синканёт корректные objectives —
этот оверрайд убрать»), выполнено** → оверрайд удалён целиком.

**Правки:**
- Удалён `src/data/eft-collector.ts` (и `COLLECTOR_DROP_ITEM_IDS`, и `COLLECTOR_EXTRA_ITEMS` мертвы).
- `src/app/eft/progress/collector/page.tsx`: читает item-objectives квеста напрямую (§4.11), без
  base+extras мержа и drop-фильтра.
- `src/lib/kappa-objectives.server.ts` (второй потребитель — id'ы Каппы для Досье/инференса роли):
  синхронно убран оверрайд, `objectiveId` = реальный `o.id` цели.

**Итог (live-verify, dev :3000):** Всего **44** (было 48), 0 дублей. Поиск «мясо» → одна карточка
GigaBeef с реальной иконкой; Багет/YMXC/KC-130 по одной. tsc + eslint чисто.

**Долг (не блокер):** у Багета `shortName` в зеркале = `Coсaoo_` с **кириллической** `с` (U+0441)
вместо латинской (артефакт tarkov.dev). Приняли как есть (§4.11 — зеркало канон); правильное место
починки — латинизация гомоглифов в крон-синке квестов, не оверрайд на странице.

**Побочный эффект (мелкий):** у кого локально были отмечены 4 дублированные еды через *ту* (extra)
карточку — ключ прогресса сменился с `extra:<slug>` на реальный objective-id, отметку по этим 4
предметам нужно поставить заново один раз.
