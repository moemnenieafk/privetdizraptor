# Откуда tarkov.dev берёт 512px-иконки EFT и может ли ЦТА сделать это автономно офлайн

> Дата: 2026-06-24. Deep-research (workflow `wf_a198ffd6-8d4`, 13 агентов, 8 утверждений верифицированы адверсариально против первичного исходного кода the-hideout, ветки `master`/`main`). Где верификатор уточнил/опроверг — стоит caveat, а не исходная формулировка.

---

## 1. TL;DR

**Где tarkov.dev берёт 512px:** `image512pxLink` (то самое `{id}-512.webp`, которое ЦТА уже импортировал) — это **даунскейл `image.resize(512,512,{fit:'inside'})` высокоразрешённого 8x-мастера**, а не отдельное извлечение и **не апскейл 64px-иконки**. 8x-мастер — это канонический исходник (для предмета 1×1 ровно 512×512), который заливает доверенный контрибьютор из заранее собранной локальной папки `HQ_IMAGE_DIR/{id}.png`. Сам инструмент, который рождает пиксели 8x-мастера, **в открытых репозиториях the-hideout НЕ опубликован**.

**Можно ли воспроизвести автономно офлайн (BattlEye-safe, без tarkov.dev, без боевого клиента):**
**Нет — не «вытащить готовый спрайт», но да — «отрендерить самому».** Готовых 512px-иконок в бандлах EFT не лежит: иконка рождается **рантайм-рендером 3D-модели** через preview-камеру. Офлайн из бандлов (AssetStudio/AssetRipper/UABEA — это работа с *файлами*, не с памятью, поэтому BattlEye-safe) извлекаются **меши + текстуры материалов + PreviewPivot-ракурс**, но не финальная 2D-иконка. Чтобы получить 512px без tarkov.dev, нужно **построить собственный render-to-texture пайплайн** (Unity/headless, воспроизводящий ракурс камеры BSG) — это существенная инженерия. Пути «просто скопировать спрайт из бандла» **не существует**.

**Практический вывод:** текущий подход ЦТА (зеркалить уже отрендеренные 512px webp как статический ассет через синк, не per-request) — правильный и дешёвый. Собственный рендер-пайплайн стоит строить, только если полная независимость от tarkov.dev станет жёстким требованием.

## 2. Пайплайн картинок tarkov.dev

Все варианты картинок производит один npm-пакет **`the-hideout/tarkov-dev-image-generator`** (форк `kokarn/tarkov-image-generator`). Ключевой принцип: **все шесть вариантов — из одного исходника на предмет**, tarkov.dev **никогда** не качает картинки с BSG/официального эндпоинта.

Сетка EFT (из `image-functions.js`): `getItemGridSize = {width:(item.width*63)+1, height:(item.height*63)+1}` (1 ячейка = 63px + 1px бордер). `get8xSize = gridSize*8`. Поэтому 8x-мастер предмета 1×1 = **64×8 = 512px**.

| Link-тип (GraphQL поле) | Источник пикселей | Разрешение | Как генерится (функция в `image-functions.js`) |
|---|---|---|---|
| **iconLink** (`icon`) | локальный Icon Cache (~63px/ячейка) **или** даунскейл HQ-мастера | 64×64 | `createIcon` → `resize(64,64,{fit:'inside'})` + шахматный фон + drop-shadow + бордер. *(deprecated в схеме, авто-фолбэк)* |
| **gridImageLink** (`grid-image`) | тот же исходник | `(w*63+1)×(h*63+1)` | `createGridImage` → `resize(gridSize,{fit:'inside'})` + фон + тень + бордер + текст `shortName`. *(deprecated)* |
| **baseImageLink** (`base-image`) | тот же исходник | = grid-размер | `createBaseImage` → `resizeToGrid {fit:'contain'}`, **без** фона/тени/бордера/текста. *(deprecated)* |
| **inspectImageLink** (`image`) | HQ-мастер (нужен ≥512w **или** ≥350h) | ≤512×350 | `createInspectImage` → `resize(512,350,{fit:'inside'})`, композит поверх `background.png` |
| **image512pxLink** (`512`) | **даунскейл 8x-мастера** | ≤512×512 | `create512Image` → `if (w>512 \|\| h>512) image.resize(512,512,{fit:'inside'})`; webp **lossless**. **Никогда не апскейлит** |
| **image8xLink** (`8x`) | **сам HQ-мастер** | ровно `gridSize*8` (1×1 → 512×512) | `create8xImage` → **НЕ ресайзит**; `canCreate8xImage` требует `w===gridSize.w*8 && h===gridSize.h*8`. Чистый re-encode, webp `{lossless:true}` |

**Уточнение верификатора:** 8x **не «производится ресайзом»** — это pass-through исходника, который уже обязан быть 8x. А `icon`/`grid` — не «голый resize», а resize + композит (фон/тень/бордер/текст).

**Два пайплайна-входа в генератор:**

1. **`generate.js`** — читает локальный Icon Cache: `iconCacheFolder = LOCALAPPDATA + '\Temp\Battlestate Games\EscapeFromTarkov\Icon Cache\live\'`. Маппит хэшированные имена на id через `index.json` + порт хэша RatScanner/RatStash. Единственный сетевой вызов — `api.tarkov.dev/graphql` за **метаданными** (не байты картинок). Из 64px-исходника выходят только `icon`/`grid`/`base`; ветки `512`/`8x`/`inspect` гейтятся `canCreate*` и тихо пропускаются.
2. **`hq-gen.js`** — читает заранее собранные hi-res PNG: `sharp(HQ_IMAGE_DIR/{id}.png)` → гонит все шесть вариантов → заливает через `scanner-api.js submitImage()`. Папку наполняет `copy-from-paths.mjs` из рукотворного `paths.json` `{id: путь}`.

**Сервер (`tarkov-data-manager/modules/image-create.mjs`):** `regenerateFromExisting()` качает `item.image8xLink` и пере-выводит icon/grid/base/inspect/512 из него — **8x есть мастер-эталон**. `baseImageSkip=['512','8x']` — при base-исходнике 512/8x пропускаются.

**Хранение:** `Key = {id}-{imageType}.{format}` → `{id}-512.webp` в AWS S3 за Cloudflare (`assets.tarkov.dev`). Ровно паттерн, который ЦТА зеркалит.

## 3. Откуда берётся высокое разрешение (512px / 8x)

**Итог: 512px/8x НЕ извлекаются как спрайт из бандлов, НЕ апскейлятся, НЕ качаются с BSG. Это рантайм-рендер 3D-модели, потом даунскейл.**

- **Не апскейл (confirmed):** `create512Image` ресайзит только если `width>512 || height>512` (`fit:'inside'` не увеличивает); исходники <512 по обеим осям **отвергаются**. Ветки апскейла нет → hi-res арт обязан существовать заранее.
- **Не извлечение из бандла, иконки рендерятся рантаймом (confirmed):** по туториалу SP-Tarkov `WTT_Vol1`, предмет в бандле = 3D-**префаб** (меш + материалы) + скрипт **`PreviewPivot`** (ракурс камеры); иконка = «Render Icon» (render-to-texture). Подтверждение per-assembly рендера: `hash-calculator.js` строит ключ кэша из **собранного пресета** (XOR слотов, `HasHinge ^=23`, `Foldable ^=23<<1`, видимые патроны). Разные моды → другая иконка → не фиксированный спрайт. *(Доказано для moddable; статичные предметы могут иметь запечённые спрайты, но tarkov.dev их из бандлов всё равно не тянет.)*
- **Истинный потолок офлайн:** разрешение **сеточное** `(ячейки*63)+1`; 8x = ×8 → 1×1 = 512px. Рутинный Icon Cache ~63px/ячейка → для мелких предметов проваливает `canCreate512Image`. **Готового 512px/8x-спрайта в бандлах для обычных предметов нет.**
- **Поправка верификатора:** премиса «кэш всегда 64px» держится только для **мелких** (1×1) предметов. Крупные многоячеечные (≥~9 ячеек по оси) могут уже быть ≥512px в кэше и пройти `canCreate512Image` без HQ-источника.
- **Не подтверждено:** конкретный инструмент, рождающий пиксели 8x-мастера, **не опубликован** (`paths.json` → произвольные локальные файлы мейнтейнера). Asset-bundle-extraction или приватный hi-res in-game-захват — код не устанавливает. Definitively **НЕ** 64px-кэш и **НЕ** BSG-API. Confidence medium.

Источники: `wiki.sp-tarkov.com/modding/tutorials/WTT_Vol1`; `RatScanner/EfTIcons`; `forge.sp-tarkov.com/mod/1097/clear-icon-cache`; EFT KB `escapefromtarkov.com/support/knowledge/512`; the-hideout `image-functions.js`/`hash-calculator.js`/`generate.js`/`hq-gen.js`.

## 4. Может ли ЦТА воспроизвести 512px автономно офлайн (BattlEye-safe)?

**Чистой выемкой готовых 512px-спрайтов из бандлов — НЕТ. Через собственный рендер модели — ДА, но серьёзная инженерия.**

- **Почему «вытащить из бандла» не работает:** готовых иконок там нет (рендерятся рантаймом). Офлайн-инструменты (AssetStudio/AssetRipper/UABEA, BattlEye-safe — работают с файлами) извлекают **меши + материалы/текстуры + PreviewPivot** = входы для рендера, не финальные 2D-иконки.
- **Что НЕ годится:** дамп своего Icon Cache (~64px, наполняется только живым клиентом → BattlEye); поднять клиент в высоком разрешении (живой клиент → BattlEye); IL2CPP-реверс боевого клиента (зашифрованная метадата + BattlEye).
- **Реалистичный автономный пайплайн (= РЕНДЕР):**
  1. Офлайн-извлечение (BattlEye-safe): AssetRipper/AssetStudio → меш + материалы + `PreviewPivot` из бандлов.
  2. Render-to-texture (строить самим): headless Unity/Blender, воспроизвести preview-камеру EFT, рендер в 512 на прозрачный фон.
  3. Прогнать PNG через открытый `create512Image` → идентичный 512 webp lossless.
- **Тяжёлые места:** точно повторить per-item ракурс камеры BSG (`PreviewPivot`), материалы/шейдеры, сборку оружия/пресетов из деталей. Фиделити кадрирования трудно повторить точь-в-точь. Confidence medium.

**Итог: офлайн-пути, выдающего готовые 512px без построенного вами рендер-шага или работающей игры, не существует.**

## 5. Новые / недостающие предметы

**Публичной игрок-загрузки иконок у tarkov.dev НЕТ** — поток закрытый и permission-gated.

- **Обнаружение новых предметов:** закрытые **сканеры** (единственная закрытая часть; `infrastructure.md`: «This is the only portion of the project that is closed source» — чтобы не сделали трейд-ботов). Публикуют найденные id в SQL.
- **Пока картинки нет — плейсхолдер `unknown-item`** (генератор детектит подстроку и ставит `needsIcon`/`needs512`/...). *(В текущем `master` часть skip-блоков закомментирована.)*
- **Заливка только по выданным кредам (confirmed):** POST на `manager.tarkov.dev/api/scanner/image` с `API_USERNAME`/`API_PASSWORD`; сервер проверяет auth. Самостоятельной регистрации скан-кредов нет.
- **Скорость:** публичного SLA нет. Базовый 64px-icon появляется быстро (как только клиент скан-контрибьютора отрендерит в кэш); **истинный 512px/8x отстаёт** (нужен отдельно добытый hi-res + ручной HQ-пайплайн). → **512px самых свежих предметов — самое слабое и медленное звено** tarkov.dev. Реальный зазор свежести.

## 6. Рекомендация для ЦТА

Учитывая: IL2CPP-реверс боевого клиента заблокирован (шифрование + BattlEye); готовых 512px-спрайтов в бандлах нет; цель — без рантайм-вызовов tarkov.dev (CLAUDE.md правило 11).

1. **Оставить текущий подход основным.** ЦТА уже само-хостит 512px webp в Supabase (`cta-media/items/eft/{id}.webp`, `src/lib/item-icon.ts`). Зеркалировать уже отрендеренные 512px как **статический ассет через синк-крон** (не per-request) — дёшево, устойчиво, не нарушает правило 11.
2. **Не пытаться «вытащить 512px из бандлов» — этого пути нет.** Не закладывать сроки под «просто распакуем бандл».
3. **Собственный рендер-пайплайн — только если полная независимость станет жёстким требованием.** AssetRipper (офлайн) → меши+материалы+`PreviewPivot` → headless render 512 → `create512Image`. Отдельный спринт/проект, трудное фиделити (оружие/пресеты).
4. **Заложить зазор свежести.** UI устойчив к временному отсутствию 512px: graceful-фолбэк/скелетон (Nightfall `animate-pulse`), синк-крон идемпотентный «дозаливщик».
5. **Честный факт планирования:** автономия «без рендера И без tarkov.dev» **недостижима** при текущих ограничениях (рантайм-рендер блокируется BattlEye, офлайн-рендер пока не построен).

## 7. Открытые вопросы / что не подтвердилось

- **Провенанс 8x-мастера (medium):** инструмент, рождающий hi-res пиксели, не опубликован (`paths.json` → локальные файлы мейнтейнера). Bundle-extraction или приватный in-game-захват — неизвестно. Точно НЕ 64px-кэш и НЕ BSG-API.
- **«Кэш всегда 64px» не держится полностью:** для крупных многоячеечных предметов кэш-файл может быть ≥512px и дать 512 без HQ-источника. «512 невозможен из кэша» верно только для мелких (1×1).
- **Per-assembly рендер доказан для moddable;** статичные предметы могут иметь запечённые спрайты (но tarkov.dev их из бандлов не тянет).
- **Нет published SLA на свежесть 512px;** вывод «512 отстаёт от 64px» — механический.
- **Ветки ссылок:** дефолт `tarkov-dev-image-generator` = `master` (не `main`); `tarkov-data-manager` = `main`.

Релевантный файл ЦТА: `src/lib/item-icon.ts` (единая точка URL иконки; 512px webp уже зазеркалены в свой бэкенд по in-game id).
