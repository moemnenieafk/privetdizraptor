Как строится граф сейчас
1. Позиционирование узлов (computeLayout в QuestMapClient.tsx)
Шаг 1 — Глубина: каждому квесту считается "глубина" по дереву prerequisite:

нет prereq → depth 0
есть prereq → 1 + max(глубина всех prereq)
Шаг 2 — Колонки по торговцам: каждый торговец = отдельная вертикальная колонка

Шаг 3 — Внутри колонки:

квесты сортируются: depth по возрастанию → имя по алфавиту
группируются в строки по максимум 4 штуки
строки стекаются вертикально через ROW_GAP = 96px
узлы в строке расставляются горизонтально через CELL_GAP = 40px
Размеры:


Карточка квеста:  348 × 90px (высота плавающая по кол-ву objectives)
Портрет торговца: 168 × 196px
Зазор между строками: 96px
Зазор между колонками торговцев: 160px
Макс узлов в строке: 4
2. Как рисуются линии связи
Все линии — SVG <path> на отдельном слое (тот же трансформ что и канвас).

Функция makeQuestPath(x1, y1, x2, y2):

если узлы почти на одной вертикали → прямая линия вниз
иначе → S-кривая с закруглёнными углами: вниз → поворот → горизонталь → поворот → вниз
Три типа линий:

Тип	От	До	Форма
Prereq внутри торговца	низ карточки-источника	верх карточки-цели	S-кривая (или прямая если цепочка 1-в-1)
Портрет → корневые квесты	низ портрета	верх 1–4 корневых	Прямая
Кросс-трейдер через stub	низ stub-заглушки	верх дочернего квеста	S-кривая
Цвета и прозрачность:

квест выполнен → зелёная линия, opacity 0.25
квест активен → цвет торговца, opacity 1.0
квест заблокирован → серая, opacity 1.0
Hover: при наведении на квест, все линии НЕ в цепочке (предки + потомки) уходят в opacity 0.05

3. Кросс-трейдер зависимости — stub-узлы
Если квест B зависит от квеста A другого торговца — над B появляется маленькая "заглушка" (stub, 180×52px, пунктирная рамка). Стабы группируются горизонтально над дочерним квестом, max 5 видимых.
